# ToDoTree

ゴールまでの道のりを **分岐と合流のあるグラフ（DAG）** で書き出して進める、C# / WPF の Todo 管理アプリ。

マインドマップのように枝を伸ばし、Git のブランチのように分かれた作業を合流させられます。
「いま着手できるステップ」はグラフから自動で判定されるので、次に何をやればいいか迷いません。

## 主な機能

- **依存関係から次の行動を判断** … 着手可能なステップ、最長経路、期限から逆算した要着手日を自動で計算
- **素早く書き出して繋ぐ** … 箇条書きの一括入力、カード上での直接編集、分岐・合流、ステップの分割
- **大きなグラフを見渡す** … 自動整列、折りたたみ、フォーカスモード、タグ絞り込み、ミニマップ、丸と線だけのミニマル表示
- **進捗を先まで読む** … 理由付きの「次にやること」、完了見込み、期限に間に合うかの判定
- **複数プロジェクトを並行して開く** … プロジェクトごとのタブ、独立したUndo・検索・表示状態、前回のタブ復元
- **外へ共有する** … Markdown / Mermaid への書き出しと、Mermaid 図のコピー
- **安心して保存する** … 読みやすい JSON 形式、原子的保存、バックアップ、自動保存、未保存データの復元

## 動かし方

必要なもの: **.NET 10 SDK**（Windows）

SDK のバージョンは `global.json` で 10.0.1xx 系に固定しています。

```powershell
cd C:\W\CSharp\WPF\ToDoTree
dotnet run --project src\ToDoTree.App
```

Visual Studio なら `ToDoTree.slnx` を開いて `ToDoTree.App` をスタートアッププロジェクトにして F5。
ソリューションは XML 形式の `.slnx` なので、Visual Studio 2022 17.14 以降（または Visual Studio 2026）が必要です。

Core のテスト（TUnit / Microsoft.Testing.Platform）:

```powershell
dotnet test
```

テストプロジェクトはそれ自体が実行ファイルなので、直接走らせることもできます。

```powershell
dotnet run --project tests\ToDoTree.Core.Tests
```

## 使い方

初回起動ではサンプルのプロジェクトが開きます。`Ctrl+N` で自分のプロジェクトを始めてください。

### 基本の流れ

1. **まとめて入力**（`Ctrl+I`）に、やることを箇条書きで貼り付ける。インデントがそのまま親子になります
2. 足りないものはカードを選んで `Enter`。続きのステップが繋がって追加され、**そのカードの上で**すぐ名前が打てます
3. 打ったら `Enter`、また打って `Enter` …… で、ステップの列がどんどん伸びる
4. 分岐させたいときは分岐元を選んで `Enter`、合流させたいときはカード右端の丸から相手のカードへドラッグ
5. `Ctrl+L` で自動整列。保存先を決めたあとは自動保存されます

### 右クリックでできること

キャンバスは、押した場所によって出るメニューが変わります。

| 押した場所 | できること |
|---|---|
| 線の上 | **ここにステップを挟む**、この線を外す |
| ステップの上 | 続きを追加、並行して追加、ここから繋ぐ、完了 / 未着手、この先を畳む、この筋だけ、分割、削除 |
| 背景 | ここにステップを追加、まとめて入力、自動整列、全体表示、全部開く |

「ここにステップを挟む」は、`A → B` を `A → 新しいステップ → B` に繋ぎ直します。
あとから「やっぱりこのあいだに一手要る」と気づいたときに、線を外して繋ぎ直す手間が要りません。
挟んだステップは前後のカードと重ならない場所に置かれるので、
線の上にきちんと載せたいときは `Ctrl+L` で並べ直してください。

### 複数のプロジェクトを開く

「新規」または「開く」で、現在のプロジェクトを閉じずに別のタブを追加できます。
タブをクリックして切り替え、右側の `×` で閉じます。同じファイルをもう一度開いた場合は、
重複したタブを作らず、すでに開いているタブへ移動します。

選択中のステップ、検索・絞り込み、Undo / Redo、キャンバスの位置と拡大率はタブごとに独立しています。
保存や書き出しなどの操作は、現在選択しているタブが対象です。終了時に開いていた保存済みプロジェクトと
未保存プロジェクトの復旧データは、次回起動時にまとめて復元されます。

### 表示を軽くする

ステップが増えて画面が重くなったら、`Ctrl+Shift+M` で **ミニマル表示** に切り替えます。
カードが丸ひとつと名前だけになり、同じ広さにずっと多くのステップが収まります。
状態は丸の描き分けで分かります。

| 丸 | 意味 |
|---|---|
| 中抜き・細い枠 | 待ち（先行が残っている） |
| 中抜き・太い緑の枠 | 着手できる |
| 塗りつぶし | 進行中 |
| 灰色の塗りつぶし | 完了・取り消し（名前に取り消し線） |

外側の輪は、オレンジなら最長経路、それ以外は種別（起点・節目・ゴール）です。
期限を過ぎている、あるいは要着手のステップには、名前のうしろに小さな点が付きます。

切り替えても**位置は動きません**。詰めたいときは `Ctrl+L` で、この表示に合った間隔に並び直します。
もう一度 `Ctrl+Shift+M` でカード表示に戻ります。選んだ表示は次の起動にも引き継がれます。

### 次に何をやるか

左パネルの一番上に「次にやること」が 3 件、**理由付き**で出ます。
着手できるステップが複数あるとき、次の材料から順位を決めています。

- 最長経路（クリティカルパス）の上にあるか
- 期限が近いか、過ぎているか
- 終えると何個のステップが動き出すか（＝詰まりの解消度）
- この先にどれだけ仕事が控えているか

ツールバーの「最長経路」を押すと、全体の背骨になっている鎖がオレンジで浮かび上がります。
期限から逆算した開始日を過ぎているステップには「要着手」の印が付きます。

下のバーには **完了見込み** が出ます。残っている見積りを、これまで実際に片付けてきたペースで割った予測です
（完了記録が 2 件に満たないうちは「1 日 4 時間」として計算します）。
ゴールに期限を付けておくと、間に合うか・何日足りないかまで出ます。

ステップを完了すると、そのとき新しく着手できるようになったステップの名前が下に出ます。

### キー操作

| 操作 | キー |
|---|---|
| 箇条書きをまとめて取り込む | `Ctrl+I` |
| Markdown / Mermaid で書き出す | `Ctrl+Shift+E` |
| 続きのステップを追加 | `Enter` |
| 並行のステップを追加（同じ先行にぶら下げる） | `Shift+Enter` |
| 名前を編集（カードの上で直接） | `F2` / カードをダブルクリック |
| 完了 / 未着手 を切り替え | `Space` |
| 削除（前後は自動で繋ぎ直し） | `Delete` |
| 元に戻す / やり直す | `Ctrl+Z` / `Ctrl+Y` |
| 隣のステップへ移動 | `←` `→` `↑` `↓` |
| ここから繋ぐ（相手を選んで `Enter`） | `Ctrl+E` |
| すべて選択 / この枝をまとめて選択 | `Ctrl+A` / `Ctrl+Shift+↓` |
| 自動整列 | `Ctrl+L` |
| 全体表示 | `Ctrl+0` |
| 拡大 / 縮小 | `Ctrl++` / `Ctrl+-` / ホイール |
| 新規 / 開く / 保存 / 名前を付けて保存 | `Ctrl+N` / `Ctrl+O` / `Ctrl+S` / `Ctrl+Shift+S` |
| 明るい配色 / 暗い配色 を切り替え | `Ctrl+Shift+D` |

※ `Enter` `Space` `Delete` `F2` はキャンバスにフォーカスがあるときのキーです（`Enter` はタイトル入力欄でも効きます）。

### マウス操作

- カードをドラッグ … 移動（複数選んでいれば、まとめて動きます）
- カードをダブルクリック … その場で名前を書き換える
- カード右端の丸からドラッグ … 別のステップへ繋ぐ（循環する繋ぎ方は自動で拒否されます）
- **線をクリック** … その繋がりを選ぶ。`Delete` で外せます
- **Ctrl+クリック** … 選択に足す / 外す
- **Alt+ドラッグ** … 矩形で囲んでまとめて選ぶ
- 背景をドラッグ / 中ボタンドラッグ … 画面を動かす
- ホイール … カーソル位置を中心に拡大縮小
- 左の一覧をダブルクリック … そのステップの位置へ移動
- 右下のミニマップをクリック … そこへ飛ぶ

複数選んだ状態で `Space` を押せばまとめて完了に、`Delete` でまとめて削除できます。

### 数が増えてきたら

- **カード隅の `▾`** … その先を畳みます。畳んだ数が `▸ 12` のように出ます。
  別の枝からも辿れるステップは畳まれません（合流の先は消えません）
- **「この筋だけ」** … 選んだステップの上流・下流だけを残して、他を隠します
- **「完了したものを隠す」** … 済んだステップをキャンバスと一覧の両方から外します
- **タグの絞り込み** … ツールバーのタグを選ぶと、該当しないステップが薄くなります
- **ミニマップ** … 右下に全体図。青い枠がいま見ている範囲です

### 明るい配色と暗い配色

右上の月／太陽のボタン（`Ctrl+Shift+D`）で切り替えます。選んだ配色は次回起動時も保たれます。
色はすべて `Themes/Palette.Light.xaml` と `Palette.Dark.xaml` に集めてあるので、
自分好みの色にしたいときはこの 2 つを書き換えるだけで、画面全体（カード・線・ミニマップまで）に反映されます。

### 色の意味

| 見た目 | 意味 |
|---|---|
| 緑の枠 | **着手できる**（先行がすべて片付いている） |
| 青の枠 | 進行中 |
| 灰色の枠 | 待ち（未完了の先行がある） |
| 取り消し線・薄い | 完了 / 取り消し |
| 赤い「期限超過」 | 期限を過ぎている |
| オレンジの「要着手」 | 逆算した開始日を過ぎている（このままでは間に合わない） |
| オレンジの太い枠・線 | 最長経路の上（表示を切り替えたとき） |
| カード左の色帯 | 種別（スタート / ステップ / 節目 / ゴール） |

### 外に持ち出す

「書き出す」（`Ctrl+Shift+E`）で **Markdown** か **Mermaid** に出せます。
Markdown には進捗・次にやること・全体図（Mermaid）・直近 7 日で終えたこと・全ステップ一覧が入るので、
週報や進捗共有にそのまま使えます。「図をコピー」ならクリップボードに Mermaid が入り、
GitHub や Notion に貼るだけで図が出ます。

### 大きすぎるステップを割る

ステップを選んで「分割」を押すと、箇条書きで細かいステップに割れます。
割ったステップは元のステップの下に入り、**元の後続にはそのまま繋がる**ので流れが切れません。

## 保存形式

1 プロジェクト = 1 ファイルの JSON（`*.todotree.json`）。人が読める形なので Git で差分管理もできます。
保存は一時ファイルに書いてから置き換えるので、途中で落ちても元ファイルは壊れません（`.bak` も残ります）。

保存先が決まっていれば **5 秒ごとに自動保存** します。まだ保存していない作業は、タブごとに
`%APPDATA%\ToDoTree\autosave\<タブID>.todotree.json` へ退避され、次回起動時に復元されます。

開いていたファイル、タブの順序、選択中のタブ、キャンバスの表示位置は
`%APPDATA%\ToDoTree\settings.json` に覚えていて、次回起動時に復元されます。

## 構成

```
ToDoTree.slnx
global.json           … .NET SDK の固定（10.0.1xx）と dotnet test のランナー指定（MTP）
├ src/ToDoTree.Core   … 画面に依存しないロジック（net10.0）
│   ├ Models          … TodoNode / TodoEdge / TodoProject
│   ├ Graph           … DAG 操作、循環検出、着手可能判定、進捗、クリティカルパス
│   ├ Layout          … 階層レイアウト（Sugiyama 風）
│   └ Storage         … IProjectStore と JSON 実装
├ src/ToDoTree.App    … WPF（net10.0-windows、MVVM、外部パッケージ無し）
│   ├ ViewModels      … WorkspaceViewModel（タブ）/ MainViewModel（各プロジェクト）/ NodeViewModel
│   ├ Controls        … GraphView（ズーム・パン・ドラッグ）、EdgeLayer（線の描画）
│   ├ Services        … 設定の保存、配色の切り替え（ThemeManager）
│   └ Themes          … Palette.Light / Palette.Dark（色）、Controls / Calendar（部品）、Styles（文字）
└ tests/ToDoTree.Core.Tests … Core のテスト（TUnit）
```

保存層は `IProjectStore` で抽象化してあるので、SQLite に替えたくなったら実装をひとつ足すだけです。
