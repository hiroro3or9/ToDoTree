# ToDoTree JSON 保存形式

更新日: 2026-09-10

対象: 現在の作業ツリーの実装（`schemaVersion: 10`）

`ToDotree.json` などのプロジェクトファイルの構造、各項目の意味、読み込み時の制約を説明します。
アプリの標準拡張子は `.todotree.json` で、ファイル名そのものは固定されていません。
1ファイルに1プロジェクトを保存します。保存操作、自動保存、バックアップ、復旧手順は
[保存と復旧](STORAGE.md)を参照してください。

## 1. 基本ルール

| 項目 | 保存形式 |
|---|---|
| 文字コード | UTF-8（BOMなし） |
| 構造 | ルートはJSONオブジェクト。改行・インデント付き |
| プロパティ名 | `schemaVersion`、`fromId` などのcamelCase |
| 列挙値 | `Step`、`NotStarted`、`Auto` など、C#の列挙名の文字列 |
| ID | GUID文字列。例: `11111111-1111-4111-8111-111111111111` |
| 日時 | `DateTimeOffset` のISO 8601形式の文字列。例: `2026-09-09T10:30:00+09:00`。小数秒が付く場合もある |
| 数値 | 整数または浮動小数点数。数値を文字列で囲まない |
| 未設定の任意項目 | 値が `null` のプロパティは保存時に省略 |
| 既定値・空の値 | `false`、`0`、空文字列、空配列は省略せず保存 |
| 日本語 | 原則そのまま出力。改行・引用符・バックスラッシュなどはJSONの規則でエスケープ |

読み込みではプロパティ名の大文字・小文字を区別しません。列挙値も大文字・小文字を区別せず読み取りますが、
外部ツールで生成する場合は本書の表記を使用してください。標準設定ではコメント・末尾カンマを許可しません。

表の「省略時」は読み込みでプロパティが存在しない場合の初期値です。**省略と明示的な `null` は同じとは限りません。**
特に日時・数値・真偽値・GUIDなどの非nullable項目には `null` を指定しないでください。
文字列・配列にも、任意項目として記載したもの以外は型に合った値を使用してください。

## 2. プロジェクト（ルート）

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `id` | 文字列（GUID） | 新しいGUID | プロジェクトID |
| `name` | 文字列 | `新しいプロジェクト` | プロジェクト名 |
| `description` | 文字列 | 空文字列 | 説明 |
| `bookmark` | オブジェクト | なし | 作業のしおり。プロジェクトにつき最大1つ |
| `schemaVersion` | 整数 | 現在の形式番号 `10` | 保存形式のバージョン。外部生成時も明示する |
| `variables` | オブジェクト配列 | `[]` | プロジェクト変数（§7）。オブジェクトのキーではなく一覧なので、重複した定義を読み込み時に検出できる |
| `inbox` | オブジェクト配列 | `[]` | 未配置の項目。`id`（GUID）、`title`（空白のみ不可）、`createdAt`（日時）を持つ。IDは受信箱内で一意。グラフや進捗の対象外 |
| `nodes` | オブジェクト配列 | `[]` | ステップ一覧（§3） |
| `edges` | オブジェクト配列 | `[]` | 依存関係の線（§4） |
| `blocks` | オブジェクト配列 | `[]` | ステップをまとめるブロック（§5） |

階層をJSONの入れ子で表す方式ではありません。ノード・線・ブロックをそれぞれ配列に保存し、IDで参照します。
`nodes`、`edges`、`blocks` に明示的な `null` がある場合は空配列として扱います。

### 作業のしおり `bookmark`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `nodeId` | 文字列（GUID） | 空GUID | 再開するノードのID。`nodes` に存在するIDを指定 |
| `note` | 文字列 | 空文字列 | 再開時のメモ |

しおりがなければ `bookmark` 自体を省略します。ブロックIDはしおりの対象にできません。
存在しないノードへの参照は読み込み時に拒否されます。

## 3. ステップ `nodes[]`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `id` | 文字列（GUID） | 新しいGUID | ノードID。ノード間で重複不可 |
| `title` | 文字列 | 空文字列 | タイトル |
| `notes` | 文字列 | 空文字列 | メモ。複数行は `\n` などで表現 |
| `kind` | 文字列（列挙値） | `Step` | 種別 |
| `status` | 文字列（列挙値） | `NotStarted` | ユーザーが指定する状態 |
| `due` | 文字列（日時） | なし | 任意の期限 |
| `completedAt` | 文字列（日時） | なし | 項目全体の完了日時 |
| `estimateMinutes` | 整数 | なし | 見積もり時間。単位は分 |
| `repeat` | オブジェクト | なし | 指定回数で完了する設定。通常項目では省略 |
| `tags` | 文字列配列 | `[]` | タグ一覧 |
| `x` | 数値 | `0` | キャンバス上のカード左上のX座標 |
| `y` | 数値 | `0` | キャンバス上のカード左上のY座標 |
| `isPinned` | 真偽値 | `false` | `true` なら自動レイアウトで位置を動かさない |
| `createdAt` | 文字列（日時） | 読み込み時の現在日時 | 作成日時 |
| `updatedAt` | 文字列（日時） | 読み込み時の現在日時 | 更新日時 |
| `isSettled` | 真偽値 | 再計算 | 計算プロパティ。完了または取り消しなら `true` |
| `isOverdue` | 真偽値 | 再計算 | 計算プロパティ。未完了・未取り消しで、期限が現在日時より前なら `true` |
| `isRepeating` | 真偽値 | 再計算 | 計算プロパティ。`repeat` があれば `true` |

座標はズーム・スクロール前のキャンバス座標です。ノードに所属ブロックIDは保存せず、`blocks[].nodeIds` を参照します。

### 種別と状態

| `kind` | 意味 |
|---|---|
| `Start` | 出発点 |
| `Step` | 通常のステップ |
| `Milestone` | 節目・中間目標 |
| `Goal` | ゴール |

| `status` | 意味 |
|---|---|
| `NotStarted` | 未着手 |
| `InProgress` | 進行中 |
| `Done` | 完了 |
| `Cancelled` | 取り消し。後続の依存関係では完了と同様に待ちを解消 |

「いま着手できる」「先行の完了待ち」といった `Readiness` はグラフから計算し、保存しません。

### 回数 `repeat`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `targetCount` | 整数 | `3` | 目標回数。`2`〜`9999` |
| `completedCount` | 整数 | `0` | 達成回数。`0`〜`targetCount` |
| `isFull` | 真偽値 | 再計算 | `completedCount >= targetCount` |
| `isFinalNext` | 真偽値 | 再計算 | `completedCount + 1 >= targetCount`。完了済みでも `true` になる |

`repeat` はどの `kind` にも設定できます。各回の実施日時・履歴は保存しません。
画面の自己ループは繰り返しの表示であり、`edges` に自己参照の線は保存しません。

読み込み・保存では、回数の範囲に加えて以下を検証します。

| 回数 | 許される状態（取り消し以外） | `completedAt` |
|---|---|---|
| `0` | `NotStarted` または `InProgress` | なし |
| `1`〜目標回数未満 | `InProgress` | なし |
| 目標回数と同じ | `Done` | 必須 |
| 範囲内の任意の回数 | `Cancelled` | なし |

取り消し中も達成回数を保持できます。不整合な回数や状態は自動補正せず拒否します。
この回数・状態・完了日時の整合性検証は `repeat` がある項目に適用されます。

### 計算プロパティの扱い

現在の保存処理は読み取り専用プロパティを除外していないため、`isSettled`、`isOverdue`、`isRepeating` と
`repeat.isFull`、`repeat.isFinalNext` も出力します。ただし、読み込み時にこれらの値を復元するsetterはありません。
状態・期限・回数から再計算するため、外部ツールから入力する際は省略できます。これらの値だけを編集しても状態は変わりません。
特に `isOverdue` は現在時刻に依存し、保存後に意味が変わるため、保存値を判定の正本にしないでください。

## 4. 依存関係 `edges[]`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `id` | 文字列（GUID） | 新しいGUID | 線のID。線同士で重複不可 |
| `fromId` | 文字列（GUID） | 空GUID | 先行するノードまたはブロックのID |
| `toId` | 文字列（GUID） | 空GUID | 後続のノードまたはブロックのID |
| `label` | 文字列 | なし | 任意のラベル |
| `colorId` | 文字列 | なし | 個別色のID（§6） |
| `fromSide` | 文字列（列挙値） | `Auto` | 接続元の辺 |
| `toSide` | 文字列（列挙値） | `Auto` | 接続先の辺 |
| `fromPortId` | 文字列（GUID） | なし | 接続元ブロック内の接続点ID |
| `toPortId` | 文字列（GUID） | なし | 接続先ブロック内の接続点ID |
| `waypoints` | オブジェクト配列 | `[]` | 接続元から接続先へ順に通る点 |

接続辺は `Auto`（自動）、`Right`（右）、`Top`（上）、`Bottom`（下）、`Left`（左）のいずれかです。
明示的な接続点IDがある場合は、その接続点の辺と位置が使われます。接続点IDを省略すると、指定辺または自動判定による標準位置になります。
ノードを端点にする場合、対応する接続点IDは指定できません。

ブロックを端点とする線は、計算時に所属ノード全体の依存関係に展開されます。
例えばブロックAの所属が2件、ブロックBの所属が3件なら、A→Bの1本は計算上6通りの依存関係になります。
保存するのはブロックIDを端点にした元の1本です。接続点は線の表示位置を指定するもので、依存する所属ノードを絞るものではありません。

### 通過点 `waypoints[]`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `x` | 数値 | `0` | キャンバス上のX座標 |
| `y` | 数値 | `0` | キャンバス上のY座標 |
| `isSmooth` | 真偽値 | `false` | 通過点で線を滑らかにつなぐ指定 |

配列順が通過順です。通過点は表示上の情報であり、タスク数・依存関係には影響しません。
`waypoints: null` は空配列として扱います。

## 5. ブロック `blocks[]`

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `id` | 文字列（GUID） | 新しいGUID | ブロックID。ブロック間およびノードIDとの重複不可 |
| `parentBlockId` | 文字列（GUID） | なし | 直接の親ブロックID。省略時は最上位 |
| `title` | 文字列 | `新しいブロック` | 見出し |
| `isCollapsed` | 真偽値 | `false` | ブロックを折りたたんだ状態 |
| `colorId` | 文字列 | なし | 個別色のID（§6） |
| `nodeIds` | 文字列（GUID）配列 | `[]` | 直接所属するノードID。子ブロックのノードは含めない |
| `ports` | オブジェクト配列 | `[]` | ブロックの辺上にある接続点 |

所属情報の正本は `nodeIds` と `parentBlockId` です。同じノードを複数ブロックへ直接所属させることはできません。
ブロックは任意段数に入れ子にできますが、自分・子孫を親にする循環や存在しない親は指定できません。
`nodeIds` の順番は表示位置を決めません。ブロックの座標・幅・高さは所属ノードから計算し、保存しません。
`nodeIds`、`ports` に明示的な `null` がある場合は空配列として扱います。直接所属が空でも子孫に
1件以上のノードがあれば有効ですが、子孫にもノードがないブロックは検証で拒否されます。

### 接続点 `ports[]`

| キー | JSON型 | 制約・意味 |
|---|---|---|
| `id` | 文字列（GUID） | 空GUID不可。同じブロック内で一意。線の接続点IDから参照 |
| `side` | 文字列（列挙値） | `Top`、`Bottom`、`Left`、`Right`。`Auto` は不可 |
| `position` | 数値 | 辺上の位置の割合。有限の `0`〜`1`。`0.5` が中央 |

上辺・下辺では左端が `0`、右端が `1`。左辺・右辺では上端が `0`、下端が `1` です。
絶対座標ではないので、ブロックの大きさが変わっても辺上の割合を維持します。
外部生成時は3項目とも明示してください。`position` の省略値は `0` ですが、`id` や `side` の省略値は検証を通りません。
接続点IDの一意性はブロック単位で検証され、線は端点ブロックと接続点IDの組で参照します。

## 6. 個別色 `colorId`

線とブロックで共通のIDを使います。

| ID | 表示名 |
|---|---|
| `slate` | 灰 |
| `red` | 赤 |
| `orange` | 橙 |
| `amber` | 黄 |
| `green` | 緑 |
| `teal` | 青緑 |
| `blue` | 青 |
| `violet` | 紫 |
| `pink` | 桃 |

省略・`null` は既定色です。未知のIDも値は保持しますが、表示には既定色を使います。
RGB値やテーマ別の色は本体には保存しません。選択・強調などでは状態色が優先されます。

## 7. プロジェクト変数 `variables[]`

プロジェクトの中だけで通じる名前と表示値です。ステップの原文に書いた `{Hoge}` を、
表示するときだけ定義値へ置き換えます。保存する原文は書き換わりません。

| キー | JSON型 | 省略時 | 意味 |
|---|---|---|---|
| `name` | 文字列 | 空文字列 | 変数名。1〜64文字。文字または `_` で始まり、以降は文字・結合文字・10進数字・`_` |
| `value` | 文字列 | 空文字列 | 定義値。改行を含まない1〜4096 UTF-16コード単位。空白だけの値は不可。前後の空白は保持 |

名前の比較は序数（`StringComparer.Ordinal`）です。大文字・小文字を区別し、正規化も空白の除去も行いません。
`製品名` のような日本語の名前も使えます。名前が重複する一覧は読み込み・保存とも拒否します。

置き換えの対象は `nodes[].title`、`nodes[].notes`、`inbox[].title` の3つだけです。
プロジェクト名・説明、ブロック名、接続点名、タグ、チェック項目、ブロックの理由、しおりのメモは対象外です。

| 原文 | 表示（`Hoge` = `値` のとき） | 扱い |
|---|---|---|
| `{Hoge}` | `値` | 定義のある参照 |
| `{Fuga}` | `{Fuga}` | 定義が無いので原文のまま。読み込みは拒否しない |
| `{{Hoge}}` | `{Hoge}` | エスケープ。`{{` が `{`、`}}` が `}` |
| `{Hoge`、`{ Hoge }`、`{a b}` | 入力どおり | 参照として解釈しない |

走査は左から1回だけで、エスケープを先に処理します。展開した値は再走査しないので、
`Hoge` の値が `{Other}` でも結果は文字列 `{Other}` のままです。

形式9以前のファイルを読み込むときは、対象フィールドの `{` と `}` をそれぞれ二重にして
形式10へ移行します。これまでの表示をそのまま保つためで、通常保存で形式10として確定します。
移行後の文字列を変数として使いたい場合は、編集で `{Hoge}` に書き換えてください。

## 9. 検証と互換性

### 参照と依存関係

読み込み・保存時には、主に次の不整合を拒否します。

- ノードIDの重複、ブロックIDの重複、ノードIDとブロックIDの衝突。
- 空ブロック、存在しない所属ノード、同じブロック内の所属重複、複数ブロックへの所属。
- 存在しないノード・ブロックを端点とする線。
- 線IDの重複、または同じ `fromId` と `toId` の組の重複。接続点だけ違う線も重複扱い。
- 所属ノードへ展開した依存関係の循環。自己接続も含む。
- 不正な接続点ID・辺・位置、および端点ブロック内に存在しない接続点への参照。
- §3の回数・状態・完了日時の不整合。
- §7の不正な変数名・定義値、および名前の重複。

しおりの参照先チェックは `Load` にあります。`Save` には同じチェックがないため、
外部コードがモデルを直接作って保存する場合も、実在するノードIDを設定してください。

### 形式バージョン

形式9では各ノードに `isManuallyBlocked`（真偽値、既定false）、`blockReason`（文字列、既定空）、
`checklist`（配列、既定空）を追加しました。チェック項目は `id`（GUID、カード内で一意）、
`title`（文字列）、`isChecked`（真偽値）を持ちます。項目IDには空GUIDを使えません。
受信箱とチェックリストのnull配列は空として読み込みますが、配列内のnull要素は拒否します。
手動ブロック中は着手候補から外れますが、`status`は保持します。完了・取り消しの操作で
ブロックの印を解除し、理由は保持します。チェック済み件数はカードの完了状態と独立しています。

| バージョン | 追加された保存情報 |
|---|---|
| `1` | 基本のノード・依存関係 |
| `2` | ブロック |
| `3` | 作業のしおり |
| `4` | ブロックの折りたたみ、ブロックを端点にした接続 |
| `5` | ブロックと線の個別色 |
| `6` | 指定回数で完了する項目 |
| `7` | ブロックの接続点、線からの接続点参照 |
| `8` | ブロックの親子関係 |
| `9` | 受信箱、カード内チェックリスト、手動ブロックと理由 |
| `10` | プロジェクト変数、対象フィールドの波括弧のエスケープ |

旧形式1〜9は読み込み時にメモリ上で10へ移行し、次の保存で10として出力します。
読み込みだけでは元ファイルを書き換えません。10より大きい形式番号は読み込みを拒否します。
形式8以前を名乗るファイルに受信箱・チェックリストの項目、手動ブロックまたは理由が含まれる場合は拒否します。
形式9以前を名乗るファイルに空でない `variables` が含まれる場合も拒否します。

`schemaVersion < 2` でブロックが入っているファイルと、`schemaVersion < 6` で `repeat` があるファイルは拒否します。
それ以外の追加項目すべてについて、導入バージョンとの一致を個別に検査しているわけではありません。
形式番号の下限チェックもなく、省略すると現行の9になります。外部生成では必ず正しい形式番号を明示してください。

未知のプロパティは標準のデシリアライズ処理で無視され、再保存時には保持されません。
未知の `colorId` の値を保持する挙動とは異なります。列挙値は通常の文字列出力を使ってください。
現在の列挙コンバーターは整数入力も許可しますが、未定義値に対する検証は項目ごとに異なるため、外部生成では使用しないでください。

## 10. 本体に保存しない情報と外部編集

Undo/Redo履歴、検索・選択、一時的なフォーカス・枝の折りたたみ、吸着ガイドは本体に保存しません。
ブロック自身の折りたたみは `isCollapsed` として保存します。
タブ一覧、ズーム・画面位置、テーマ、カード表示方式、配置方向は別の `settings.json` の対象です。
部品ライブラリのファイル形式も、本書のプロジェクト形式とは別です。

外部編集する場合はアプリを閉じ、コピーを編集してから開いて確認してください。
保存先があるプロジェクトは自動保存で上書きされるため、起動中の外部編集は競合するおそれがあります。
IDを変更したら、線の端点・ブロック所属・しおり・接続点参照も対応させてください。
