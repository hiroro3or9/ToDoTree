# ドキュメント案内

更新日: 2026-09-08

ToDoTreeは、依存関係のあるステップをグラフで管理するWindowsアプリです。
開発では、書く・つなぐ・動かす・直す操作の手触りを最優先します。

## 文書の役割

- READMEは利用者向けの入口。操作を変えたときはここを更新する。
- 保存と復旧は現在の保存仕様の参照先。保存周期、対象、失敗時の挙動を集約する。
- 全体設計は実装の構成を説明し、個別機能の細かい仕様は設計書へリンクする。
- 機能別設計書は当初の判断・制約・受け入れ条件も残す。冒頭に実装状況と後続の変更先を明記する。
- ロードマップは現時点の優先順位を管理する。候補は実装予定の確約ではない。
- 調査メモは調査日の記録。現在の実装状況や最新版の外部製品情報として扱わない。

## 更新するとき

1. 操作・保存・構造など、変更に対応する文書を更新する。
2. 機能が完成したらロードマップと設計書の状態を更新する。
3. 検証結果は日付と対象を付ける。「テスト成功」と「実マウスで確認済み」を区別する。
4. 新しい文書を追加したら、この一覧へリンクする。
5. 相対リンクが実在するファイルを指すことを確認する。

開発エージェント向けの既存の取り決めは[CLAUDE.md](../CLAUDE.md)にあります。
同ファイルのCowork環境の制約は、その環境に限定した記録です。
