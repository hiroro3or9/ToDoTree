# 保存ファイルの見本（schemaVersion 1）

[データ・保存](../specs/04-data-model.md)の形式で書いた完成例です。
フィールド名・enumの綴り・日時の書き方・nullの省略で迷ったら、表よりこちらを正とします。

| ファイル | 内容 | 使う段階 |
|---|---|---|
| [sample.todotree.json](sample.todotree.json) | 初回サンプル（[全体設計](../specs/01-architecture.md)の11枚）そのもの | 01・03・06・07 |
| [full-fields.todotree.json](full-fields.todotree.json) | 全フィールドを一度ずつ使う小さなプロジェクト | 06・10・12・13 |

## 見本の約束

- 書き出しの形はSystem.Text.Jsonの出力に合わせている（インデント2、日本語はそのまま、整数値のdoubleは `80`）。
  読込側は `80` と `80.0` のどちらも受け付けること。プロパティの順序は問わない。
- nullのフィールドは出力しない（`due` `completedAt` `estimateMinutes` `parentTaskId` `label` `colorId`
  `fromPortId` `toPortId` `parentBlockId` `bookmark`）。空文字・空配列・`false`・`Auto` は出力する。
- IDは読みやすさのため規則的なGUID（ノード `a…`、線 `e…`、ブロック `b…`、ポート `c…`、
  チェック項目 `d…`、受信箱 `9…`、プロジェクト `f…`）。実アプリでは `Guid.NewGuid()` で採番する。
- 日時は例として `2026-09-24T09:00:00+09:00` に固定している。
  実アプリの初回サンプルは、起動時に新しいIDと現在時刻で作る（座標も自動整列で決める）。
- 座標は整列結果の一例。読込では保存値をそのまま使い、読込時に整列し直さない。

## 読み込んだときの期待値

テストの期待値に使える。「今日」の日付や期限に依存しない項目だけを挙げる。

### sample.todotree.json

- 着手判定: `アイデアを決める` `やることを書き出す` `開発環境を用意する` はDone。
  `画面のラフを描く` はInProgress。`データ構造を決める` `アイコンを作る` はReady。残り5件はBlocked。
- ステータスバー: `進捗 3 / 11（27%）`、`着手できる 2 件 ・ 進行中 1 件 ・ 待ち 5 件`。
  重み付きの進捗は 195 ÷ 1545 分。
- 最長経路: アイデアを決める → やることを書き出す → 画面のラフを描く → 画面を実装する →
  つないで動作確認 → 紹介用のスクショを撮る → 公開する（累積1050分）。
- 次にやること（上から）:
  1. 画面のラフを描く — `最長経路の上にある、すでに手を付けている`
  2. データ構造を決める — `終えると 1 つが動き出す、この先に 4 ステップ控えている`
  3. アイコンを作る — `いま着手できる`
- 完了見込み: 完了済み3件のcompletedAtが同じ時刻なので、日数は1日として割り、ペース195分/日。
  残り1350分 → `残り 22.5h ・ これまでのペースなら {今日+7日} 完了見込み`。Goalに期限がないので余裕は出ない。

### full-fields.todotree.json

- 最上位の階層に出るカードは4枚（スタート・資料を集める・下書きを作る・提出する）。
  `構成を決める` `本文を書く` は `下書きを作る` の内部ステップ。
- 着手判定:
  - スタートはDone。
  - 資料を集めるは、保存statusがInProgressでも手動ブロックなのでBlocked。
  - 下書きを作るはInProgress（判定順3が先に当たる）。
  - 提出するはBlocked。ブロック「準備」を端点にした線で、資料・下書きの両方を待つ。
  - 構成を決めるはDone。
  - 本文を書くはBlocked。先行は完了しているが、祖先の下書きを作るの依存が片付いていない。
- 進捗: 最上位で `進捗 1 / 4（25%）`、下書きを作るの内部で `進捗 1 / 2（50%）`。
  下書きを作るのカードには `内部 1／2 件完了`。
- ブロック: 「準備」（teal、右辺中央に接続点）の中に子ブロック「調べもの」。
  資料を集めるは「調べもの」、下書きを作るは「準備」に直接所属する。
- 線: スタート→資料を集める は青・ラベル付き・右から出て左へ入り、通過点2つ（2つ目は滑らか）。
- 受信箱: `未整理 1 件`。進捗・計画には入らない。
- しおり: 資料を集めるに旗。再開メモ `回答が来たら見積りの前提から読む`。
- 資料を集めるの右パネル: 手動ブロックの理由 `先方の回答待ち`、チェックリスト `1/2`。
  提出するの「この作業・ゴールが止まっている理由」に、上流の手動ブロック（資料を集める）が出る。

## 検証テストの作り方

`full-fields.todotree.json` を読み、1か所だけ壊して読込が拒否されることを確かめる。例:

| 壊し方 | 期待 |
|---|---|
| 提出するの `id` をスタートと同じにする | IDの重複で拒否 |
| ブロック「準備」の `id` を資料を集めると同じにする | ノードとブロックのID衝突で拒否 |
| スタート→スタートの線を足す | 自己ループで拒否 |
| 線の `toId` を存在しないIDにする | 存在しない端点で拒否 |
| スタートの `completedAt` を消す | 状態と完了日時の不整合で拒否 |
| 資料を集める→下書きを作るの逆向きの線を足す | 循環で拒否 |
| 構成を決める（内部）とスタートを線で結ぶ | 階層をまたぐ線で拒否（段階13から） |
| しおりの `nodeId` を存在しないIDにする | しおりの参照切れで拒否 |
| 線の `fromPortId` を存在しないIDにする | 不正なポート参照で拒否 |
| ポートの `position` を `1.5` にする | position範囲外で拒否 |
| `schemaVersion` を `2` にする | 未知の版として更新案内とともに拒否 |

拒否したとき、開いている文書・タブ・設定が変わらないことも確かめる。
