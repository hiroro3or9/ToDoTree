# ブロック移動の位置合わせガイドと吸着

作成日: 2026-09-06  
状態: 初版実装済み（2026-09-06）  
対象: ブロックの見出しをドラッグしたときの、ブロック同士の位置合わせ

## 1. 目的

ブロックを「だいたいここ」と動かすだけで、他のブロックと端や中心を揃えられるようにする。
操作感を優先し、微調整の往復を減らす。吸着先が頻繁に切り替わる、遠くへ引っ張られる、
狙った位置に置けない、といった挙動を避ける。

初版はブロック同士だけに限定する。カード単体・複数選択・通過点の吸着、
等間隔配置、グリッド、サイズ変更、衝突回避、自動的な所属変更は対象外。

## 2. 現在の実装との接点

- `GraphView.xaml.cs`が見出しの押下位置、ドラッグ開始しきい値、ワールド座標の差分を管理している。
- `MainViewModel.BeginBlockDrag()`はノードと内部通過点の初期座標を控える。
- `UpdateBlockDrag(dx, dy)`は初期座標に差分を適用する。
- `CommitBlockDrag()`と`CancelBlockDrag()`は既存のトランザクションで確定・取消を行う。
- `BlockViewModel.Bounds`は見出しを含む囲みの矩形。可視件数と移動可否も取得できる。
- キャンバスではAlt＋ドラッグが矩形選択に使われている。

新機能は、既存の移動処理へ渡す差分を補正する層と、ガイドを描く表示層として追加する。
ノードや通過点を別々に吸着させない。

## 3. 操作仕様

| 操作 | 動作 |
|---|---|
| 見出しをドラッグ | 近くのブロックとの位置合わせを有効にする |
| 端・中心が吸着範囲に入る | 一致する座標へ補正し、ガイド線を表示 |
| 吸着した座標からさらに引く | 解除距離を超えたら自由移動へ戻る |
| ドラッグ中にAltを押す | 即座に吸着を解除し、ガイドを消す |
| Altを離す | 現在の未補正位置から候補を探し直す |
| MouseUp | 最後のポインター位置とAlt状態で再評価して確定 |
| Esc | ノードと通過点を押下前へ戻す。ガイドと吸着状態を破棄 |

Altの押下・解放はマウスを動かさなくても反映する。
Altによる解除では補正していた分だけ位置が戻る。新しいドラッグ原点を作り直さず、
元の押下位置に対するポインターの移動量へ戻す。

### Alt＋矩形選択との優先順位

- ブロック見出しで押下した場合は、Altの有無にかかわらずブロック移動を優先する。
- 見出しをAltを押したままドラッグすると、最初から自由移動になる。
- 見出し以外からのAlt＋ドラッグは従来の矩形選択を維持する。
- 一度決まったジェスチャーは途中のAlt操作で種類を切り替えない。
- 見出しの名前入力欄は通常のテキスト編集を優先し、移動を開始しない。

ドラッグ中のAltはメニューのアクティブ化へ流さない。ドラッグ中のキー処理だけで消費し、
通常時のメニューアクセスキーやIME操作には影響を与えない。

## 4. 吸着対象と幾何

### 移動元と対象ブロック

移動元はドラッグ開始時の`BlockBounds`を固定して使う。ドラッグの途中で表示境界を読み直して
計算原点にしない。移動元は全所属ノードが表示され、既存の`CanMove`がtrueのものに限る。

対象は同じ文書の、自分以外で全所属ノードが表示されているブロック。
一部非表示のブロック、全体非表示のブロック、画面にまったく見えていないブロックは対象外。
検索やタグで薄くなるだけのものは対象に含める。

ドラッグ開始時に対象IDと矩形をスナップショットする。対象の矩形は部分的にでも
ビューポートと交差しているものを採用する。
移動中のズーム・パンは後述のとおり抑止するため、画面への出入りで候補を入れ替えない。

### 揃える線

| 軸 | 移動元・対象で比較する座標 |
|---|---|
| X（縦ガイド） | 左端、横方向の中心、右端 |
| Y（横ガイド） | 上端、縦方向の中心、下端 |

左端同士、中心同士、右端同士のように、同じ種類のアンカーだけを比較する。
異なる端同士を合わせる隣接配置は、初版では提供しない。
対象にする矩形はカードだけの外接矩形でなく、見出しと余白を含む囲み全体。

XとYは独立に吸着でき、異なる対象ブロックへ揃ってもよい。
ただし無関係に遠いブロックへ揃わないよう、直交軸の矩形間隔が画面上160 DIP以内の候補に限定する。
間隔は投影区間が重なれば0、それ以外は最寄りの端同士の距離とする。

例: Xを揃える場合、上下に離れすぎたブロックは候補に含めない。
候補の絞り込みと順位は、吸着補正前の移動矩形で計算する。

吸着は重なりを防ぐ機能ではない。自由移動と同様に囲みの重なりを許容し、
位置合わせによって所属や依存関係が変わることはない。

## 5. 距離と吸着状態

### 初期パラメーター

| 項目 | 初期値（ビューポート上のDIP） |
|---|---:|
| 新しく吸着する距離 | 6 |
| 現在の吸着を解除する距離 | 10 |
| 直交方向の候補範囲 | 160 |
| 吸着中の直交方向の解除範囲 | 184 |
| ガイドの線幅 | 1 |
| ガイド端の延長 | 8 |

値はコード上の一か所に集約し、実操作で調整する。初版は設定画面を追加しない。
これらは物理ピクセルではなく、WPFのデバイスに依存しない単位。
OSのDPI倍率はWPFに任せ、グラフのズーム倍率だけでワールド座標との距離を変換する。

`画面上の距離 = abs(対象アンカー - 未補正アンカー) × zoom`

25%表示では吸着開始が24ワールド単位、100%では6、250%では2.4になる。
ズームによって見た目の吸着範囲が変わらない。

### 軸ごとの状態機械

1. 未吸着なら開始距離以内の候補から1つ選ぶ。
2. 吸着中なら、同じ対象IDとアンカー種別を保持する。
3. 未補正位置が解除距離以内、かつ直交方向の解除範囲以内なら、もっと近い別候補が現れても切り替えない。
4. 解除距離または直交方向の範囲を超えたら解放する。その更新ではその軸を自由移動とし、次の更新から候補を探す。
5. Alt、取消、対象消失では状態を破棄する。

開始と解除の距離に差を設け、境界付近の小さな手ぶれで吸着・解除を繰り返さないようにする。
判定の距離は必ずポインターから求めた未補正位置で計算する。
表示上の吸着位置で判定すると距離が0のままとなり、外れなくなるため。

### 候補の順位

未吸着時は次の順に比較する。

1. 吸着に必要な画面上の移動距離が小さい。
2. 直交方向の矩形間隔が小さい。
3. アンカー種別の固定順（左／上、中心、右／下）。
4. 対象ブロックIDの固定順。

同距離判定は0.01 DIPの許容差で行う。辞書や描画順の偶然に依存させない。
1軸につき1候補のみ採用し、線を大量に表示しない。

## 6. 移動差分

```text
rawDelta = 現在のポインターのワールド座標 - 押下時のワールド座標
rawBounds = 開始時の囲み + rawDelta

X吸着中: dx = 対象Xアンカー - 開始時のXアンカー
X未吸着: dx = rawDelta.X
Y吸着中: dy = 対象Yアンカー - 開始時のYアンカー
Y未吸着: dy = rawDelta.Y

UpdateBlockDrag(dx, dy)
```

補正後の差分を既存処理へ一度だけ渡す。
全所属ノードと両端が内部にある線の通過点は、同じ差分だけ動く。
外部へつながる線の通過点は従来どおり絶対位置を保持する。
吸着補正を次のフレームのrawDeltaへ加算しない。

## 7. ガイド表示

- 実際に吸着している軸だけ表示する。接近中の予告線は初版には設けない。
- Xのガイドは一致するX座標で、移動元と対象の上下端を結ぶ範囲に表示する。
- Yも同様に、両矩形の左右端を結ぶ範囲に表示する。
- 線の端を画面上8 DIP延長し、ビューポートの外はクリップする。
- 最大で縦1本、横1本。細い破線とし、依存関係の実線と区別する。
- ガイドはカードと線より前面、ポインターの操作を奪わない`IsHitTestVisible=false`の層に置く。
- ワールド座標をビューポート座標へ変換して描き、ズームしても線幅と破線間隔を保つ。
- ライト／ダークに同名の`AlignmentGuideBrush`を追加する。
- ガイドの座標・対象・吸着状態は保存せず、Undo履歴にも含めない。

見出しのツールチップに「ドラッグで位置合わせ・Altで自由移動」を追加する。
ドラッグ中の補助表示は「Altで吸着を解除」に固定し、候補が変わるたびにステータス文言を更新しない。
確定・取消では既存の結果メッセージに戻す。

## 8. ジェスチャーの終了と例外

| 状況 | 動作 |
|---|---|
| MouseUp | 最終座標を再評価、既存の確定処理、状態とガイドを破棄 |
| Esc、予期しないキャプチャ喪失、ウィンドウ非アクティブ化 | 既存の移動取消、状態とガイドを破棄 |
| タブ切替、GraphViewの文書差し替え・破棄 | 移動を取り消してから文書を切り替える |
| 明示保存・文書終了で既存処理がドラッグを確定 | 最後に表示した補正済み座標を確定し、View側の状態も破棄 |
| Alt解放イベントを取り逃した場合 | 次のMouseMove／MouseUpで現在の修飾キーを再取得して同期 |
| 対象の構造・可視性・表示モードが外部から変わる | ドラッグを取り消し、古い候補を使用しない |

ブロックの押下待機中とドラッグ中は、ホイール・ズームキー・全体表示・パンの入力を抑止する。
初版ではドラッグ中の自動パンも追加しない。座標変換が途中で変わって原点が跳ぶことを防ぐ。
通常のノード移動など他ジェスチャーへの適用は本変更の対象外。

キー入力を使わずに呼ばれる保存・タブ切替もあるため、ガイドの後始末をMouseUpだけに依存させない。
`IsBlockDragging`がfalseになったときと文書差し替え時に、共通の終了処理を呼ぶ。

## 9. 実装構成

### Core: `src/ToDoTree.Core/Layout/BlockSnapService.cs`（新規）

WPFに依存せず、候補選択と軸ごとの状態遷移を計算する。

型の案:

```csharp
public enum SnapAnchor { Start, Center, End }
public sealed record SnapTarget(Guid Id, BlockBounds Bounds);
public sealed record AxisSnap(Guid TargetId, SnapAnchor Anchor);
public sealed record SnapState(AxisSnap? X, AxisSnap? Y);
public sealed record SnapGuide(bool IsVertical, double Coordinate, double From, double To);
public sealed record SnapResult(Vec2 Delta, SnapState State, IReadOnlyList<SnapGuide> Guides);
```

`Compute(startBounds, rawDelta, targets, previousState, zoom, isBypassed, options)`を純粋計算として提供する。
結果には補正済み差分、新状態、ワールド座標のガイド区間を含める。
ガイドの8 DIP延長とクリッピングは描画側が担当する。
モデルの座標はCoreの吸着サービスから変更しない。
対象一覧は文書側が検証済みの不変スナップショットとして渡す。
非正値のズームやNaN／無限座標は入力エラーとして拒否し、Appで移動を取り消す。

### App: `GraphView.xaml.cs`

既存のブロックドラッグ情報へ、開始時の囲み、対象一覧、吸着状態、最後のポインター位置を追加する。
候補はドラッグしきい値を超え、`BeginBlockDrag()`が成功した時点で取得する。
rawDeltaの原点には従来どおり押下時の座標を使う。

MouseMove、AltのKeyDown／KeyUp、MouseUpが同じ更新関数を利用する。
ViewModelが直接確定した場合も、終了通知を受けて状態とガイドを消す。
入力優先順位は、編集中の入力欄 → 見出しのジェスチャー → 既存のAlt矩形選択の順へ整理する。

### App: `AlignmentGuideLayer`（新規）

軽量な描画要素で最大2本のガイドを描く。`GraphView.xaml`のビューポート内へ配置する。
既存の座標変換を共有し、別のズーム・パン計算を持たない。
ガイド更新だけで`RefreshAll()`やレイアウト計算を呼ばない。

### ViewModel

既存の`UpdateBlockDrag()`の責務は維持する。
必要なら、ドラッグ対象IDを除く可視ブロック矩形を取得する読み取り専用メソッドを追加する。
Undo、通過点、自動保存抑止は既存のブロック移動を利用する。
プロジェクトJSONや設定ファイルの形式変更は不要。

## 10. 性能

対象矩形をドラッグ開始時に取得し、更新時には対象数に比例した比較だけを行う。
1対象につきX/Y各3組の比較で済む。初版で空間インデックスは導入しない。
移動の更新1回につき候補計算も1回、補正済み差分の適用も1回とする。

100ノード／10ブロックを通常ケース、300ノード／30ブロックを負荷ケースとして計測する。
候補計算単体と、既存の線の再描画を含むドラッグ全体を分けて記録する。
通常ケースで候補計算の95パーセンタイル1 ms以内を目標とし、
ドラッグ全体のフレーム時間も導入前と比較する。これらは未計測の目標。

## 11. 受け入れ条件

### Coreのテスト

- 左・中心・右、上・中心・下がそれぞれ一致する。
- 開始6 DIP、保持10 DIP、直交範囲160／184 DIPの境界を検証する。
- 25%、100%、250%のズームで画面上の開始・解除距離が一致する。
- より近い候補が現れても、保持条件内では対象を切り替えない。
- 解除した更新ではその軸に再吸着せず、次の更新から候補を取得する。
- 候補の配列順を入れ替えても選択結果が同じ。
- X/Yの片軸・両軸吸着、異なる相手への両軸吸着を検証する。
- 遠い候補、対象なし、対象消失、負の座標、サイズの異なる囲みを扱える。
- Alt時はrawDeltaがそのまま返り、状態とガイドが空になる。
- rawDeltaから毎回計算し、累積誤差や解除不能が起きない。

### 実画面の確認

1. 2つのブロックを上下に置き、左端・中心・右端へゆっくり揃える。
2. 吸着距離の境界で手を小刻みに動かし、線と囲みがガタつかないことを確認する。
3. 近くに3つ目のブロックを置き、意図しない吸着先切替がないことを確認する。
4. ポインターを止めたままAltを押す／離す。位置とガイドが即時に変わることを確認する。
5. Altを押した状態から見出しを動かし、背景のAlt矩形選択も従来どおり動くことを確認する。
6. 25%、100%、250%、OSの100%／150%表示、ライト／ダークで操作と線幅を確認する。
7. 内部の通過点が同じ差分で動き、外部接続の通過点と他ブロックが変化しないことを確認する。
8. MouseUp、Esc、キャプチャ喪失、タブ切替、保存、非アクティブ化後にガイドが残らないことを確認する。
9. 1回のUndoで全移動が戻り、取消時にRedoと未保存状態が変わらないことを確認する。
10. 吸着により最終位置が開始位置と完全一致した移動で履歴が増えないことを確認する。

特に「揃えたい位置に止められる」「離したいときにすぐ外れる」を実操作で判断し、
開始・解除距離は両者のバランスを見て調整する。

## 12. 実装順

1. Coreの候補計算、保持と解除、ズーム換算のテスト。
2. 既存ブロックドラッグへ補正差分を接続し、通過点とUndoを確認。
3. ガイド描画、Altの即時反映、入力優先順位と終了処理を実装。
4. 実操作と性能を確認し、距離・色・線幅を調整。
5. READMEへ操作を追記し、設計書の状態を更新。

次の拡張はカード単体・複数選択への適用。その際も移動対象全体の外接矩形へ
1つの差分を適用し、複数カードの相対配置を崩さない方針を引き継ぐ。

## 実装時の検証記録

- ソリューションのビルド成功、警告・エラーなし。
- Coreテスト149件成功（吸着の新規テスト9件を含む）。
- 一時的なWPF検証ホストでガイド描画、吸着後のノード・内部通過点の追従、外部通過点の保持を確認。
