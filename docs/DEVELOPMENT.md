# 開発・検証ガイド

更新日: 2026-09-06

## 開発環境

WPFアプリのビルドと起動にはWindowsと.NET 10 SDKを使う。
リポジトリの`global.json`は`10.0.100`を基準に`latestFeature`でロールフォワードする。
10.0.1xxだけへの固定ではなく、同じ10.0の利用可能な後続feature bandも選択対象。

以下のコマンドはリポジトリのルートで実行する。SDK選択もそのディレクトリの`global.json`を基準にする。

```powershell
dotnet --version
dotnet restore ToDoTree.slnx
dotnet build ToDoTree.slnx --no-restore
dotnet run --project src/ToDoTree.App
```

実行時の外部NuGet依存は増やさず、WPFに依存しない計算はCoreへ置く方針。
配色は両テーマのパレットに同名のキーを用意し、UIから参照する。

## 自動テスト

テストはTUnit／Microsoft.Testing.Platform。

```powershell
dotnet test
```

テストプロジェクト自体を実行する方法もある。

```powershell
dotnet run --project tests/ToDoTree.Core.Tests
```

Coreテストはグラフ操作、計画、保存、表示対象の計算、配置、線の経路、ブロック、内部整列、吸着を対象にする。
WPFのフォーカスや実マウスの操作感を自動的に保証するものではない。

2026-09-06のブロック吸着実装時にはビルドとCoreテスト149件が成功した。
これは当日の検証記録であり、今後も件数が149件であることを要求しない。
同日の一時WPF検証ホストによる確認内容は[吸着設計書](BLOCK_SNAP_DESIGN.md)に記録している。
一時ホストはリポジトリに含まれないため、通常のテストコマンドでその確認が実行されるわけではない。

## UI変更後の確認

| 対象 | 確認する操作 |
|---|---|
| 連続入力 | Enterで追加、日本語変換の確定、F2で編集、Escで取消 |
| 接続 | 分岐・合流、線の選択・削除、循環する接続の拒否 |
| 選択と移動 | Ctrl複数選択、背景のAlt矩形選択、個別／一括移動 |
| ブロック | 作成・命名、所属変更、見出し移動、解除、内部整列 |
| 吸着 | 端と中心、境界での手ぶれ、Alt押下・解放、ズーム違い |
| 通過点 | 内部線の追従、外部線の位置保持、滑らかさ、Undo |
| 終了経路 | MouseUp、Esc、キャプチャ喪失、非アクティブ化、タブ切替 |
| 保存 | 手動保存、5秒周期の保存、未保存タブの退避、再起動復元 |
| 見た目 | 明暗両テーマ、カード／ミニマル、異なるズームとOS表示倍率 |

保存や復旧の確認にはコピーしたサンプルを使う。保存先ありの文書は自動保存で本体が更新される。
異常終了の確認を行う場合も、通常利用中のデータと分けた環境を使う。

ブロックの整列や吸着では、対象外のノードが動かないこと、1操作のUndo、取消時のRedo保持も確認する。
機能別の受け入れ条件は各設計書を参照する。

## 文書だけを変更した場合

動作を変えない文書変更では、ビルドやテストを機械的に再実行せず、次を確認する。

- 記述を該当コードと照合する。
- 相対リンクのファイルと必要な見出しが存在する。
- 未実装の案、実装済みの仕様、過去の調査が区別されている。
- `git diff --check`で差分の空白エラーを確認する。

## 作業環境に起因する失敗

SDKやファイルのアクセス拒否と、コードのコンパイルエラーは区別する。
過去のCowork環境に関する制約は、現在のWindows環境にも一律に当てはまるとは限らない。
作業環境の権限に従い、実行できなかった確認は未確認として記録する。
