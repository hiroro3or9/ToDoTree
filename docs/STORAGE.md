# 保存と復旧

更新日: 2026-09-06

対象: 現在のコードによる保存仕様（形式バージョン3）

## 保存するファイル

| ファイル | 用途 |
|---|---|
| ユーザーが指定した`*.todotree.json` | プロジェクト本体。1プロジェクトにつき1ファイル |
| 本体パスに`.tmp`を付けたファイル | 本体の置き換え前に書く一時ファイル |
| 本体パスに`.bak`を付けたファイル | 直前の保存内容を保持する1世代のバックアップ |
| `%APPDATA%\ToDoTree\autosave\<タブID>.todotree.json` | 保存先未指定のタブの復旧用データ |
| `%APPDATA%\ToDoTree\settings.json` | タブ一覧・表示位置・アプリ設定 |

タブIDはハイフンなしのGUID。退避ファイルも本体と同じ保存処理を使うため、`.tmp`や`.bak`を伴う場合がある。

## プロジェクト本体の内容

- プロジェクトのID・名前・説明・形式バージョン。
- タスクのID・タイトル・メモ・種別・状態・期限・完了日時・見積り・タグ・座標・位置固定・作成／更新日時。
- 依存関係のID・接続元／先・ラベル・接続辺指定・通過点の位置／順序／滑らかさ。
- ブロックのID・名前・所属タスクID。

ブロックの境界は所属タスクから計算し、保存しない。
Undo/Redo履歴、検索・選択、フォーカス・枝の折りたたみなどの一時的な表示状態、吸着ガイドは本体の復元対象外。
JSONは改行・インデント付きで、日本語はそのまま出力する。プロパティ名はcamelCase、列挙値は文字列。

## 手動保存

| 操作 | 動作 |
|---|---|
| `Ctrl+S` | 現在のタブを保存。保存先未指定なら保存ダイアログを表示 |
| `Ctrl+Shift+S` | 保存ダイアログを表示し、成功後は新しいパスを使用 |
| 保存ダイアログの取消 | ファイルの保存や保存先の切替を行わない |

保存前に途中のブロック移動・命名を確定する。この確定はダイアログを開く前に行われる。
別タブが使用中の保存先は拒否する。同じファイルを開き直した場合も、既存タブへ切り替える。

保存成功時は未保存の`*`を消し、当該タブの退避本体ファイルを削除する。
失敗時は理由をダイアログで表示し、成功扱いにはしない。

## 自動保存

ワークスペース共通のタイマーが、開いている全タブを5秒周期で確認する。
UIスレッドのタイマーなので、操作や処理状況によって実行時刻は遅れる場合がある。
保存周期の設定画面はない。

| 状態 | 動作 |
|---|---|
| 変更なし | 書き込まない |
| ブロックの移動・命名中 | 書き込まない。確定／取消後の周期で再確認 |
| 保存先あり・変更あり | 本体へ直接上書きし、`*`を消す |
| 保存先なし・変更あり | タブ専用の退避ファイルへ保存し、`*`を維持 |

退避後も未保存状態を維持するため、保存先未指定の変更済みタブは以降の周期でも退避される。
自動保存の編集抑止は現在`IsBlockEditing`によるもので、すべての入力・ドラッグ一般を一括して抑止する仕様ではない。

自動保存の例外は通知せず、作業を継続する。未保存状態は残り、次の周期で再試行される。
成功時の時刻メッセージは保存先ありのタブで表示する。

## 本体の置き換えとバックアップ

1. 保存対象をJSON化して、`<保存先>.tmp`へ書く。
2. 本体があれば`File.Replace`で置き換え、旧本体を`<保存先>.bak`へ残す。
3. 初回保存なら`File.Move`で`.tmp`を本体名へ移す。

本体へ直接書き込まないことで、書き込み途中の不完全なJSONで本体を上書きすることを避ける。
バックアップは手動保存・自動保存で共通の1世代。日時別の履歴ではなく、保存のたびに更新される。
ディスク障害や電源断を含めてデータ消失を完全に防ぐ保証ではない。

`.bak`からの自動復元や専用UIはない。復元を試すときは、アプリを閉じて対象の本体と`.bak`を
別途コピーし、`.bak`のコピーを別名の`*.todotree.json`として開いて内容を確認する。
`.bak`を直接開くとそのパスが自動保存先になるため、コピーを使う。

## タブを閉じる・アプリを終了する

未保存変更があれば「保存する／保存しない／キャンセル」を確認する。
アプリ終了時は全タブのブロック操作を確定してから、未保存タブを順に確認する。

- 保存する: 保存成功後に閉じる。ダイアログ取消や保存失敗なら閉じない。
- 保存しない: メモリ上の未保存変更を破棄する。
- キャンセル: 終了を中止する。

**「保存しない」は、すでに自動保存された本体を元に戻す操作ではない。**
保存先ありのプロジェクトでは、最後の保存以後に残った変更だけが破棄対象になる。

タブを閉じる場合は退避本体を削除する。保存先未指定の変更済みタブを保存せずアプリ終了する場合も、
退避本体を削除してセッションの復元対象から外す。削除失敗は通知しない。
削除対象は退避本体であり、付随する`.bak`や`.tmp`の一括清掃は実装されていない。

## 次回起動時の復元

`settings.json`のタブ一覧に沿って復元する。退避フォルダー全体を走査して復元する方式ではない。

| 記録されたタブ | 復元元 |
|---|---|
| 保存先あり | 指定された本体ファイル。退避ファイルや`.bak`へ自動フォールバックしない |
| 保存先なし | タブIDに対応する退避ファイル。未保存状態として復元 |
| ファイルなし・読み込み失敗 | そのタブをスキップし、他の復元を続ける |

前回の選択中タブがあれば選択し、なければ先頭タブを選ぶ。
旧版の最終ファイル・単一退避ファイルを引き継ぐ経路もある。
何も復元できなければサンプルを表示する。

保存前・最初の退避前の変更や、直近の自動保存以後の変更は異常終了後に復元できない場合がある。
設定が失われた場合、退避ファイルが残っていても自動では発見しない。
必要な退避ファイルは別の場所へコピーしてから「開く」で確認できる。

## 設定ファイル

保存対象はタブのパス・順序・ID・選択中タブ、各タブのズーム／画面位置、配色、カード／ミニマル表示、配置方向。
タブ操作、文書状態の変更、5秒周期の保存処理、正常終了時などに更新する。

設定は`File.WriteAllText`で直接上書きし、本体のような`.tmp`／`.bak`による置き換えは行わない。
読み書きに失敗しても通知しない。読み込めなければ既定の設定で起動する。

## 形式の互換性

現在の`schemaVersion`は3。1・2のファイルはメモリ上で3へ移行し、次の保存で3として書く。
形式3はプロジェクトに1つの`bookmark`（対象の`nodeId`と再開メモ`note`）を保存する。しおりがない場合は省略する。
形式1を名乗るファイルにブロックが入っている場合や、ブロック所属に不整合がある場合は読み込みを拒否する。
存在しないステップを指すしおりも読み込みを拒否する。アプリから対象ステップを削除した場合は、しおりも一緒に外れる。
アプリが対応する値より新しい形式も拒否する。
旧形式の読み込みだけで直ちにファイルを書き換えることはない。
