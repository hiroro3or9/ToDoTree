# ブロック機能の設計

作成日: 2026-09-06  
状態: 基本機能実装済み（実装状況更新: 2026-09-06）
対象: 複数ステップを名前付きの囲みとしてまとめる機能

本文は基本機能の当初設計を残しています。型名・API案・実装順は当時の計画です。
現在の操作は[README](../README.md)、保存の実際の条件は[保存と復旧](STORAGE.md)を参照してください。
後続で[ブロック内整列](BLOCK_LAYOUT_DESIGN.md)と[吸着・ガイド](BLOCK_SNAP_DESIGN.md)を実装しました。
ブロック選択中の`Ctrl+L`は内部整列、見出しドラッグは吸着付きへ更新されています。
折りたたみ・入れ子・複製は未実装です。

## 1. 目的と優先順位

操作感と手触りの向上を最優先する。複数選択したステップを持続するまとまりにし、
「この一帯を動かす」「ここまでが設計だと示す」を少ない操作でできるようにする。

ブロックは整理と移動の単位であり、タスクではない。ブロックを作成・解除しても、
ノード同士の依存関係、着手可能判定、進捗、最長経路、完了予測は変わらない。
接続されていないステップ同士もまとめられる。

成功の基準は、囲みを作った直後から移動・内部編集・解除が迷わず行え、
通常のカード編集やキャンバス移動を邪魔しないこと。

## 2. 初版の範囲

実装するもの:

- 複数選択からのブロック作成、見出しの直接編集。
- 淡い背景と枠、名前、所属件数の表示。
- 見出しをつかんだ一括移動、内部アイテムの通常編集。
- 選択したステップの所属追加・取り外し。
- 囲みだけの解除。
- 自動整列、表示絞り込み、ミニマル表示との共存。
- 保存・復旧・タブ独立性・Undo / Redo。

次段階に回すもの:

- ブロックの折りたたみと外部接続の集約。
- ブロックの入れ子、ブロック同士の複数選択・一括移動。
- ブロックの複製・テンプレート化。色の個別設定は[個別の色分け](COLOR_DESIGN.md)で実装済み。
- 境界をまたぐドラッグによる所属変更、手動リサイズ。
- ブロックを考慮した全体の最適配置。

所属を位置から推測しない。囲みの中を通ったり、カードが重なったりしても所属は変えない。
初版は1ノードにつき最大1ブロックとする。

## 3. 見た目

```text
              外部ステップ
                   │
  ┌ 設計  3件 ─────┼──────────────────┐
  │                ▼                  │
  │  [要件整理] → [画面設計] → [確認] ───→ [実装]
  │                                   │
  └───────────────────────────────────┘
```

- 枠と背景はカードや線より奥。カードの状態色を主役にする。
- 見出しと枠は選択時に強調。ホバー時は見出しをつかめると分かるカーソルを出す。
- 本体の空白部分は通常のキャンバスと同じで、背景ドラッグによるパンを妨げない。
- 枠は接続先にせず、エッジルーティングの障害物にも含めない。
- 見出しは枠の上端に置く。線と重なっても読める不透明な下地を使う。
- 名前が長い場合は省略表示とツールチップ。編集中は全文を編集できる。
- ライト／ダークに共通のリソースキーを追加し、文字と選択枠の視認性を確認する。

境界は保存せず、所属ノードの表示矩形の外接矩形から計算する。
初期値は左右・下の余白を24 DIP、上に見出し32 DIPと余白12 DIP。
これはキャンバス座標の寸法であり、実際の表示で調整する。
ミニマル表示では丸の固定寸法を使い、ホバーで出る名前には追従させない。

囲みが重なっても所属は変わらない。見出しのヒット判定は描画順と一致させ、
選択中のブロックをブロック層内の最前面にする。

## 4. 操作仕様

### 4.1 作成と命名

1. 未所属のステップを2件以上選択する。
2. `Ctrl+G` または右クリックの「ブロックにまとめる」を実行する。
3. 位置と接続を保ったまま囲みを出し、見出し入力にフォーカスする。
4. 初期名「新しいブロック」を全選択し、そのまま入力できる。
5. Enterまたは外側クリックで確定。空白だけなら初期名を採用する。

日本語変換中のEnterは変換確定だけに使い、編集中はグラフのショートカットを抑止する。
新規作成中のEscは囲みの作成ごと取り消し、元のノード選択へ戻す。
作成と最初の命名は1回のUndoで戻る。

所属済みノードが含まれる場合は新規作成を無効にし、
「所属を外してからまとめてください」と理由を表示する。既存のまとまりを暗黙に解体しない。

### 4.2 選択と名前の変更

| 入力 | 動作 |
|---|---|
| 見出しをクリック | ブロックを選択。所属ノードは補助強調するが、ノードの複数選択にはしない |
| 内部カードをクリック | 通常のノード選択に切り替える |
| 見出しをダブルクリック／選択中にF2 | 見出しを直接編集 |
| 名前編集中のEsc | 編集前の名前へ戻す |
| 選択中にEsc／背景をクリック | 選択を解除 |
| 右クリック「中のステップを選択」 | 所属ノードの複数選択へ切り替える |

ブロック選択とノード・エッジ・通過点選択は排他的にする。
ブロック選択中のEnter、Space、Deleteにはタスクの追加・完了・削除を割り当てない。
囲みの解除は明示した操作だけで行う。
ノードの矩形選択やCtrl+Aは従来どおりノードを対象にし、囲みは対象外。

### 4.3 ブロックの移動

- 見出しをドラッグすると全所属ノードを同じ差分だけ移動する。内部の相対配置は保つ。
- 開始判定は画面座標でWPFのドラッグしきい値を使い、ズーム倍率に左右されないようにする。
- 差分は押下時のワールド座標から算出する。毎フレーム加算して誤差を蓄積しない。
- マウスキャプチャで画面外への移動にも追従し、MouseUpで確定する。
- Esc、予期しないキャプチャ喪失、タブ切替時は移動を取り消す。確定に伴う通常のキャプチャ解放とは区別する。
- 微小移動や元の位置に戻した操作では履歴も未保存状態も増やさない。
- 固定済みノードも手動移動には参加する。各ノードの`IsPinned`の値は変更しない。

線の通過点の扱い:

| 線 | 移動時の通過点 |
|---|---|
| 両端とも移動対象 | 全通過点を同じ差分で移動。滑らかさ設定を保つ |
| 片端だけ移動対象 | 通過点の座標は保持し、接続部分を再計算 |
| 両端とも対象外 | 変更しない |

囲みの境界はノードだけから算出し、外へ迂回した通過点によって巨大化させない。
全体表示では従来のノード・通過点に加え、囲みと見出しの範囲も含める。

### 4.4 所属の追加・取り外し

- ノード選択の右クリックに「ブロックに追加」サブメニューを出し、既存ブロック名を選ぶ。
- 初版の追加対象は未所属ノードのみ。所属先が混在した選択では追加を無効にする。
- 「ブロックから外す」は選択ノードの所属だけを取り除き、位置と接続を維持する。
- 各操作は複数ノード分をまとめて1回のUndoで戻す。
- 残り1件でも囲みを維持する。0件になった囲みは同じ操作内で取り除く。
- 内部ノードを普通にドラッグした場合、所属は保持し、囲みの境界が追従する。
- 外部ノードが幾何学的に囲みの中へ入っても自動加入しない。
  ブロック選択中は所属ノードだけを補助強調して区別できるようにする。

既存の追加操作との関係:

| 既存操作 | 新しいノードの所属 |
|---|---|
| 所属ノードからEnter／Shift+Enterで追加 | 起点のブロックを引き継ぐ |
| 所属ノードの続きへアウトラインを取り込む | 取り込んだ全ノードが起点のブロックを引き継ぐ |
| ステップを分割 | 分割で生成されたノードが元の所属を引き継ぐ |
| 線にステップを挟む | 両端が同一ブロックの場合のみ、その所属を引き継ぐ |
| 背景から追加／起点なしの取り込み | 未所属 |

所属更新はノード生成と同じ履歴単位に含める。

### 4.5 解除とノード削除

- 選択したブロックで`Ctrl+Shift+G`、または見出しの右クリック「ブロックを解除」。
- 囲みと所属情報だけを除去し、内部ノードと全接続・通過点を保持する。
- 解除後は元の所属ノードを複数選択し、そのまま移動を続けられるようにする。
- 「ブロックごとタスクを削除」は初版には設けない。
- 通常のノード削除では、既存の前後の接続し直しに加えて所属IDを取り除く。
  最後の所属ノードの削除による囲み消去も、同じUndoで復元する。

## 5. 既存機能との整合

### 自動整列

初版の`Ctrl+L`は、ブロック所属ノードを一時的な固定対象として、未所属ノードを整列する。
所属ノードの座標と内部の通過点は保持する。モデルの`IsPinned`を書き換えず、
レイアウト計算のオプションとして固定ID集合と囲みの占有領域を渡す。
未所属ノードの配置先は囲みと重ならないようにする。
「ブロックの配置を保持して整列しました」とステータスに示す。

全ノードがブロック所属または固定済みなら、位置変更とUndo追加を行わない。
方向切替でも所属ノードの配置は保持する。この制約はメニューの説明に含める。
一時固定や占有領域が現在のレイアウトで正しく扱えるかは、実装時にテストして補強する。

グループを1ノードへ縮約して既存のDAGレイアウトへ渡す方法は初版で採用しない。
例えば`A → X → B`でAとBを同じブロックにすると、縮約後は`ブロック → X → ブロック`となる。
元がDAGでも縮約後に循環し得るため、将来の全体配置では別途対処が必要。

### 検索・折りたたみ・表示絞り込み

- 検索・タグで薄くなるだけなら通常の境界を維持。ノード検索の対象は変更しない。
- 完了非表示、枝の折りたたみ、フォーカスモードでは、可視の所属ノードから境界を計算する。
- 一部が非表示なら見出しに「表示3 / 全5件」と示す。全件非表示なら囲みも隠す。
- 隠れた所属ノードがあるときは、見えないものを動かさないようブロック移動を無効にする。
  見出しに理由を表示する。可視カードの個別編集と囲みの解除は可能。
- 選択ブロックが非表示になった場合は選択を解除する。
- ミニマル表示への切替は境界表示だけを再計算し、座標・所属・履歴を変更しない。
- ミニマップには囲みの外周を控えめに表示し、独自の選択操作は増やさない。

### 保存・書き出し

保存、自動保存、未保存タブの復旧にはブロック情報を含める。
タブ切替で選択状態が混ざらないよう、ブロック選択は各`MainViewModel`が所有する。
Markdown / Mermaid書き出しは初版では既存のタスク・接続の内容を維持し、囲みは出力しない。
書き出し画面に「ブロックの囲みは含まれません」と表示する。

## 6. データ設計

追加案:

```csharp
public sealed class TodoBlock
{
    public Guid Id { get; set; } = Guid.NewGuid();
    public string Title { get; set; } = "新しいブロック";
    public List<Guid> NodeIds { get; set; } = [];
}

// TodoProject
public List<TodoBlock> Blocks { get; set; } = [];
```

- 所属の正本は`TodoBlock.NodeIds`のみ。ノード側に`BlockId`を重複保存しない。
- ノード→所属ブロックの辞書は派生インデックスとして構築・更新する。
- 座標は既存の`TodoNode.X/Y`だけを保存し、ブロックの位置・幅・高さは派生値にする。
- `TodoProject.DeepClone()`にブロックと所属IDリストのディープコピーを追加する。
- ブロック名は重複可能。操作と参照はIDで行い、追加先メニューには件数も添える。
- 初版には`IsCollapsed`や親ブロックIDを先行追加しない。

### 形式の互換性と検証

基本機能の追加時に`CurrentSchemaVersion`を1から2へ上げた。旧形式は`Blocks = []`として
読み込み時にメモリ上で移行し、次の保存では2を書き込む。
旧アプリの既存の新形式拒否処理により、ブロック情報を落として上書きすることを防ぐ。

読み込み時と変更確定前に次を検証する:

- ブロックIDの重複がない。
- 所属IDが実在し、同一リスト内に重複がない。
- 同じノードが複数ブロックに所属しない。
- 空のブロック、nullのブロック・所属リストを許容しない。
- タイトルのnullや空白は既定名に正規化する。

旧形式での`Blocks`欠落は正常とする。不正な新形式は具体的な理由付きで読み込みを中止し、
元ファイルを上書きしない。UI上の通常操作による0件ブロックは検証前に除去する。

### 履歴とドラッグのトランザクション

現状は`PushUndo()`がRedoを消去し、プロジェクト全体をコピーする。
そのままドラッグ開始に使って後からUndoだけ捨てると、キャンセル時にRedoが失われる。

ブロック操作は変更前スナップショットを一時保持する方式にする。
プレビュー中はUndo/Redoを変更せず、確定して実際の差分がある場合だけ
変更前状態をUndoへ追加し、Redoを消去する。キャンセルでは座標・名前・未保存状態を戻す。
プレビュー中はその文書の自動保存を見送り、確定・取消後に通常の保存周期へ戻す。
明示的な保存と文書終了処理は編集中操作を確定してから実行する。

既存履歴は選択ノード1件しか復元していないため、履歴エントリに選択種別とID集合を
持たせる。ブロック解除のUndoではブロック選択、作成のUndoでは元のノード選択へ戻す。
選択情報はプロジェクトJSONには含めない。

### 描画負荷

移動中に毎回`RefreshAll()`や全グラフの解析を呼ばない。
変更ノード、接続辺、所属ブロックの境界に絞って更新し、同一フレームの更新をまとめる。
エッジの迂回では障害物の移動に影響される非接続辺もあるため、確定時には全辺を再検証する。
ドラッグ中の保存用スナップショット作成は開始時の1回に抑える。

## 9. 受け入れ条件

### 自動テスト

- 作成・追加・取り外し・解除でノード数、エッジ集合、着手可能判定が変化しない。
- 同じノードの二重所属を拒否でき、失敗時に部分変更が残らない。
- 0件の囲みの除去と1件の囲みの保持が正しい。
- ノード生成・分割・線への挿入・削除で所属規則が守られる。
- ブロック移動で相対座標と固定フラグを保ち、内部・外部の通過点を仕様どおり扱う。
- 作成、名前変更、移動、所属変更、解除、ノード削除を1操作単位でUndo/Redoできる。
- 取消と無変更操作でRedo、未保存状態、履歴件数が変わらない。
- 新形式の往復保存、旧形式移行、破損した所属情報の拒否、DeepCloneの独立性。
- 自動整列で所属ノードが動かず、未所属ノードが囲みに配置されない。
- 表示絞り込み時の境界・件数・移動可否と、全体表示の範囲が正しい。

### 実際のWPF画面で確認する操作

1. 10件を書き、3件を選択してまとめ、日本語のブロック名を入力する。
2. 25%、100%、200%のズームで見出しをクリック・ドラッグする。押した瞬間に位置が跳ねない。
3. 内部カードを編集・移動・接続し、囲みが操作を奪わないことを確認する。
4. 内部の線に角と滑らかな通過点を置き、ブロック移動で形が保たれることを確認する。
5. ドラッグ中のEsc、タブ切替、キャプチャ喪失から復帰し、Undo/Redoを続ける。
6. 追加・取り外し・解除後も入力フォーカスと選択が自然に続くことを確認する。
7. 完了非表示、フォーカス、枝の折りたたみ、ミニマル表示、配色を切り替える。
8. 自動保存、明示保存、再起動復元で所属・名前・座標を確認する。

性能の検証用データは、100ノード／150辺／10ブロックを通常ケース、
300ノード／450辺／30ブロックを負荷ケースとする。通過点付きの辺も含める。
検証機の環境とフレーム時間を記録し、通常ケースでドラッグ更新の95パーセンタイルを
16.7 ms以内、100 msを超える停止なしを目標とする。これは未計測の目標値であり、達成済みではない。

## 10. 次段階: 折りたたみ

初版の手触りが安定してから設計を具体化する。

- 初版のダブルクリックは名前編集に統一し、折りたたみは専用の開閉ボタンを追加する。
- 折りたたみカードは名前と完了件数を表示し、内部ノードの保存座標は保持する。
- 表示上だけ外部接続を集約し、実際の辺とノードIDは保持する。
- 同一相手への複数の辺は束ね、件数と元の接続を確認できるようにする。
- 集約線の削除・接続追加をどの実ノードへ適用するかを曖昧にしない。
  最初は展開してから編集する方式を候補とする。
- 折りたたみ状態での移動は内部ノードと内部通過点へ同じ差分を適用する。
- 表示上の循環、検索による展開、枝の折りたたみとの優先順位を別途決める。
