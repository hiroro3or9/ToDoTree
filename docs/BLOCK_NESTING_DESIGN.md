# ブロックの入れ子設計

作成日: 2026-09-09  
状態: 初版実装済み（2026-09-10）  
対象: ブロック内への子ブロックの作成、既存ブロックの移籍、階層を保った編集

## 1. 方針

ブロックを親子関係のある囲みとして扱う。ステップは直近のブロックにだけ所属し、
親ブロックの移動・件数・依存条件には子孫のステップも含める。
階層は整理の関係であり、親子にするだけで内部に実行順序を追加しない。
ただし接続済みブロックへの加入・離脱は、既存仕様と同様に外部への依存条件を変える。

```text
┌ リリース準備  全5件 / 子ブロック2個 ─────────────┐
│ [方針確認]                                      │
│ ┌ 設計  全2件 ──────────┐ ┌ 実装  全2件 ─────┐ │
│ │ [画面設計] → [レビュー]│ │ [開発] → [確認]   │ │
│ └───────────────────────┘ └───────────────────┘ │
└────────────────────────────────────────────────┘
```

初版に含めるのは、同じ親のステップからの子ブロック作成、既存ブロックの移籍・取り外し、
再帰的な描画・移動・折りたたみ・接続・解除、保存・部品化・Undo/Redoへの対応。
ブロックの複数選択、ステップとブロックの混在選択、空ブロック、手動リサイズは後続とする。
構造は任意段数の木を許し、深い階層は集中表示で編集する。走査には循環検出と明示的なスタックを使う。

## 2. 操作

| 入力 | 結果 |
|---|---|
| 同じブロックに直接所属するステップを2件以上選択して `Ctrl+G` | その親の中に新しい子ブロックを作り、選択ステップの直接所属を移す |
| 未所属ステップを2件以上選択して `Ctrl+G` | 従来どおり最上位ブロックを作る |
| 所属先が混在したステップで `Ctrl+G` | 無効。「同じブロック内のステップを選んでください」 |
| 見出し右クリック「ブロックに入れる」 | 選んだブロック全体を指定先の直接の子へ移籍する |
| 見出し右クリック「親ブロックから外す」 | 一段上へ移す。最上位では無効 |
| 見出し右クリック「このブロックを包む」 | 同じ位置に新しい親を作る。既存の親があれば、その親の子として挿入する |
| 見出しの通常ドラッグ | 所属を維持し、子孫をまとめて平行移動する |
| 見出しを `Shift`＋ドラッグ | ドロップ先の子にする。全候補の外なら最上位へ移す |
| `Ctrl+Shift+G`／「ブロックを解除」 | 選択した囲みだけ解除し、直接の中身を一段上へ戻す |

追加先メニューは「リリース準備 / 設計」のような階層パスと件数を表示する。
同名の候補は短いIDも添え、内部操作は常にIDを使う。自分・子孫・現在の親は候補から除く。
メニューによる移籍は座標を維持し、親の囲みを広げる。「入れる」ための自動整列は行わない。
作成と最初の命名はUndo1回。命名中のEscでは作成前の階層と選択へ戻す。

ドラッグ先は開始時点の可視矩形で判定する。見出しをつかんだポインター位置を基準に、
最も深い有効な候補、同じ深さなら面積の小さい候補、同面積なら描画の前面を優先する。
候補全体の強調と「設計の中へ移動」の表示を出す。現在の親もドロップ判定には残し、同じ親なら所属変更なしとする。
自分や子孫に重なる場合は無効先として示し、外側への移籍と誤解しない。
循環などで無効なドロップは位置も含めて全取消。Shiftを離した場合は位置だけを確定する。
折りたたまれたブロックも受け入れ先とし、成功したら先を展開して移動した子を選択する。
既存のステップのShiftドラッグも同じ候補優先順位を使い、直接所属先だけを変更する。

## 3. データモデルと検証

`TodoProject.Blocks` の平坦なリストを維持し、`TodoBlock` に次のフィールドを追加する。

```csharp
public Guid? ParentBlockId { get; set; } // null は最上位
```

- `NodeIds` は直接所属するステップのみ。子孫のIDを親へ重複保存しない。
- 子ブロック一覧は `ParentBlockId` から導出し、`ChildBlockIds` は保存しない。
- 位置は既存のステップの絶対座標を正本とする。親に対する相対座標へは変換しない。
- `IsCollapsed`、色、接続点は各ブロックが独立して持つ。親の色は子の設定を上書きしない。
- ブロック単体では `NodeIds.Count == 0` を許すが、子孫に最低1件のステップが必要。

検証は、ID・参照先 → 所属階層 → 非空条件 → 接続点 → 展開後の依存関係の順で行う。
自己参照、存在しない親、親子の循環、ステップの二重直接所属を拒否する。
親に孫のステップIDを重複登録することも二重直接所属として拒否する。
不正ファイルの階層を `Prune` で勝手に平坦化せず、理由を示して読み込みを止める。

新しい `BlockHierarchy` は親・子・直接所属の索引を作り、次の問い合わせを集約する。

| API案 | 用途 |
|---|---|
| `DirectOwnerOf(nodeId)` | ノード追加時の所属継承、直接の移籍 |
| `ChildrenOf(blockId)` / `AncestorsOf(blockId)` | 描画順、親の更新、候補除外 |
| `DescendantNodeIds(blockId)` | 接続展開、件数、移動、集中表示 |
| `IsAncestorOf(ancestorId, blockId)` | 循環防止、レイアウト障害物の除外 |

既存の `BlockService.BlockOf` は直接所属の意味を維持する。
`NodeIds` の参照を一律に再帰集合へ置き換えず、編集には直接所属、集計には子孫集合を使い分ける。
索引は構造変更・読み込み・Undo/Redoで再構築する。全子孫集合の常時保存は避け、
必要な集合を処理単位でキャッシュして、ドラッグの毎フレームに全階層を走査しない。

## 4. 囲み・移動・表示

囲みは子から親へ計算する。展開中の囲みは「可視の直接ステップ矩形＋可視の直接子ブロック矩形」
の外接矩形に既存の余白と見出し高さを加える。子の見出しも必ず親の内側に入る。
件数と完了件数は子孫の実ステップを一度ずつ集計し、ブロック自体はタスク数や工数に加算しない。

折りたたみカードの位置は、全子孫を展開した場合の境界の左上を基準にする。
これを折りたたみ用の基準境界として表示境界と分け、子の展開状態でカード位置が飛ぶのを防ぐ。
非表示フィルターは囲みの表示境界へ反映し、基準境界には反映しない。
全件がフィルターで隠れた場合は囲みも隠す。折りたたみだけによる非表示とは区別する。

- 背景と見出しは祖先から子孫へ描画する。選択した親を子の前面へ出さない。
- ヒット判定は描画順と合わせ、子の見出し・接続点の入力が親へ二重に伝わらないようにする。
- 背景の空白は従来どおりキャンバスのパンに使う。選択は見出しまたは枠で行う。
- 親の移動は子孫ノード集合を一度だけ動かす。子の移動はその子孫だけを動かし、祖先の境界を再計算する。
- 固定フラグを維持し、固定ノードも手動の一括移動に含める。
- 両端の解決先ステップ集合がすべて移動対象である線は通過点も同じ差分で移動する。
  片側だけの線は通過点を維持する。線IDで重複排除し、1本を複数回動かさない。
- 吸着候補から移動部分木とその祖先を除外する。祖先は追従して伸縮するため、固定した目標にしない。
- 全体表示、ミニマップ、スクロール範囲にも子孫を含む表示境界を使う。

親を畳むと子ブロックと全内部ステップを隠すが、子の `IsCollapsed` は変更しない。
親を開けば子の展開状態を復元する。隠れた子が選択されていた場合は畳んだ親を選択する。
フィルターによる部分非表示がなければ、畳まれた子孫を含む一括移動を許可する。

集中表示は対象の全子孫ステップと直接の先行・後続を対象とする。
対象とその子孫を表示上だけ展開し、祖先の囲みは省いて階層パスを表示する。
終了時は元のフィルター・展開状態・視点へ戻す。集中先の変更でも最初の復帰先を保つ。
しおりや「内部ステップを表示」は目的の端点までの祖先をすべて開く。

## 5. 接続と投影

`BlockConnections.Members` と `Expand` はブロック端点を全子孫ステップへ解決する。
例えば「親A → 親B」はAの全子孫からBの全子孫への依存となる。
親とその子・内部ステップの接続は、解決先が重なって自己依存を作るため拒否する。
兄弟間の接続は許可し、展開したグラフ全体で循環がないことを確認する。

特に `A → B` があるときBをAへ入れると、Aの端点集合にBの中身が加わり自己依存が生じる。
これを所属変更時に拒否する。階層の循環チェックだけでは足りない。
作成・加入・移籍は候補プロジェクトで階層と接続を検証してから一括反映する。
失敗理由は「移動すると『確認』が自分自身の先行条件になります」のように対象を示す。

実線／破線は線全体ではなく各端点の表示解決結果から決める。

| 状態 | 表示 |
|---|---|
| 実際の端点が可視 | 元の端点へ接続。可視ブロック自身の接続点を使う |
| 端点が祖先の折りたたみで隠れた | 外側から最初に出会う折りたたみ祖先へ投影 |
| 片側でも投影された | 破線。投影側には祖先の標準位置を使い、子の接続点は編集しない |
| 両端が同じ表示ブロックへ投影された | 内部線として非表示 |

保存上は元のブロックID・ステップID・接続点IDを維持する。
例えば子ブロックの実線も親が畳まれると破線になり、展開すると元の接続点へ戻る。
投影中の線は通過点を隠し、「内部の接続を表示」で必要な祖先を開いてから編集する。
可視の実端点側に指定された接続点は、片側が投影中でも反映する。

## 6. 解除・削除・整列

囲みの解除では、直接ステップを元の親へ移し、直接子ブロックの `ParentBlockId` を元の親へ付け替える。
最上位を解除した場合は、それぞれ未所属・最上位に戻る。孫以下の関係、座標、状態を保持する。
解除した囲みを端点に持つ線だけを、解除前の全子孫ステップへ展開する。
子ブロックを端点に置き換える方式は、後から子へ追加したステップにも条件が及ぶため採用しない。
解除前後の展開済み依存集合を一致させ、重複する直接線は増やさない。
解除した端点の接続点参照だけを外し、他端の接続点、ラベル、通過点などは既存解除仕様に従う。
解除後は元の親を選択し、最上位だった場合は選択解除とする。Undoでは解除したブロック選択を戻す。

通常の削除・移籍で空になった囲みは、子から親へ除去する。
直接ステップが0件でも子ブロックが残る親は削除しない。
空囲みの端点の線も同じ操作で除去する。「ブロックごとタスク削除」は追加しない。

内部整列は初版では子ブロックを持たない囲みだけ対応する。
親での `Ctrl+L` は「子ブロックを選ぶと中を整列できます」と理由を表示する。
葉の整列では祖先を障害物から除外し、兄弟や祖先に直接所属する外部ステップとの衝突を検証する。
整列で伸びた祖先の囲みについても、その外の囲み・ノードとの衝突を確認する。
全体整列はブロック所属ノードを固定し、最上位ブロックの占有領域を使う従来方針を維持する。
親内で子を一つの箱として並べる機能は後続とする。縮約後は元がDAGでも循環し得るため、
既存のDAG整列へそのまま渡さない。

## 7. 保存・履歴・再利用

保存形式は8。1〜7は `ParentBlockId = null` として読み込む。
旧形式を名乗るデータに非nullの親参照がある場合は読み込みを拒否する。
8以降の階層を読めない旧アプリは新形式拒否により上書きを防ぐ。
この設計段階では現在の保存仕様やバージョンを変更しない。

- `TodoBlock.Clone` の親IDを保持し、プロジェクト全体の複製では同じID関係を維持する。
- 操作の差分検出に親IDを追加する。位置を動かさない移籍もUndo対象にする。
- 自動保存・復旧・保存前検証は同じ階層検証を使う。
- ドラッグは既存トランザクションを拡張する。位置、通過点、親ID、空囲み除去、展開状態をUndo1回にまとめる。
- Esc、キャプチャ喪失、非アクティブ化、タブ切替は全取消。Redo・未保存状態・選択も戻す。
- 無変更では履歴を増やさない。プレビュー中は自動保存を保留する。

部品のキャプチャでは選択ステップを含むブロックと必要な祖先を残し、直接所属を選択範囲に絞る。
子だけを含む親も残す。ブロック選択からの部品化は全子孫ステップを選択集合とする。
外部ステップと外部への線は含めず、残した端点同士の線と接続点を保持する。
配置時は全ブロック・ステップの新ID対応表で親IDも再割り当てし、未着手・展開状態へ戻す。
部品ストアの旧形式移行も更新し、子孫参照や削除済み親への参照を残さない。
Markdown / Mermaid書き出しは従来どおり展開したステップ間依存を出力する。

| 4 | Core/Layout/BlockGeometry.cs、BlockSnapService.cs、BlockLayoutService.cs | 再帰境界、移動集合、祖先を除いた吸着・衝突判定 |

| 6 | App/Controls/GraphView.xaml、GraphView.BlockFeatures.cs、BlockPorts.cs、Snap.cs | 描画順、メニュー、ドロップ候補、投影端点操作 |

表の省略ファイル名は同じ接頭辞・ディレクトリを指す。
ステップの追加・分割は直接所属を継承する。線への挿入も、両端ステップが同じ直接所属の場合だけ継承し、
共通の祖先があるだけでは所属を付けない。グラフの解析・繰り返し・完了予測は再帰展開後の依存を使う。
全実装後に操作説明、保存仕様、JSON形式、文書の実装状態を更新する。

## 9. 受け入れ条件

1. 3段以上の階層と、直接ステップを持たない親を作成・保存・復元できる。
2. 自分への移籍、子孫への移籍、不在親、二重直接所属、階層循環を部分変更なく拒否する。
3. `A → B` のBをAへ入れる操作を依存循環として拒否し、位置・Redoも復元する。
4. 外部から親への接続が全子孫の着手条件になる。親子の存在だけでは実行順序を増やさない。
5. 親移動で各ノード・内部通過点が1回だけ動き、子移動で兄弟・外部は動かない。
6. 親を畳んで開いても子の折りたたみ状態を保ち、投影線は外側の可視祖先に接続する。
7. 親が隠した子ブロック端点も投影でき、展開で元の接続点を復元する。
8. 解除前後で展開した依存集合、ステップ数、状態、座標が一致し、子孫の囲みが残る。
9. 最後の直接ステップを移しても、子が残る親は消えない。完全に空なら祖先まで必要な分だけ除去する。
10. 位置不変の移籍もUndo/Redoでき、キャンセルと無変更で履歴・未保存状態が変わらない。
11. 葉の内部整列が祖先との包含を衝突扱いせず、兄弟・外部との新たな衝突は拒否する。
12. 旧プロジェクト・旧部品は平坦なまま移行し、新形式の不正階層は元データを変更せず拒否する。
13. 部品配置で親IDが新ブロックを指し、部分選択でも空親・宙に浮いた親参照を作らない。
14. 集中表示・しおり・完了非表示・ミニマル表示・繰り返し項目が、隠れた子孫でも整合する。
15. WPFの明暗テーマ、IME編集中、ズーム、親子見出しのヒット判定、Shift解除、タブ切替を実操作で確認する。

Coreは階層・接続・解除・保存・部品のテストを追加し、既存のBlock系テストを回帰確認する。
AppのSmokeTestsは親IDだけの変更履歴、折りたたみ投影、取消、描画を対象とする。
性能は100ノード・20ブロック・深さ5の移動を通常ケース、1000ノード・200ブロック・深さ20を負荷ケースとし、
ドラッグ中の境界再計算範囲と依存展開回数を測る。毎フレームの依存グラフ再構築は避ける。
階層・接続・解除・保存・部品の Core テストと WPF スモークテストを実装済み。
実マウス・IME・大規模データでの性能目標は引き続き手動確認の対象とする。
