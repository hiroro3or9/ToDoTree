# カード移動の位置合わせと吸着

作成日: 2026-09-07  
状態: 初版実装済み（2026-09-07）。ビルド・テスト・実操作の確認は未実施  
対象: カード（ステップ）をドラッグしたときの、他のカード・ブロックとの位置合わせ

## 1. 目的

[ブロック吸着](BLOCK_SNAP_DESIGN.md)で作った操作感を、カードの移動へ広げる。
カード表示でもミニマル表示でも、近くのカードやブロックの囲みと端・中心が揃う位置へ
軽く吸着し、破線のガイドを出す。ROADMAP の優先2番「カード単体・複数選択への吸着拡張」。

微調整の往復を減らすことが目的で、整列そのものを自動化するものではない。
吸着先が頻繁に切り替わる、遠くへ引っ張られる、狙った位置に置けない、といった挙動を避ける。

今回入れないもの: 等間隔配置、グリッド、通過点の吸着、サイズ変更、衝突回避、
吸着をきっかけにした所属変更、ズーム連動の自動整列。

## 2. 切り替えの持ち方

**吸着の入切はドラッグ中の `Alt` だけで行う。** 常設のスイッチも設定項目も足さない。
ブロック見出しの移動と同じキー・同じ意味にし、覚えることを増やさない。

| | 吸着する | 吸着しない |
|---|---|---|
| 操作 | そのままドラッグ | ドラッグ中に `Alt` を押す（押し始めから押していてもよい） |
| ガイド | 揃った軸だけ破線 | 出さない |
| 対象 | カードもブロック見出しも同じ | 同上 |

`Alt` の押下・解放はマウスを動かさなくても即座に反映する。
解除では補正していた分だけ位置が戻る。新しいドラッグ原点を作り直さず、
押下位置に対するポインターの移動量へ戻す。

将来「常に吸着しない」を保存したくなった場合は、`AppSettings` に真偽値を1つと
「表示」メニューのチェック項目を足すだけで載る。設計上そこは開けておくが、今回は作らない。

## 3. 現在の実装との接点

| 場所 | いまの役割 | 今回の扱い |
|---|---|---|
| `GraphView.BeginDrag()` | 選択カード群の、ポインターからの相対位置を控える | 開始座標・外接矩形・吸着先の一覧も控える |
| `GraphView.OnViewportMouseMove()` | `ポインター + 相対位置` を各カードへ代入 | `開始座標 + 補正済み差分` へ置き換える |
| `MainViewModel.UpdateNodeDragWaypoints()` | 内部通過点を同じ差分で運ぶ | 補正済み差分を渡す |
| `MainViewModel.BeginNodeDrag()` / `FinishNodeDrag()` / `CancelNodeDrag()` | Undo のトランザクション | 変更しない |
| `GraphView.UpdateMembershipPreview()` | Shift でのドロップ先の下見 | ポインター基準のまま。吸着で判定を変えない |
| `BlockSnapService`（Core） | 囲みの吸着計算 | そのまま使う。矩形の吸着計算であって囲み専用ではない |
| `AlignmentGuideLayer` | ガイド描画 | そのまま使う |
| `NodeViewModel.CardWidth` / `CardHeight` | 表示モードで変わる箱の寸法 | そのまま使う |

`NodeViewModel.CardWidth` は `NodeMetrics` を見ているので、
カード表示（224×88）とミニマル表示（24×24）の違いは矩形の寸法として自然に入る。
**吸着側に表示モードの分岐を書かない。** 書くと、次に寸法を変えたときに二重管理になる。

`BlockSnapService` の型名は据え置く。囲みとカードの両方から使う共通計算だと分かるよう、
クラスの要約だけ「矩形の吸着」と書き直す。改名はテストとファイル名にしか効かないので行わない。

## 4. 操作仕様

| 操作 | 動作 |
|---|---|
| カードをドラッグ | 近くのカード・ブロックとの位置合わせを有効にする |
| 端・中心が吸着範囲に入る | 一致する座標へ補正し、ガイド線を表示 |
| 吸着した座標からさらに引く | 解除距離を超えたら自由移動へ戻る |
| ドラッグ中に `Alt` | 即座に吸着を解除し、ガイドを消す |
| `Alt` を離す | 現在の未補正位置から候補を探し直す |
| `Shift` を押しながら離す | 従来どおりドロップ先ブロックへ所属を変更。吸着とは独立 |
| MouseUp | 最後のポインター位置と `Alt` 状態で再評価して確定 |
| Esc | 押下前へ戻す。ガイドと吸着状態を破棄 |

### 既存ジェスチャーとの優先順位

- カードの上で押した場合は、`Alt` の有無にかかわらずカード移動を優先する（現状と同じ）。
  `Alt` を押したまま掴めば、最初から自由移動になる。
- 背景からの `Alt`＋ドラッグは従来どおり矩形選択。一度決まったジェスチャーは
  途中の `Alt` 操作で種類を切り替えない。
- 名前の入力中は通常のテキスト編集を優先し、移動を開始しない。
- ドラッグ中の `Alt` はメニューのアクティブ化へ流さない。ドラッグ中のキー処理だけで消費する。
  ブロック移動で既に同じ扱いをしているので、判定を `_blockPress` から
  「カード移動中も含む」へ広げる。

## 5. 吸着対象と幾何

### 移動元

ドラッグ開始時に決めた**移動群の外接矩形**を固定して使う。途中で読み直さない。

- 単体選択: そのカードの矩形。
- 複数選択: 可視な選択カードすべての外接矩形。
  補正は群全体へ1つの差分として当てるので、**カード同士の相対配置は崩れない**。
- 非表示のカードは群に入れない（現状の `_dragGroup` と同じ条件）。

### 対象

同じ文書の、次を満たすものをドラッグ開始時にスナップショットする。

| 種類 | 含める条件 |
|---|---|
| カード | 可視で、移動群に入っていない |
| ブロックの囲み | 可視で、**移動群のカードを1件も含まない** |

移動群を含むブロックの囲みは、カードが動けば囲みも動くので対象にしない。
畳んだブロックの中のカードは個別には見えないので、囲みだけが対象になる。
検索やタグで薄くなるだけのものは対象に含める。

ビューポートと部分的にでも交差しているものだけを採用する。
ドラッグ中のズーム・パンは後述のとおり抑止するため、画面への出入りで候補を入れ替えない。

### 揃える線

| 軸 | 移動元・対象で比較する座標 |
|---|---|
| X（縦ガイド） | 左端、横方向の中心、右端 |
| Y（横ガイド） | 上端、縦方向の中心、下端 |

同じ種類のアンカーだけを比較する（左端同士、中心同士、右端同士）。
異なる端を突き合わせる隣接配置は今回も提供しない。
ブロックの矩形は見出しの帯と余白を含む囲み全体で、これは既存の吸着と同じ。

X と Y は独立に吸着でき、異なる対象へ揃ってもよい。
無関係に遠いものへ揃わないよう、直交軸の矩形間隔が画面上160 DIP 以内の候補に限る。

### ミニマル表示での見え方

箱が 24×24 なので、左端・中心・右端は 12 ワールド単位ずつしか離れていない。
100% 表示では吸着開始が 6 DIP なので候補は重ならないが、25% 表示では
開始距離が 24 ワールド単位になり、左端・中心・右端が同時に候補へ入る。
順位付けは「画面上の移動距離 → 直交間隔 → アンカー種別 → ID」で決まっているので
結果は一意になる。実操作で違和感が出たら、開始距離ではなく
**箱の寸法に応じた上限**（例: 幅・高さの 1/4）を足して詰める。初版は既存の距離のまま出す。

ミニマル表示では名前が箱の外へ出る。揃うのは箱であって、名前の長さは揃わない。これは仕様とする。

## 6. 距離と吸着状態

既存の `BlockSnapOptions` の初期値をそのまま使う。カード用に別の値を持たせない。

| 項目 | 値（ビューポート上の DIP） |
|---|---:|
| 新しく吸着する距離 | 6 |
| 現在の吸着を解除する距離 | 10 |
| 直交方向の候補範囲 | 160 |
| 吸着中の直交方向の解除範囲 | 184 |

距離は必ず**ポインターから求めた未補正位置**で判定する。
表示上の吸着位置で判定すると距離が 0 のままとなり、外れなくなる。

軸ごとの状態遷移、開始と解除の距離差、候補の順位付けは `BlockSnapService` の実装のまま。
カード側で状態機械を書き直さない。

## 7. 移動差分

```text
rawDelta   = 現在のポインターのワールド座標 - 押下時のワールド座標
result     = BlockSnapService.Compute(開始時の外接矩形, rawDelta, 対象, 前回の状態, zoom, Altか)

各カード:   X = 開始X + result.Delta.X 、 Y = 開始Y + result.Delta.Y
内部通過点: UpdateNodeDragWaypoints(移動群, result.Delta.X, result.Delta.Y)
```

補正済み差分を一度だけ当てる。次のフレームの `rawDelta` へ足し込まない。
いまの実装は「ポインター + 押下時の相対位置」で座標を作っており、
足し込みではないので誤差は溜まらない。この性質を保ったまま基準を開始座標へ置き換える。

所属変更（Shift）の判定は、これまでどおり**ポインターの位置**で行う。
吸着でカードがずれても、下見と結果が食い違わないようにする。

外部へつながる線の通過点は従来どおり絶対位置を保持する。

## 8. ガイド表示

- 実際に吸着している軸だけ表示する。接近中の予告線は出さない。最大で縦1本・横1本。
- 既存の `AlignmentGuideLayer` をそのまま使う。ブロック移動と同じ破線・同じ色
  （`AlignmentGuideBrush`）で、カードとブロックで見た目を変えない。
- ガイドの座標・対象・吸着状態は保存せず、Undo 履歴にも含めない。

### ステータス文言

カード移動中は所属変更の案内が毎フレーム出ている。ここへ吸着の案内を足すが、
**候補が変わるたびに文言を差し替えない**。次の3種類だけを使う。

| 状況 | 文言 |
|---|---|
| Shift なし | `Shiftを押すと、ドロップ先へ所属を変更できます。Altで吸着を解除。` |
| Shift あり・ドロップ先あり | 既存の「…へ所属を変更します（Shiftを離すと位置だけ移動）。」のまま |
| Shift あり・ドロップ先なし | 既存の「ブロックから外します（Shiftを離すと位置だけ移動）。」のまま |

確定・取消では既存の結果メッセージに戻す。

## 9. ジェスチャーの終了と例外

| 状況 | 動作 |
|---|---|
| MouseUp | 最終座標を再評価、既存の確定処理、状態とガイドを破棄 |
| Esc、キャプチャ喪失、ウィンドウ非アクティブ化 | 既存の移動取消、状態とガイドを破棄 |
| タブ切替、`GraphView` の文書差し替え・破棄 | 移動を取り消してから切り替える |
| 保存・タブを閉じるで既存処理が移動を確定 | 最後に表示した補正済み座標を確定し、View 側の状態も破棄 |
| `Alt` 解放イベントを取り逃した場合 | 次の MouseMove／MouseUp で現在の修飾キーを再取得して同期 |
| 表示モードの切替など、対象の寸法・可視性が外部から変わる | ドラッグを取り消し、古い候補を使わない |

ブロック移動と同じく、**カードのドラッグ中もホイール・ズームキー・全体表示・パンを抑止する**。
座標変換が途中で変わって原点が跳ぶことと、ガイドが古い倍率のまま残ることを防ぐ。
いまはカード移動中でもホイールズームが効くので、ここは既存の挙動が変わる。

セッションの妥当性は毎フレーム見る。ブロックの `SnapSessionIsValid()` に合わせ、
移動群のカードが残っていて可視であること、`NodeMetrics.Generation`（表示モードの通し番号）、
ノード・辺・ブロックの件数、向き、対象の矩形が開始時と一致することを確かめる。
崩れていたら移動ごと取り消す。

`IsNodeDragging` が false になったときと文書差し替え時に、ガイドの後始末を共通の終了処理から呼ぶ。
MouseUp だけに依存させない。

## 10. 実装構成

### Core: `src/ToDoTree.Core/Layout/CardSnapService.cs`（新規）

WPF に依存せず、移動群の外接矩形と吸着先の組み立てだけを行う。
吸着計算そのものは `BlockSnapService` に任せ、ここには状態機械を持たせない。

```csharp
public sealed record BlockSnapCandidate(Guid Id, BlockBounds Bounds, IReadOnlyList<Guid> NodeIds);

public static class CardSnapService
{
    /// <summary>動かすカードの外接矩形。1件も無ければ null。</summary>
    public static BlockBounds? MovingBounds(IReadOnlyList<NodeRect> moving);

    /// <summary>吸着先。移動群のカードと、移動群を含む囲みは除く。</summary>
    public static IReadOnlyList<SnapTarget> Targets(
        IReadOnlyList<NodeRect> visibleCards,
        IReadOnlyList<BlockSnapCandidate> visibleBlocks,
        IReadOnlySet<Guid> moving,
        BlockBounds viewport);
}
```

### App: `GraphView`

カードのドラッグ情報へ、開始座標・開始時の外接矩形・対象一覧・吸着状態・
最後のポインター位置を足す。`_dragGroup` の要素を
「ポインターからの相対位置」から「開始座標」へ変えるのが中心の変更になる。

ブロック用の `BeginSnap` / `UpdateSnap` / `ClearSnap` / `SnapSessionIsValid` と
役割が重なるので、**吸着の状態と後始末を1組にまとめる**。
「いま吸着している矩形は何か」だけを持ち、掴んだのがカードかブロックかは
差分の当て先（`UpdateBlockDrag` かカード群か）で分ける。
`GraphView.Snap.cs` を新しく切り出し、`GraphView.xaml.cs` からは呼ぶだけにする。

MouseMove、`Alt` の KeyDown／KeyUp、MouseUp が同じ更新関数を通る。
`OnSnapModifierKey` の入口判定を、ブロック押下中だけでなくカード移動中も通すよう広げる。

### ViewModel

`UpdateNodeDragWaypoints()` の責務は変えない。渡す差分が補正済みになるだけ。
カードの座標を書くのは今までどおり View 側で、ViewModel へ移さない。
Undo、通過点、自動保存の抑止は既存のカード移動をそのまま使う。
プロジェクト JSON と設定ファイルの形式は変えない。

## 11. 性能

対象はドラッグ開始時に1回だけ集める。更新時は対象数に比例した比較だけで、
1対象につき X／Y 各3組。ブロックと違ってカードは数が多い（300 件規模）が、
1回あたり 1,800 回の差の絶対値で済むので空間インデックスは今回も入れない。

100ノード／10ブロックを通常ケース、300ノード／30ブロックを負荷ケースとして計測する。
通常ケースで候補計算の95パーセンタイル 1 ms 以内を目標とし、
線の再描画を含むドラッグ全体のフレーム時間も導入前と比較する。

## 12. 受け入れ条件

### Core のテスト

- 外接矩形が、単体・複数・座標が負の場合で正しい。移動群が空なら null。
- 対象から、移動群のカードと、移動群を含む囲みが外れる。
- 移動群を含まない囲みと、同じブロック内の動かさないカードは対象に残る。
- ビューポートと交差しないものが外れ、部分的に交差するものは残る。
- カード寸法 24×24（ミニマル）でも 224×88（カード）でも、
  既存の吸着計算が同じ規則で端・中心を揃える。
- 既存の `BlockSnapTests` は変更なしで通る。

### 実画面の確認

1. カード表示で、2枚を上下に置き左端・中心・右端へ揃える。左右に置き上端・中心・下端へ揃える。
2. ミニマル表示で同じ操作を行い、丸の中心が揃うことと、線がガタつかないことを確認する。
3. 複数選択でまとめて動かし、群の外接矩形が揃い、**カード同士の相対位置が変わらない**ことを確認する。
4. ブロックの囲みの端・中心へカードが揃うこと、自分が所属する囲みには吸着しないことを確認する。
5. ポインターを止めたまま `Alt` を押す／離す。位置とガイドが即時に変わることを確認する。
6. `Shift` を押しながら他のブロックへ落とし、吸着していても所属変更が意図どおり働くことを確認する。
7. 25%、100%、250%、OS の 100%／150% 表示、ライト／ダークで操作と線幅を確認する。
8. 内部通過点が同じ差分で動き、外部接続の通過点が変わらないことを確認する。
9. MouseUp、Esc、キャプチャ喪失、タブ切替、保存、非アクティブ化後にガイドが残らないことを確認する。
10. 1回の Undo で移動が戻り、取消時に Redo と未保存状態が変わらないことを確認する。
11. 吸着で最終位置が開始位置と完全一致した移動で、履歴が増えないことを確認する。
12. 表示モードを切り替えた直後にドラッグしても、古い寸法の候補が使われないことを確認する。

「揃えたい位置に止められる」「離したいときにすぐ外れる」を実操作で判断する。
カードはブロックより数が多いので、**吸着先が多すぎて鬱陶しくないか**を特に見る。
うるさければ、直交方向の候補範囲（160 DIP）を先に詰める。

## 13. 実装順

1. Core の `CardSnapService` とテスト。
2. `GraphView` のカード移動を「開始座標 ＋ 差分」へ置き換える。
   この時点では吸着を挟まず、従来と同じ動きになることを確認する。
3. 吸着状態と後始末を `GraphView.Snap.cs` へまとめ、ブロックとカードで共有する。
4. カード移動へ吸着とガイドを繋ぎ、`Alt` の即時反映と入力の抑止を入れる。
5. ステータス文言、終了処理、セッションの妥当性判定。
6. 実操作と性能を確認し、距離を調整。
7. README と ROADMAP を更新し、この設計書の状態を「実装済み」にする。

次の拡張候補は等間隔配置と、通過点の吸着。どちらも
「移動対象全体へ1つの差分を当てる」方針を引き継ぐ。

- ドラッグ中の案内文言を、掴む前の文言へ戻すようにした。所属を変えたときの結果メッセージは上書きしない。
- カードの揃え先は、開始時のスナップショットと件数・寸法・向きの一致だけで妥当性を見る。
  動くのはドラッグ中のカードだけで、それを含む囲みは揃え先から外してあるため、
  毎フレーム全件の矩形を突き合わせない（ブロック移動は従来どおり突き合わせる）。
- カードの座標更新は `NotifyVisualsChanged` から呼び返されるので、
  その最中に後始末が走らないよう再入の印を 1 つ足した。
