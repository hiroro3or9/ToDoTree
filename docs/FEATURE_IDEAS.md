# 機能アイデア集：117案の詳細

作成日・更新日: 2026-09-11

## この文書の目的と位置付け

2026-09-10〜11の会話で挙がった117案を、使う場面や初版の範囲まで検討できる企画メモとして残す。会話で近い案をまとめたものも、ここでは元の提案ごとに独立して記載する。F001〜F117は最初に提案した順の固定IDであり、優先順位を表さない。本文は14分野に並べ替えている。

**全項目はアイデア・拡張候補であり、採用済みの仕様や実装予定ではない。** 「最小構成」は着手する場合のたたき台であり、実装済みという意味ではない。既存機能との関係は[アプリのREADME](../README.md)・[ロードマップ](ROADMAP.md)・[文書一覧](README.md)に記載された2026-09-11確認時点の範囲を基準にしている。コード全体の実装調査や工数見積もりは行っていない。

各案は次の内容で構成する。

- **説明**：何ができ、どのような場面で役立つか。
- **利用例**：利用者がどのように操作し、何を得るか。
- **最小構成・既存機能との関係**：小さく試す範囲と、利用できる既存の仕組み。
- **検討点**：採用前に決める挙動、保存・依存条件などへの影響。
- **関連案**：共通の仕組みや比較の観点を持つ案へのリンク。実装順序の強制ではない。

## 現在の機能を活かすときの注意

| 現在の土台 | この案集での拡張方向 | 混同しない点 |
|---|---|---|
| 着手判定・次の行動・最長経路・完了予測 | 候補選び、経路表示、仮計画 | 予測には入力値と稼働条件が必要。全前提が必要な合流を、1本の最短経路だけで達成できるとは限らない |
| 完了後のプレビュー・線を流れる光 | 開通力、達成演出 | 解放される後続と件数は既にプレビューできる。新規性は常時比較や選び方への組み込み |
| 作業のしおり・再開メモ・タブ復元 | バトンタッチ、着地、作業机 | 再開場所の保存は既存。入力ガイドや名前付き表示セットが追加部分 |
| 手動ブロック・チェックリスト | 待ち、完了条件、引き渡し | チェック全件達成による通常カードの自動完了は現行仕様ではない |
| 部品ライブラリ・作業手順・実施履歴 | 手順の改善、比較、練習 | 部品の複製と手順の実施は異なる。過去の実施内容を最新版で上書きしない |
| プロジェクト変数 | 数量展開、前提の見直し | 現行は文字列の表示置換。数値計算や意味的な影響分析は追加設計が必要 |
| ミニマル表示・フォーカス・分割 | ズーム連動、道案内、ハサミ | 現行のミニマル表示は手動。既存操作の改善案と新しいデータ機能を分ける |
| 通常ToDoの保存・手順の保存時点閲覧 | タイムラプス、比較、展示 | 通常ToDoの過去状態がすべて記録されているわけではない |

保存条件は[保存と復旧](STORAGE.md)、データ項目は[JSON保存形式](JSON_FORMAT.md)、手順と実施の区別は[作業手順と実施記録](PROCEDURE_RUN_DESIGN.md)を参照する。

### F001｜「あと15分」モード

作業に使える時間と気力から、今着手できるカードを少数に絞る。選ぶ負担を減らし、短い空き時間も使いやすくする。

- **利用例**：会議まで15分、気力は低めと指定すると、確認5分と返信8分が候補になる。
- **最小構成・既存機能との関係**：既存の着手判定・見積もりを利用し、時間上限と軽い／普通／重いの手動分類から始める。
- **検討点**：見積もり未入力は0分扱いにしない。準備や切り替え時間を含むか示し、候補の選定理由も表示する。
- **関連案**：[F002](#f002)、[F041](#f041)、[F056](#f056)、[F059](#f059)、[F073](#f073)、[F074](#f074)、[F112](#f112)

### F002｜ゴールへの「最短クエスト」

選んだゴールに必要な未完了作業を抽出し、今進める1枚を大きく見せる。完了するたび次の選択へ進む体験にする。

- **利用例**：アプリ公開を選ぶと、まずテストを提示し、完了後に説明文作成と画像準備から選べる。
- **最小構成・既存機能との関係**：フォーカス表示と着手候補を組み合わせ、前提が満たされたカードだけを順に提示する。
- **検討点**：現行の全前提が必要な合流では、1本の経路だけ終えても完成しない。「最短」が件数か時間かを定義し、必要な別枝を落とさない。
- **関連案**：[F001](#f001)、[F041](#f041)、[F056](#f056)、[F059](#f059)、[F073](#f073)、[F074](#f074)、[F112](#f112)

### F041｜挑戦する枝を抽選

着手可能なカードから1件を抽選し、選択に迷う時間を減らす。

- **利用例**：趣味プロジェクトの軽い作業だけに絞って「今日の1件」を引く。
- **最小構成・既存機能との関係**：既存の着手候補とタグ絞り込みを使い、抽選・引き直し・開始を分ける。
- **検討点**：候補を見ただけでは状態を変えない。期限優先の有無を設定し、候補がない場合はその理由を示す。
- **関連案**：[F001](#f001)、[F002](#f002)、[F056](#f056)、[F059](#f059)、[F073](#f073)、[F074](#f074)、[F112](#f112)

<a id="f056"></a>

### F056｜場所で変わる作業一覧

実行できる場所や道具を指定し、その場に合った候補だけを見せる。

- **利用例**：電車内を選び、スマホで可能・ネット不要の着手候補を表示する。
- **最小構成・既存機能との関係**：既存タグを場所・道具のプリセットとして選べるUIを作り、手動切り替えにする。
- **検討点**：位置の自動検出は初版に不要。場所だけ一致しても前提未完了の作業は着手候補にせず、複数条件のAND／ORを明確にする。
- **関連案**：[F001](#f001)、[F002](#f002)、[F035](#f035)、[F041](#f041)、[F058](#f058)、[F059](#f059)、[F063](#f063)、[F073](#f073)、[F074](#f074)、[F112](#f112)、[F114](#f114)

<a id="f059"></a>

### F059｜ゴールからのお迎え

残り作業が少ないゴールを見つけ、仕上げられる目標として提示する。

- **利用例**：複数プロジェクトの中から「あと2件で完成」の小さなツールを見つける。
- **最小構成・既存機能との関係**：まず開いているプロジェクトから未完了の前提を数え、残件数と着手可能な一歩を表示する。
- **検討点**：少ない件数でも長時間や待ちを含む。見積もりとブロック理由を添え、件数だけで簡単と断定しない。
- **関連案**：[F001](#f001)、[F002](#f002)、[F041](#f041)、[F056](#f056)、[F073](#f073)、[F074](#f074)、[F112](#f112)

<a id="f073"></a>

### F073｜カードの束を引く

候補を3枚ほどめくって比較し、大きな一覧から選ぶ負担を小さくする。

- **利用例**：短い作業を3枚引き、その中から気になる1枚を開始する。
- **最小構成・既存機能との関係**：着手可能なカードを重複なく抽出し、引き直し・候補固定・開始を用意する。
- **検討点**：1件を選ぶ抽選案と共通化できるが、本案は少数の比較が中心。提示だけで状態を変えず、候補数不足にも対応する。
- **関連案**：[F001](#f001)、[F002](#f002)、[F041](#f041)、[F056](#f056)、[F059](#f059)、[F074](#f074)、[F112](#f112)

<a id="f074"></a>

### F074｜目標の距離を歩数で表示

残りの作業件数と最初の一歩を並べ、抽象的な割合を具体的な道のりへ変える。

- **利用例**：「進捗67%」のそばに「必要作業はあと4件。まず画像を用意」と表示する。
- **最小構成・既存機能との関係**：選択ゴールの未完了の前提集合と、そこに含まれる着手可能カードを表示する。
- **検討点**：最長経路の長さと全必須作業の件数は違う。共有カードを重複カウントせず、回数指定カードを件数と達成回数のどちらで数えるか示す。
- **関連案**：[F001](#f001)、[F002](#f002)、[F041](#f041)、[F056](#f056)、[F059](#f059)、[F073](#f073)、[F112](#f112)

<a id="f082"></a>

### F082｜タスクのカロリー予算

集中力・対人負担・体力の消費も見ながら、無理のない一日の作業を組む。

- **利用例**：会議の多い日は重い設計を避け、短い確認を中心に選ぶ。
- **最小構成・既存機能との関係**：各軸を任意の3段階で付け、今日使える量と候補の目安を表示する。
- **検討点**：客観的な健康指標として扱わない。単純加算は本人の目安にとどめ、未入力のカードを低負担扱いにしない。
- **関連案**：[F014](#f014)、[F081](#f081)、[F096](#f096)、[F106](#f106)

<a id="f096"></a>

### F096｜タスクの相性メモ

作業単体の負担だけでなく、前後の組み合わせや状況による進めやすさを記録する。

- **利用例**：打ち合わせ直後は整理が進みやすい、重い設計の後は単純作業が合うと残す。
- **最小構成・既存機能との関係**：タグの組み合わせと本人の短いメモを保存し、順番を組むときに参照できるようにする。
- **検討点**：少数の実績から因果関係を断定しない。条件が変わることを前提に日付を残し、古いメモの無効化と見直しを用意する。
- **関連案**：[F014](#f014)、[F081](#f081)、[F082](#f082)、[F106](#f106)

<a id="f112"></a>

### F112｜次の節目までの道案内

最終完成より近い、試す・見せる・感想をもらう地点までを抜き出す。長い計画に途中の到着点を作る。

- **利用例**：全機能完成の前に、デモできる状態までに必要な3件だけを見る。
- **最小構成・既存機能との関係**：既存の節目カードを到着点として選び、その前提集合と次の候補を表示する。
- **検討点**：最短クエストと探索基盤を共有するが、本案は中間成果を選ぶことが中心。表示外の必須前提も欠落させない。
- **関連案**：[F001](#f001)、[F002](#f002)、[F041](#f041)、[F056](#f056)、[F059](#f059)、[F073](#f073)、[F074](#f074)

### F003｜「もしも」シミュレーション

期間・期限・実施範囲を仮に変え、ゴールへの影響を本体に反映せず比較する。見通しを確かめてから計画を変更できる。

- **利用例**：調査が2日延びた場合と、追加機能を見送った場合の完了見込みを並べる。
- **最小構成・既存機能との関係**：現在の予測計算に仮の見積もり変更を渡し、変更前後の差を表示。採用した変更を1回のUndo単位で反映する。
- **検討点**：仮状態を自動保存しない。枝の見送りは依存条件にも関わるため、見積もり変更より後の段階で扱う。
- **関連案**：[F038](#f038)、[F069](#f069)、[F079](#f079)、[F087](#f087)

<a id="f030"></a>

### F030｜「待つ」を扱うカード

返信・配送・時間経過など、自分が作業していない待ちを記録する。次の確認日と、並行できる別の枝を見えるようにする。

- **利用例**：発注後を配送待ちにし、到着予定日に確認する。その間は設置場所の準備へ進む。
- **最小構成・既存機能との関係**：既存の手動ブロックに待ちの種類・確認日を添え、確認対象の一覧を追加する。
- **検討点**：予定日を迎えただけで到着済みや完了にしない。見積もりの作業時間と経過時間を分け、予測へ使う前提を示す。
- **関連案**：[F019](#f019)、[F042](#f042)、[F047](#f047)、[F050](#f050)、[F051](#f051)、[F061](#f061)、[F094](#f094)

<a id="f032"></a>

### F032｜タスクの賞味期限

遅延ではなく、時期を過ぎると作業の価値が変わることを表す。不要になった作業を見直しやすくする。

- **利用例**：展示会の事前調査に開催日を設定し、開催後は継続・目的変更・見送りを選ぶ。
- **最小構成・既存機能との関係**：期限とは別の再評価日を持ち、期日を迎えたカードを見直し一覧へ出す。
- **検討点**：自動削除や自動完了は行わない。後続が依存しているカードを見送る際は、他の作業への影響も見せる。

<a id="f042"></a>

### F042｜完成までの予算ゲージ

カードごとの費用からゴールまでの支出を見積もり、選ぶ経路の違いを比較する。

- **利用例**：自作なら材料費、購入なら製品代を入力して、所要時間と費用を並べる。
- **最小構成・既存機能との関係**：単一通貨の見込み額・実績額と、対象範囲の合計から始める。
- **検討点**：共有作業の二重計上、未入力と無料の区別が必要。選択分岐が未実装なら、比較は別の仮プランとして扱う。
- **関連案**：[F019](#f019)、[F030](#f030)、[F047](#f047)、[F050](#f050)、[F051](#f051)、[F061](#f061)、[F094](#f094)

<a id="f047"></a>

### F047｜未来の詰まり予報

依存関係と待ちの見込みから、後で作業が尽きる場所を探す。先に依頼を出す判断を助ける。

- **利用例**：明日以降の候補がすべて承認待ちになるため、今日のうちに依頼カードを進める。
- **最小構成・既存機能との関係**：待ちカードと予想解除日を使い、選択ゴールまでの待ちが集まる箇所を示す。
- **検討点**：待ち時間が未入力なら断定しない。最長経路表示とは別に、誰が同時に何件進められるかという予測条件を明示する。
- **関連案**：[F019](#f019)、[F030](#f030)、[F042](#f042)、[F050](#f050)、[F051](#f051)、[F061](#f061)、[F094](#f094)

### F051｜準備できたらまとめて通知

件数やブロック全体の状態を条件に、まとめて動けるタイミングを知らせる。

- **利用例**：レビュー可能なカードが3件揃ったら、まとめて確認する通知を出す。
- **最小構成・既存機能との関係**：アプリ起動中の条件評価と通知一覧から始め、対象範囲・しきい値を設定する。
- **検討点**：同じ状態で何度も通知しない。通知済み条件の再成立やUndoを扱い、アプリ終了中の監視は常駐設計が必要だと分ける。
- **関連案**：[F019](#f019)、[F030](#f030)、[F042](#f042)、[F047](#f047)、[F050](#f050)、[F061](#f061)、[F094](#f094)

### F061｜終わった後の追跡カード

公開・送付・修正をした後に、結果を確かめる作業を忘れずにつなぐ。

- **利用例**：不具合修正を完了すると、1週間後に利用状況を確認するカードを作る。
- **最小構成・既存機能との関係**：カードに追跡用の名前と完了からの相対日数を設定し、完了時に1枚生成する。
- **検討点**：完了のUndo・再完了による重複を防ぐ。生成済みカードを編集した後の取り消し方と、手順の次回実施との区別を決める。
- **関連案**：[F019](#f019)、[F030](#f030)、[F042](#f042)、[F047](#f047)、[F050](#f050)、[F051](#f051)、[F094](#f094)

### F081｜割り込みの見える化

急な作業を予定へ入れたとき、今日の枠から押し出される作業を見せる。引き受ける影響を判断しやすくする。

- **利用例**：1時間の緊急対応を差し込むと、夕方の改善作業が翌日候補へ移る。
- **最小構成・既存機能との関係**：今日の路線図に作業可能時間と見積もりを加え、変更後の配置をプレビューする。
- **検討点**：カードの締め切りを勝手に変更しない。見積もり未入力・待ち・同時進行の扱いを示し、採用するまでは仮の表示にする。
- **関連案**：[F014](#f014)、[F082](#f082)、[F096](#f096)、[F106](#f106)

<a id="f094"></a>

### F094｜探索に予算を付ける

調査や試行錯誤の枝に時間の上限を置き、探索と結論のバランスを取る。

- **利用例**：ライブラリ比較を90分までと決め、到達したら採用・延長・別案を選ぶ。
- **最小構成・既存機能との関係**：枝の対象範囲と予算、手入力の実績時間を持ち、残量と見直しの入口を表示する。
- **検討点**：上限到達で勝手に打ち切らない。共有カードの時間をどう配賦するか、見積もり上限と実際に使った時間を分けて示す。
- **関連案**：[F019](#f019)、[F030](#f030)、[F042](#f042)、[F047](#f047)、[F050](#f050)、[F051](#f051)、[F061](#f061)

<a id="f106"></a>

### F106｜プロジェクト横断の混雑表示

別々の計画が同じ人の時間を使うことを考慮し、合計の負荷を見せる。

- **利用例**：個別には期限内でも、今週の作業合計が使える20時間を超えていると分かる。
- **最小構成・既存機能との関係**：開いているプロジェクトの見積もりを日・週へ手動割当し、利用可能時間と比較する。
- **検討点**：各プロジェクトの最長経路を足すだけでは負荷にならない。共有カードの二重計上、未入力、待ち、休み、対象外ファイルの範囲を示す。
- **関連案**：[F014](#f014)、[F018](#f018)、[F065](#f065)、[F081](#f081)、[F082](#f082)、[F096](#f096)、[F099](#f099)

## 3. 分岐・達成条件を豊かにする

[F009 選択肢の分岐](#f009) ／ [F036 終わり方を先に決めるカード](#f036) ／ [F038 完成条件の切り替え](#f038) ／ [F054 失敗したときの迂回路](#f054) ／ [F069 ゴールのお試し完成](#f069) ／ [F078 鍵を集めるゴール](#f078) ／ [F085 線にもチェックリスト](#f085) ／ [F098 決断の予約](#f098) ／ [F115 取り消しやすさの地図](#f115)

<a id="f009"></a>

### F009｜選択肢の分岐

複数の道から採用するものを選び、残りを見送る。判断理由を残しながら計画を絞れる。

- **利用例**：バックアップ方法を「自作ツール」「既製品」から選び、採用した枝で設定・検証へ進む。
- **最小構成・既存機能との関係**：選択グループと採用枝を明示し、切り替え前に影響をプレビューする専用の仕組みを設計する。
- **検討点**：全前提完了で進む現在の依存条件に影響する。見送った枝を一律に完了や取り消しへ変換せず、共有の後続と選択のやり直しを定義する。
- **関連案**：[F054](#f054)、[F078](#f078)、[F085](#f085)、[F098](#f098)

<a id="f036"></a>

### F036｜終わり方を先に決めるカード

作業名と別に、どこまでできたら終わりかを見える場所に置く。調査や改善を際限なく続けることを防ぐ。

- **利用例**：「調べる」に「候補3つの長所短所を書いたら完了」と設定する。
- **最小構成・既存機能との関係**：完了条件の短文欄を追加し、カード・詳細・実施画面で表示する。
- **検討点**：既存チェックリストの全チェックとカード完了は別であることを維持する。条件を必須化するかは後で検討し、初版は本人の完了判断を支える。

<a id="f038"></a>

### F038｜完成条件の切り替え

最低限・標準・こだわるの段階で実施範囲を切り替え、時間に合った完成を選べるようにする。

- **利用例**：公開予定が近づいたら装飾の枝を外し、基本機能とテストで完成させる。
- **最小構成・既存機能との関係**：各カードの必要段階を設定し、選択段階ごとの対象範囲をまずプレビューする。
- **検討点**：最低限のカードが上位段階の作業に依存する場合を検出する。非表示と実施不要は別であり、完了率・予測・依存条件を一貫して設計する。
- **関連案**：[F003](#f003)、[F069](#f069)、[F079](#f079)、[F087](#f087)

<a id="f054"></a>

### F054｜失敗したときの迂回路

結果別の道を用意し、失敗後も次の一手が分かるようにする。

- **利用例**：審査に通れば公開、通らなければ指摘確認と修正へ進む。
- **最小構成・既存機能との関係**：結果を明示的に選ぶ分岐を設計し、各結果から次の作業を選べるようにする。
- **検討点**：修正から再審査へ戻る線はDAGの循環禁止に触れる。再試行を新しい実施として作るなど、結果分岐と反復を別々に設計する。
- **関連案**：[F009](#f009)、[F078](#f078)、[F085](#f085)、[F098](#f098)

<a id="f069"></a>

### F069｜ゴールのお試し完成

現在の成果で一度完成とみなした場合、足りない必須条件と追加で磨ける部分を分けて見る。

- **利用例**：試作品を今公開するなら何が不足するか確認し、残りの装飾は後回しにする。
- **最小構成・既存機能との関係**：完了条件と必要段階を参照する読み取り専用の確認画面を作る。
- **検討点**：正式な完了や取り消しを自動実行しない。完成条件が未定義なら不足を断定できず、本人が条件を整理する画面として扱う。
- **関連案**：[F003](#f003)、[F038](#f038)、[F079](#f079)、[F087](#f087)

<a id="f078"></a>

### F078｜鍵を集めるゴール

全項目の達成以外に、個数条件や必須と選択の組み合わせで目標を達成する。

- **利用例**：練習5種類のうち3種類、かつ基礎練習は必須という条件を作る。
- **最小構成・既存機能との関係**：条件グループに全件／指定件数を持つ設計を作り、判定結果と残り条件を可視化する。
- **検討点**：既存の回数指定は1枚を指定回数行う仕組みで、本案は複数カード間の条件。合流、進捗、予測、取り消し、手順全体完了への影響が大きい。
- **関連案**：[F009](#f009)、[F054](#f054)、[F085](#f085)、[F098](#f098)

<a id="f085"></a>

### F085｜線にもチェックリスト

作業と作業の間にある引き渡しの条件を持たせる。作ることと、相手が受け取って次へ進めることを分ける。

- **利用例**：資料作成は完了しているが、「共有済み」「相手が確認済み」が揃うまで後続を待つ。
- **最小構成・既存機能との関係**：まず引き渡しカードと既存チェックリストで表現し、必要性を見て線上の専用UIを設計する。
- **検討点**：線のチェックが着手を制約するなら依存判定の変更が必要。線の付け替え・削除・ブロック接続・Undoで条件を失わないようにする。
- **関連案**：[F009](#f009)、[F054](#f054)、[F078](#f078)、[F098](#f098)

<a id="f098"></a>

### F098｜決断の予約

情報が揃う条件や時刻を決め、調査を終えて結論を出す場を計画へ置く。

- **利用例**：候補3つが揃うか金曜になると、方式決定カードを確認する。
- **最小構成・既存機能との関係**：初版は判断日と必要情報のチェック欄を持つ決断カードを作る。
- **検討点**：日付到達は判断を促すだけで、情報不足でも自動採用はしない。OR条件を着手判定へ加えるなら、条件分岐の設計と合わせて扱う。
- **関連案**：[F009](#f009)、[F054](#f054)、[F078](#f078)、[F085](#f085)

<a id="f115"></a>

### F115｜取り消しやすさの地図

後戻りの負担を作業ごとに示し、試しやすい範囲と慎重に進む地点を見つける。

- **利用例**：材料を切断する工程の前に、寸法確認と仮組みを置く。
- **最小構成・既存機能との関係**：本人が戻せる／戻すのが大変を付け、グラフで表示する。確認カード追加への導線を用意する。
- **検討点**：現実の取り消しやすさを表す案で、アプリのUndoとは別。分類は状況依存なので、理由と見直しを記録できるようにする。

## 4. グラフを気持ちよく編集する

[F018 枝の引っ越し](#f018) ／ [F022 グラフに手書きで書き込む](#f022) ／ [F040 不確かな線](#f040) ／ [F048 タスクの磁石](#f048) ／ [F055 タスクの合体・分離](#f055) ／ [F087 お試し接続](#f087) ／ [F092 タスクへの落書きスタンプ](#f092) ／ [F099 1枚を複数の場所に映す](#f099) ／ [F110 枝を縫うペン](#f110) ／ [F111 カードを切るハサミ](#f111)

<a id="f018"></a>

### F018｜枝の引っ越し

大きくなった一帯を別プロジェクトへ独立させ、元の場所から行き来できるようにする。

- **利用例**：全体計画の「UI刷新」が膨らんだので、専用プロジェクトへ切り出す。
- **最小構成・既存機能との関係**：選択範囲の抽出とリンク用の入口を作る。初版は参照ナビゲーションに限定し、跨る依存判定は別設計にする。
- **検討点**：複数ファイルの保存失敗、Undo、ID、変数、外部との線を扱う必要がある。部品コピーだけでは安全な移動と相互接続は成立しない。
- **関連案**：[F014](#f014)、[F065](#f065)、[F099](#f099)、[F106](#f106)

<a id="f022"></a>

### F022｜グラフに手書きで書き込む

カード周辺に丸・矢印・短い言葉を自由に描き、まだ構造化しない考えを残す。

- **利用例**：怪しい合流点を囲み、「この順でいい？」と書いて後で見直す。
- **最小構成・既存機能との関係**：キャンバスにインク専用モードを用意し、ペン・消しゴム・ストローク単位のUndoを実装する。
- **検討点**：パンやカード移動との操作競合を避ける。注釈を座標に固定するかカードに追従させるか、保存・縮尺・書き出しも決める。
- **関連案**：[F048](#f048)、[F055](#f055)、[F087](#f087)、[F110](#f110)、[F111](#f111)、[F116](#f116)

<a id="f040"></a>

### F040｜不確かな線

前後関係が未確認のまま、仮説として接続を置く。計画の不確かさを消さずに書き出せる。

- **利用例**：「契約が先に必要かもしれない」を点線でつなぎ、確認後に確定する。
- **最小構成・既存機能との関係**：仮接続という明示的な種類を作り、初版は着手を制約しない注釈として扱う。
- **検討点**：点線が装飾なのか条件なのか明確にする。実線への変更時は循環検証と影響プレビューを行い、書き出しにも種類を残す。

<a id="f048"></a>

### F048｜タスクの磁石

今週・あとで・気になるなどの分類へ、カードを視覚的に集める。線を保ちつつ別の切り口で整理する。

- **利用例**：「今週」の磁石に対象カードが集まり、他の枝との依存を眺めながら量を調整する。
- **最小構成・既存機能との関係**：既存座標を変えない一時的な分類表示を作り、元のグラフへ戻れるようにする。
- **検討点**：本体の配置を変える操作とは区別する。複数分類に属するカードの位置、線の交差、ブロックとの整合を決める。
- **関連案**：[F022](#f022)、[F055](#f055)、[F087](#f087)、[F110](#f110)、[F111](#f111)、[F116](#f116)

<a id="f055"></a>

### F055｜タスクの合体・分離

書き出したカードをまとめ、必要なら再び分ける。計画の粒度を手で調整できるようにする。

- **利用例**：細かな確認3件を1枚にまとめてチェック項目にし、重くなったら分離する。
- **最小構成・既存機能との関係**：未着手カードを対象に、合体後の名前・項目・前後の接続をプレビューする。
- **検討点**：タイトル以外のメモ・期限・実績・タグを失わない。Undoで戻すことと後日元通りに分離することは別で、後者には元の構成の保存が必要。
- **関連案**：[F022](#f022)、[F048](#f048)、[F087](#f087)、[F110](#f110)、[F111](#f111)、[F116](#f116)

<a id="f087"></a>

### F087｜お試し接続

接続を確定する前に、着手候補や見込みがどう変わるか確認する。線を引きながら意味を理解できるようにする。

- **利用例**：接続先に近づけると「3件が待ちになる」と表示され、離す前に考え直せる。
- **最小構成・既存機能との関係**：仮の1本を加えたコピーで循環・着手状態の差を計算し、確定時だけ保存する。
- **検討点**：ドラッグ中の頻繁な計算負荷に注意する。既存の接続制約を使い、キャンセル・不正接続では履歴も自動保存対象も増やさない。
- **関連案**：[F003](#f003)、[F022](#f022)、[F038](#f038)、[F048](#f048)、[F055](#f055)、[F069](#f069)、[F079](#f079)、[F110](#f110)、[F111](#f111)、[F116](#f116)

<a id="f092"></a>

### F092｜タスクへの落書きスタンプ

正式な状態と別に、本人の感触を短い印で残す。細かな属性を入力しなくても状況が伝わる。

- **利用例**：カードへ「一度動いた」「要相談」「ここ好き」を押す。
- **最小構成・既存機能との関係**：小さな定型ラベルをカードに追加し、付け外しとUndoに対応する。
- **検討点**：進行中・ブロックなど既存の状態と見た目を混同しない。色だけに頼らず文字を添え、数が増えたら省略表示する。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F097](#f097)

<a id="f099"></a>

### F099｜1枚を複数の場所に映す

カードの実体を1つに保ち、複数のブロックや表示場所から同じ状態を見られるようにする。

- **利用例**：共通の環境準備を、開発側と検証側の両方に置き、どちらから完了しても反映する。
- **最小構成・既存機能との関係**：同一プロジェクト内で、元カードを参照する表示用の写しと独立した位置を持たせる。
- **検討点**：写しの削除と本体削除を分け、進捗で二重計上しない。接続先、ブロック所属、検索、Undoを参照ID基準で一貫させる。
- **関連案**：[F014](#f014)、[F018](#f018)、[F065](#f065)、[F106](#f106)

<a id="f110"></a>

### F110｜枝を縫うペン

接続モードでカードを順になぞり、連続した依存線をまとめて作る。並べたカードを手順にする操作を短くする。

- **利用例**：調査・比較・決定を一筆書きで通過し、その順番に接続する。
- **最小構成・既存機能との関係**：ドラッグ中は通過カードの列を仮表示し、確定時に一括検証して接続する。
- **検討点**：同じカードへの再進入、既存線、循環、画面端スクロールを扱う。移動操作と分け、Escで全取消・Undo1回で一括復元できるようにする。
- **関連案**：[F022](#f022)、[F048](#f048)、[F055](#f055)、[F087](#f087)、[F111](#f111)、[F116](#f116)

<a id="f111"></a>

### F111｜カードを切るハサミ

カードの文章や箇条書きに切れ目を入れ、細かなカードへ分割する。構造化を直接操作で行えるようにする。

- **利用例**：「調査・比較・決定」の間を切り、順に実施する3枚へ分ける。
- **最小構成・既存機能との関係**：既存のステップ分割を、分割位置と順次／並行を選ぶプレビューへ拡張する。
- **検討点**：元カード・前後の接続・メモをどこへ残すか明示する。既存の回数指定カードの分割制限を保ち、合流と完了条件を壊さない。
- **関連案**：[F022](#f022)、[F048](#f048)、[F055](#f055)、[F087](#f087)、[F110](#f110)、[F116](#f116)

## 5. 大きなグラフを読み解く

<a id="f006"></a>

### F006｜タスクの「開通力」表示

カードを完了した場合に解放される作業を、常時比較できる指標として見せる。多くの枝を止めている要所を探せる。

- **利用例**：候補一覧に「新しく着手可能3件」と表示し、どれから進めるか判断する。
- **最小構成・既存機能との関係**：既存のホバー時の完了後プレビューを、一覧の列や並べ替えへ拡張する。
- **検討点**：直後に解放される件数と、間接的に影響する子孫件数を分ける。件数が多いだけで重要とは限らないため、優先度の強制には使わない。
- **関連案**：[F095](#f095)、[F113](#f113)

<a id="f015"></a>

### F015｜タスク同士のワープ

関連するカードを、着手条件を変えないリンクで結ぶ。離れた枝の調査や共通知識へすぐ移動できる。

- **利用例**：別の機能で同じ問題を調べたカードに「参考」としてつなぎ、クリックで行き来する。
- **最小構成・既存機能との関係**：通常の依存線と異なる関連リンクを同一プロジェクト内に追加する。
- **検討点**：関連リンクは循環しても作業のDAG計算へ入れない。検索・書き出しで関係の種類を明示し、線が増えた場合は表示を切り替える。

<a id="f033"></a>

### F033｜成果物から逆にたどる表示

資料・機能・作品などの成果物を中心に、それに必要な作業を抽出する。共通作業の役立ち先も分かる。

- **利用例**：設計書と実装の両方に役立つ調査を、どちらの成果物からでも見つける。
- **最小構成・既存機能との関係**：成果物への関連付けを追加し、対象作業を絞り込む表示から始める。
- **検討点**：成果物との関連と実行上の依存関係を分離する。関連するだけのカードを必須工程や進捗の分母に自動追加しない。

<a id="f044"></a>

### F044｜グラフを歩くプレゼンモード

説明順にカードを巡り、拡大・移動しながら計画や成果を説明する。

- **利用例**：概要・調査結果・試作品・残課題の順に画面を移し、進捗を紹介する。
- **最小構成・既存機能との関係**：カードIDの順序と表示倍率を保存し、次へ・前へ・終了を操作できるようにする。
- **検討点**：閲覧用の移動で元の表示や内容を壊さない。カード削除時は飛ばし、動きを減らす設定とキーボード操作を用意する。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F023](#f023)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F052｜グラフの顕微鏡

ズームに応じて工程・カード・詳細へ情報量を変え、同じ場所で全体と細部を行き来する。

- **利用例**：全体ではブロック名だけ、拡大するとカード、さらに近づくとチェック項目が見える。
- **最小構成・既存機能との関係**：既存のミニマル表示と通常表示を、ズーム段階で切り替えるところから始める。
- **検討点**：現状のミニマル表示は手動切り替え。自動切り替えでは閾値付近のちらつき、カードサイズの変化、ヒット判定、描画負荷を確認する。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F064｜グラフ内検索で道案内

カード名だけでなく、出発点とゴールの間にある経路を探す。大きな計画で位置関係を把握する。

- **利用例**：現在の調査から公開までを指定し、途中の確認と合流点を強調する。
- **最小構成・既存機能との関係**：既存のグラフ探索とフォーカス表示を利用して、両端の間にある経路を抽出する。
- **検討点**：表示経路の外にも合流の前提があり得る。その前提は注記し、道案内を必要作業のすべてと誤認させない。

<a id="f079"></a>

### F079｜計画の試運転

仮のコマが依存関係に沿って進む様子を再生し、合流待ちや並行箇所を直感的に確かめる。

- **利用例**：2本の調査が合流するまでコマが待つ様子から、片側が遅いと影響することを知る。
- **最小構成・既存機能との関係**：作業時間を一律にした構造確認用の再生から始め、開始・停止・1ステップ送りを用意する。
- **検討点**：実績のタイムラプスとは異なる仮の再生。時間予測を加える場合は人数・稼働時間を明示し、コマの到着で本体を完了にしない。
- **関連案**：[F003](#f003)、[F038](#f038)、[F069](#f069)、[F087](#f087)

<a id="f095"></a>

### F095｜複数ゴールへの貢献表示

1枚の作業が届く複数のゴールを光らせ、共通の土台となる仕事を見つける。

- **利用例**：共通データ形式の整理が、検索・出力・集計の3つの目標に役立つと分かる。
- **最小構成・既存機能との関係**：既存の下流探索で到達可能なゴールを重複なく求め、カード選択時に表示する。
- **検討点**：到達可能という構造上の関連と、実際の重要度を区別する。開通力の即時解放件数とは異なり、遠いゴールへの貢献を見る案である。
- **関連案**：[F006](#f006)、[F113](#f113)

### F097｜触れる進捗バー

進捗の各区間を実際のカードへ対応させ、残っている作業へ直接移動できるようにする。

- **利用例**：大きく残っている区間を押すと、まだ終わっていない検証カードへ移動する。
- **最小構成・既存機能との関係**：既存の集計と連携し、カード単位の区間、ホバー情報、クリック移動を追加する。
- **検討点**：件数基準と見積もり時間基準を混同しない。多数の小区間はまとめて一覧にし、色以外でも状態と対象を判別できるようにする。

### F016｜「ここが分からない」ノード

作業を進めるための疑問を独立して置き、回答と根拠を蓄積する。曖昧な前提を見える形にする。

- **利用例**：「ライブラリAで印刷できる？」を置き、試した結果と公式資料を残して方式を決める。
- **最小構成・既存機能との関係**：質問・回答・未解決／解決済みを持つカード表示を追加し、既存メモと接続を活用する。
- **検討点**：単なる参考質問か、解決が必要な前提かを指定する。回答の訂正が後続の完了記録へ与える影響も整理する。
- **関連案**：[F068](#f068)、[F080](#f080)、[F084](#f084)、[F101](#f101)、[F103](#f103)、[F104](#f104)、[F113](#f113)

### F062｜調査の「証拠カード」

判断の根拠となる資料・引用・画像を独立して残し、作業や決定につなぐ。後から理由をたどれるようにする。

- **利用例**：採用ライブラリの判断に、仕様ページと試験結果の画像を添える。
- **最小構成・既存機能との関係**：資料名・URL・短い抜粋・確認日を持つカードを、依存に影響しない関連線で結ぶ。
- **検討点**：リンク先の変更に備えて出典と参照日を残す。引用と自分の解釈を分け、証拠カード自体を通常作業の完了率へ混ぜない。
- **関連案**：[F008](#f008)、[F029](#f029)、[F088](#f088)、[F093](#f093)、[F102](#f102)、[F105](#f105)

### F080｜準備が冷めるカード

確認や準備の有効性が時間経過で弱まることを表し、必要な再確認を促す。

- **利用例**：在庫確認から1週間経ったため、購入前にもう一度確認する印が付く。
- **最小構成・既存機能との関係**：確認日時と有効期間を設定し、完了状態とは別の再確認フラグを表示する。
- **検討点**：完了実績を未完了に戻すかは別判断とする。時刻・期限境界を統一し、再確認を後続の必須条件にするか明示する。
- **関連案**：[F016](#f016)、[F068](#f068)、[F084](#f084)、[F101](#f101)、[F103](#f103)、[F104](#f104)、[F113](#f113)

### F084｜矛盾を見つける付箋

両立を確認したい条件や作業を結び、解消すべき論点を残す。

- **利用例**：「予算を増やさない」と「有料サービスを追加」に付箋を置き、費用の代案を記録する。
- **最小構成・既存機能との関係**：2枚以上を選択して手動で矛盾メモを作り、未解決／解決済みを管理する。
- **検討点**：自動の矛盾判定は初版に含めない。注釈があるだけで着手を止めず、解決理由と対象カード削除時の扱いを決める。
- **関連案**：[F016](#f016)、[F068](#f068)、[F080](#f080)、[F101](#f101)、[F103](#f103)、[F104](#f104)、[F113](#f113)

### F101｜未来の自分によるレビュー

別の立場や時間の視点で計画を読み直し、説明不足や先に必要な準備を自分で指摘する。

- **利用例**：締め切り前日の自分として読み、当日に入手できない道具へ気づく。
- **最小構成・既存機能との関係**：視点ごとの短い確認文と、対象カードへのレビュー付箋を用意する。
- **検討点**：自動で正解を出す機能にしなくても成立する。レビューを繰り返し強制せず、未解決指摘から必要なカードを作る導線を整える。
- **関連案**：[F016](#f016)、[F068](#f068)、[F080](#f080)、[F084](#f084)、[F103](#f103)、[F104](#f104)、[F113](#f113)

### F103｜前提が崩れたら波紋が広がる

予算・対象環境・利用条件などの前提を記録し、変更時に影響を受ける作業を示す。

- **利用例**：Windows専用から他OS対応へ変えると、画面・配布・テストの対象が光る。
- **最小構成・既存機能との関係**：前提の名前・値・関連カードを手動登録し、値の更新時に参照先へ確認の印を付ける。
- **検討点**：既存のプロジェクト変数は表示置換であり意味的な影響分析ではない。本人が結んだ関連を根拠にし、推測で大量の作業を未完了にしない。
- **関連案**：[F016](#f016)、[F068](#f068)、[F080](#f080)、[F084](#f084)、[F101](#f101)、[F104](#f104)、[F113](#f113)

### F104｜終わったはずの作業の再点検

上流の変更で、以前完了した確認の有効性を見直す必要があることを示す。

- **利用例**：仕様変更後、完了済みのテストに「前の版で確認」と表示する。
- **最小構成・既存機能との関係**：明示的な重要変更操作を起点に、完了済みの後続へ要確認フラグを付ける。
- **検討点**：名前や位置の変更で毎回伝播させない。完了実績と要確認を分け、再点検済みにする操作と通常の再開を混同しない。
- **関連案**：[F016](#f016)、[F068](#f068)、[F080](#f080)、[F084](#f084)、[F101](#f101)、[F103](#f103)、[F113](#f113)

### F113｜学びの多い一手を探す

作業が解決する疑問を結び、多くの不確かさを減らす実験を選ぶ。完成量以外の価値で順番を考えられる。

- **利用例**：小さな試作1つで速度・互換性・操作感を確かめられると分かり、先に試す。
- **最小構成・既存機能との関係**：疑問カードと実験カードの関連を手動登録し、未解決の疑問数を根拠付きで表示する。
- **検討点**：疑問の件数と学びの価値は同じではない。想定所要時間や重要度も見せ、実験しただけで全疑問を自動解決しない。

### F008｜作業セットを一発で開く

作業に必要なフォルダー・URL・資料をカードにまとめ、開始時に開く。準備の手間と探す時間を減らす。

- **利用例**：リリース準備カードから、成果物フォルダー、手順書、公開先の管理ページを開く。
- **最小構成・既存機能との関係**：カードに名前付きのリンク一覧と「作業セットを開く」を追加し、OS標準の関連付けで開く。
- **検討点**：移動済みのファイルや大量のウィンドウを扱う。外部アプリを開く操作と、カードを進行中にする操作の失敗を別々に表示する。
- **関連案**：[F029](#f029)、[F062](#f062)、[F088](#f088)、[F093](#f093)、[F102](#f102)、[F105](#f105)

<a id="f020"></a>

### F020｜行き詰まり脱出ボタン

止まったカードから、実行可能な次の一歩を作る。困っている理由に応じた操作をその場で選べる。

- **利用例**：「API連携」で詰まったら「まず調べる」を選び、前に調査カードを挿入する。
- **最小構成・既存機能との関係**：既存の分割・線への挿入・手動ブロックをまとめて呼び出すメニューから始める。
- **検討点**：巨大な自動分解を行わず、生成されるカードと線を確認できるようにする。分割できない回数指定カードなどの条件も引き継ぐ。

<a id="f023"></a>

### F023｜カードの裏面

カードを裏返してメモ・資料・チェックリストを表示し、元の場所で確認と編集を済ませる。

- **利用例**：実装カードの裏で注意点を読み、項目をチェックして表へ戻る。
- **最小構成・既存機能との関係**：既存の詳細情報をカード内で表示する切り替えから始め、回転演出は任意にする。
- **検討点**：裏面を広げた際の重なり、IME、キーボードフォーカスを扱う。裏返しただけではデータ変更やUndo履歴を発生させない。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F035｜作業のまとまりを発見

道具・場所・相談相手などの共通点から、まとめて実行すると効率のよいカードを探す。

- **利用例**：別々の枝にある質問を、同じ人への打ち合わせで一度に確認する。
- **最小構成・既存機能との関係**：手動で付けた共通タグから着手可能なカードをまとめ、候補の根拠を表示する。
- **検討点**：グループに入っても未完了の前提は無視しない。似た名称の推測より、明示された相手や資源を優先する。
- **関連案**：[F056](#f056)、[F058](#f058)、[F063](#f063)、[F114](#f114)

<a id="f046"></a>

### F046｜タスクの「試食」

まず数分だけ触る試行を用意し、完了を約束せずに着手の重さを減らす。

- **利用例**：難しそうな移行作業を3分だけ試し、続けるか調査へ分けるか判断する。
- **最小構成・既存機能との関係**：試行開始・終了と、続行／分割／保留の選択を付ける。タイマーなしの手動終了からでも成立する。
- **検討点**：試食しただけで完了にしない。通常の進行中状態と試行セッションを分け、中断やアプリ終了後も記録を矛盾させない。

<a id="f091"></a>

### F091｜机の隅に置けるミニカード

今の1枚だけを小さなウィンドウで表示し、別アプリで作業しても目的と次の操作を見失わないようにする。

- **利用例**：コードを書きながら、画面隅で完了条件とチェック項目を確認する。
- **最小構成・既存機能との関係**：選択カードに同期するWPFの小型ウィンドウを作り、最前面・固定・元へ戻るを用意する。
- **検討点**：元画面と別コピーの状態を持たせない。削除・タブ終了・複数DPI・画面外への移動と、キーボードフォーカスを扱う。
- **関連案**：[F017](#f017)、[F024](#f024)、[F031](#f031)、[F049](#f049)、[F086](#f086)

<a id="f102"></a>

### F102｜画面を「作業面」にする

カードに適した小さな編集面を持ち、管理画面の中で実際の検討や下書きを進める。

- **利用例**：候補比較カードに3列の表を開き、長所・費用・気になる点を書いて結論を残す。
- **最小構成・既存機能との関係**：まず自由記述か単純な比較表のどちらかに絞り、既存メモと一緒に保存する。
- **検討点**：汎用オフィスソフトを丸ごと作らない。編集データの保存互換性、Undo、IME、書き出しとカード完了の関係を決める。
- **関連案**：[F008](#f008)、[F029](#f029)、[F062](#f062)、[F088](#f088)、[F093](#f093)、[F105](#f105)

<a id="f105"></a>

### F105｜成果物の受け渡しポケット

前の作業で得た結論・ファイル・数値を、次の作業の入力として見せる。転記を減らし、根拠を保つ。

- **利用例**：調査カードの候補一覧が比較カードへ届き、採用結果が実装カードから参照できる。
- **最小構成・既存機能との関係**：名前付き出力を保存し、後続に読み取り専用で表示する。初版はメモとリンクに限定する。
- **検討点**：コピーか参照かを明示する。出力更新後の再確認、複数上流の同名項目、削除済みの出典、実施ごとの版を扱う。
- **関連案**：[F008](#f008)、[F029](#f029)、[F062](#f062)、[F088](#f088)、[F093](#f093)、[F102](#f102)

<a id="f114"></a>

### F114｜準備の使い回しが見える

道具を出す・環境を起動するなどの準備を共有し、片付ける前に続けられる作業を示す。

- **利用例**：工具を出した状態で、同じ工具を使う別の着手可能カードも確認する。
- **最小構成・既存機能との関係**：共通の準備ラベルと、現在準備済みかどうかの手動切り替えを作る。
- **検討点**：作業のまとまり発見と共通化できるが、本案は今の準備状態を利用する。永続的な完了と一時的な準備済みを分け、終了時の解除を決める。

### F014｜今日の路線図

複数プロジェクトのカードを参照として集め、今日進める順番を組む。元の計画を維持して一日の実行画面を作る。

- **利用例**：午前は仕事の確認、昼は買い物、夕方は趣味の実装を1本の路線に並べる。
- **最小構成・既存機能との関係**：まず開いているタブからカードを追加する日次リストを作り、完了状態を元カードと共有する。
- **検討点**：リスト順と依存関係を区別し、前提未完了を表示する。ファイルを閉じた・移動した・削除した場合の参照切れを扱う。
- **関連案**：[F018](#f018)、[F065](#f065)、[F081](#f081)、[F082](#f082)、[F096](#f096)、[F099](#f099)、[F106](#f106)

### F017｜作業の足あと

最近選択・編集したカードの流れを薄く表示する。中断前に考えていた道筋を思い出せる。

- **利用例**：資料を確認したあと元の作業を見失っても、直前の足あとをたどって戻る。
- **最小構成・既存機能との関係**：セッション内の直近数十件の移動履歴から始め、戻る・進むと一時的な線を表示する。
- **検討点**：見るだけの移動と実際の編集を区別する。自動移動で履歴を埋めず、記録の上限と履歴消去を用意する。
- **関連案**：[F024](#f024)、[F031](#f031)、[F049](#f049)、[F086](#f086)、[F091](#f091)

### F024｜作業机の切り替え

用途別に開くタブや表示範囲・絞り込みを保存し、作業の文脈をすぐ復元する。

- **利用例**：「朝の計画」は全体表示、「実装中」は対象の枝、「週末」は完了一覧を開く。
- **最小構成・既存機能との関係**：既存のタブ復元・表示状態を名前付きプリセットとして保存する。
- **検討点**：画面配置の復元とプロジェクト内容の巻き戻しを区別する。削除済みファイルやカードを含むプリセットでも残りを開けるようにする。
- **関連案**：[F017](#f017)、[F031](#f031)、[F049](#f049)、[F086](#f086)、[F091](#f091)

### F031｜作業のバトンタッチメモ

中断時に次の操作・必要な資料・試して失敗したことを残す。再開時の思い出す時間を減らす。

- **利用例**：「次は設定画面の保存ボタンを押す。案Aは試して失敗」と書き、翌朝最初に読む。
- **最小構成・既存機能との関係**：既存の作業のしおりと手順の中断メモに、任意の入力ガイドを付ける。
- **検討点**：新しいしおりを重複して作らない。プロジェクト単位と実施単位の保存先を明示し、短い自由記述でも使えるようにする。
- **関連案**：[F017](#f017)、[F024](#f024)、[F049](#f049)、[F086](#f086)、[F091](#f091)

### F049｜作業のセーブポイント

確かに動いた状態を、確認事項や成果物への参照とともに残す。試行錯誤の基準点にできる。

- **利用例**：大きな改修前に「全テスト成功」と画像・コミットIDを記録する。
- **最小構成・既存機能との関係**：名前付き記録に日時、対象カード、メモ、添付参照を保存する。
- **検討点**：アプリの記録だけで外部ファイルを巻き戻せるわけではない。参照先の版を示し、実際の復元を提供するなら別の仕組みとして設計する。
- **関連案**：[F017](#f017)、[F024](#f024)、[F031](#f031)、[F086](#f086)、[F091](#f091)

### F066｜集中を守る封筒

別の枝を直したくなったとき、変更案だけ預けて現在の作業を続ける。一区切りでまとめて採用を決める。

- **利用例**：実装中に思いついた設定画面の変更を封筒へ入れ、今のカード完了後に見直す。
- **最小構成・既存機能との関係**：現在の作業セッションに紐づく仮メモと、終了後の確認一覧を追加する。
- **検討点**：実際の編集操作を勝手に遮断しない。寄り道ポケットは発見元への保存、本案は集中が終わるまでの確認延期という違いがある。

### F072｜枝ごとのサウンドスケープ

作業のまとまりに音を設定し、取りかかる場所に応じた雰囲気を作る。

- **利用例**：調査の枝を開始すると雨音、制作の枝を開始するとカフェ音へ切り替える。
- **最小構成・既存機能との関係**：利用者が指定したローカル音源を、明示的な作業開始に合わせて再生する。
- **検討点**：選択しただけで音を切り替えない。複数タブで同時再生しない制御、音量・停止、配布音源を使う場合の利用条件を決める。

### F086｜作業の着地モード

終了時刻までに保存・確認・片付け・再開メモを進め、安心して作業を閉じられるようにする。

- **利用例**：あと10分で終了を選び、動作確認、変更保存、次の一手のメモを済ませる。
- **最小構成・既存機能との関係**：手動起動の終了チェックリストを用意し、既存のしおり・中断メモへつなぐ。
- **検討点**：アプリの保存成功と外部作業の保存を混同しない。未完了でも終了でき、毎回同じ長いチェックを強制しないようにする。

### F005｜手順の「前回の自分からの伝言」

同じ手順を再実施するとき、対応するステップに前回の注意点を表示する。履歴を探さず経験を活かせる。

- **利用例**：月次集計の取込ステップで「前回は文字コードを変更した」を先に読む。
- **最小構成・既存機能との関係**：既存の実施履歴・実施メモを使い、直近の完了回から手動指定した伝言を表示する。
- **検討点**：手順改訂後のステップ対応を定義する。今回だけの事情と恒久的な注意を区別し、古い伝言は出典の実施日を示す。

### F043｜定番作業のショートカット化

- **利用例**：入力欄で「調査セット」を選ぶと、調査・比較・決定の3枚が現れる。
- **最小構成・既存機能との関係**：既存の部品ライブラリに検索付き挿入コマンドを加え、配置・変数取り込みを再利用する。
- **検討点**：既存カードの編集文字列とコマンドを混同しない。IME、同名部品、配置位置、1回のUndoで戻す挙動を整える。

### F045｜成功した進め方を残す

- **利用例**：「先にサンプルデータを用意したので検証が速かった」を接続のコツとして残す。
- **最小構成・既存機能との関係**：作業メモから再利用用のコツを手動で選び、部品と手順に含める。
- **検討点**：実施固有の情報を無条件で複製しない。前回の伝言は履歴参照、本案は次回にも使う知識として保存する違いがある。

### F060｜手順の抜き打ち練習

手順を隠して思い出し、後から答えを見る。作業手順を習熟用の教材にもする。

- **利用例**：月次処理の次の操作を自分で答えてから、保存済みの手順を確認する。
- **最小構成・既存機能との関係**：既存手順を読み取り専用の練習画面で表示し、次の項目を開く操作を付ける。
- **検討点**：練習の回答を実際の実施完了に反映しない。分岐で複数の正解がある場合や、記憶に頼らず確認すべき重要手順の表示を考える。

### F068｜手順に「なぜ？」を埋め込む

短い操作手順に、必要な理由と省略時の影響を添える。久しぶりの作業でも背景を理解して進められる。

- **利用例**：「バックアップする」を開くと、失敗時の復元に必要な理由を読める。
- **最小構成・既存機能との関係**：手順カードに理由と省略時の影響の任意欄を設け、通常は折りたたむ。
- **検討点**：操作本文を長い説明で埋めない。根拠が古くなった場合に見直せるよう、改訂履歴や資料参照と結びつける。

### F089｜終わった作業を手順に還元

実施で発見した不足やコツを、次回用の手順へ取り込む。実体験に沿って手順を改善する。

- **利用例**：実施中に必要だった追加確認を、終了後に次回のチェック項目へ昇格する。
- **最小構成・既存機能との関係**：まず実施メモから追加項目の下書きを作り、利用者が選んで手順改訂へ反映する。
- **検討点**：既存の実施画面で任意の構造追加が可能だとは仮定しない。反映中の改訂競合を扱い、過去の実施内容と記録は変更しない。

### F090｜手順のバージョン比較

前回使った手順と今回の版を比べ、変更された操作と注意点を強調する。

- **利用例**：いつもの月次処理を始める前に、新しい確認項目が2つ増えたことを確認する。
- **最小構成・既存機能との関係**：実施で使った手順のスナップショットと最新版を比較し、追加・削除・変更の一覧を作る。
- **検討点**：ステップIDの継承と削除後の追加を区別する。単なる位置変更と実施内容の変更を分け、過去版を勝手に更新しない。

### F100｜レシピの分量変更

### F108｜アイデアの交配

### F057｜実物に貼れるタスク

- **利用例**：プリンターに貼ったコードを読み、清掃手順と前回の作業メモを開く。

- **検討点**：スマホからローカルのWindowsファイルはそのまま開けない。別端末対応には閲覧先・認証・共有方式が必要で、QR生成手段も依存方針と照合する。

### F058｜質問をためるカード

作業中の疑問を相手ごとに集め、打ち合わせでまとめて解消する。回答を発生元の作業へ戻せる。

- **利用例**：3つの枝で出た担当者への質問を一覧にし、面談後に回答を記録する。
- **最小構成・既存機能との関係**：相手の手動ラベル、質問、回答、発生元カードを持つ一覧を作る。
- **検討点**：相手ごとの一覧はメッセージの自動送信を意味しない。1回答が複数カードに関係する場合と、個人情報を含む共有範囲を扱う。

### F063｜買い物リストがグラフから生まれる

各作業の材料や道具を集約し、必要数と不足を一覧にする。入手状況から準備できた作業を見つけられる。

- **利用例**：2つの工作で使うネジを合算して購入し、揃った材料を使う作業を確認する。
- **最小構成・既存機能との関係**：共通の品目ID、単位、必要数、入手数を持ち、明示的な入手確認を記録する。
- **検討点**：消費する材料と共有できる道具を区別する。同じ在庫を複数作業に二重割当しない。条件達成で着手可能にはなっても作業完了にはしない。

### F065｜「誰かに頼むなら」パッケージ

選択した枝から、目的・前提・作業・完成条件・資料をまとめた依頼用文書を作る。

- **利用例**：検証の枝を選び、担当者に渡す手順と期待する報告内容をMarkdownにする。
- **最小構成・既存機能との関係**：既存の書き出しを拡張し、依頼向けテンプレートと範囲外の前提一覧を用意する。
- **検討点**：これは文書生成までで、送信は別操作とする。ローカルパスが相手にも開けるか、内部メモを含めるかを出力前に確認できるようにする。

### F088｜プロジェクトの引き出し

枝に関連する資料をまとめて仮置きし、必要になってからカードへ整理する。

- **利用例**：調査中のPDFやスクリーンショットをブロックのトレーへ入れ、あとで対応する作業に結ぶ。
- **最小構成・既存機能との関係**：ブロックごとの名前付きファイル参照一覧と、カードへの関連付けを追加する。
- **検討点**：コピー保存と参照だけの保存を区別する。ブロック解除時に資料を失わず、プロジェクト移動時の相対パスとリンク切れを扱う。

### F093｜共有資料の更新が伝わる

### F034｜お片付けモード

孤立・長期未更新・似た名前のカードを少数ずつ見せ、つなぐ・まとめる・残す・手放すを選ぶ。

- **利用例**：週末に5件だけ確認し、重複した調査をまとめ、独立したメモはそのまま残す。
- **最小構成・既存機能との関係**：明確な条件の候補一覧と、既存の編集操作への入口を作る。
- **検討点**：孤立や未更新は誤りとは限らない。除外指定や後で見るを用意し、自動的な削除・接続・統合はしない。

<a id="f037"></a>

### F037｜計画の健康診断

構造や入力から見直し候補を示し、計画の不備に気づく入口を作る。

- **利用例**：ゴールへ届かない枝、期限が近いのに見積もりがない作業を順に確認する。
- **最小構成・既存機能との関係**：到達性・未入力など説明可能なルールから始め、理由を選ぶと対象へ移動する。
- **検討点**：大きすぎる作業など主観的な判定は参考扱いにする。大規模グラフでの計算負荷と、指摘を無視・解消した状態の管理を考える。

### F116｜作業手順の抜け道を探す

- **利用例**：A→B→Cがあるとき、A→Cもあることを示し、省いてよいか確認する。
- **最小構成・既存機能との関係**：通常のカード間DAGで冗長な辺を候補として示し、削除前に到達関係の維持を確認する。
- **検討点**：線のチェック・結果条件・注釈・接続点に意味がある場合は単純に削除できない。初版は条件のない通常線へ対象を限定する。

### F107｜今日の作業をコミックにする

開始メモ・途中の画像・完成品を数コマに並べ、読み返しやすい作業日誌にする。

- **利用例**：苦戦した画面、直った画像、最後のひと言を3コマにまとめる。
- **最小構成・既存機能との関係**：利用者が画像と文章を選ぶ固定レイアウトを作り、画像またはHTMLに書き出す。
- **検討点**：実績にない出来事やセリフを自動で創作しない。まず生成AIなしで成立させ、文字量・画像比率・外部に出す情報を調整できるようにする。
- **関連案**：[F004](#f004)、[F011](#f011)、[F021](#f021)、[F025](#f025)、[F029](#f029)、[F039](#f039)、[F075](#f075)、[F117](#f117)

<a id="f117"></a>

### F117｜目標を隠して振り返る

完了した作業だけを眺めて本人が活動の意味を名付け、後から当初の目標と比べる。計画外の成果にも気づける。

- **利用例**：完了履歴を見て「使いやすさを磨いた週」と名付け、当初の機能追加目標と比較する。
- **最小構成・既存機能との関係**：期間指定の完了カード一覧からゴール名を一時的に隠し、感想を入力後に表示する。
- **検討点**：元の目標や作業記録は書き換えない。隠す対象がカード名やパスに含まれる場合もあり、厳密な盲検ではなく振り返りの補助と位置付ける。
- **関連案**：[F004](#f004)、[F011](#f011)、[F021](#f021)、[F025](#f025)、[F029](#f029)、[F039](#f039)、[F075](#f075)、[F107](#f107)

### F012｜ごほうびノード

目標達成後の楽しみもグラフに置き、条件を満たすと解放される演出を付ける。

- **利用例**：3つの勉強カードを終えると「映画を見る」の鍵が開く。
- **最小構成・既存機能との関係**：既存カードの表示種別としてごほうびを追加し、通常の依存判定と完了演出を利用する。
- **検討点**：ごほうびを達成率の分母に含めるか選べるようにする。作業完了と、ごほうびを実際に楽しんだ記録を混同しない。
- **関連案**：[F013](#f013)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F013｜未来の自分への手紙

特定のステップ到達時に開くメモを仕込む。進行段階に合った問いかけや記念の言葉を届ける。

- **利用例**：試作品完成時に「最初のスクリーンショットと比べてみよう」という手紙が開く。
- **最小構成・既存機能との関係**：カードに封筒表示のメモと、着手可能時／完了時の開封条件を設定する。
- **検討点**：Undoや再完了で何度も自動表示しない。未開封でも編集・削除でき、手順再実施時に再封するかを選べるようにする。
- **関連案**：[F012](#f012)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F021｜プロジェクトのエンドロール

ゴール達成時に完了した作業・詰まり・成果を短く流し、振り返りで締めくくる。

- **利用例**：公開完了後、主要な節目と画像が流れ、最後に「今回学んだこと」を1行残す。
- **最小構成・既存機能との関係**：既存の完了記録から主要カードを選んで表示し、手動再生・スキップを付ける。
- **検討点**：細かい作業をすべて流すと長くなる。アニメーション設定へ対応し、完了訂正や再完了で繰り返し割り込まないようにする。
- **関連案**：[F004](#f004)、[F011](#f011)、[F012](#f012)、[F013](#f013)、[F023](#f023)、[F025](#f025)、[F029](#f029)、[F039](#f039)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F075](#f075)、[F077](#f077)、[F083](#f083)、[F092](#f092)、[F097](#f097)、[F107](#f107)、[F117](#f117)

### F077｜自分専用の完了儀式

節目に合わせて、記録や音や短い演出を選ぶ。小さな完了と大きな達成を自分好みに祝えるようにする。

- **利用例**：通常カードは短い音、ゴールはスクリーンショットとひと言日記を出す。
- **最小構成・既存機能との関係**：既存の完了演出設定に、音と任意メモの選択肢を追加する。
- **検討点**：一括完了で大量の画面や音を出さない。無効化、アニメーション設定、Undo後の再完了、画像取得の操作範囲を定義する。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F083](#f083)、[F092](#f092)、[F097](#f097)

### F083｜未来へつながるスキルツリー

完了した作業と経験した技能を関連付け、学習の積み重ねを見える形にする。

- **利用例**：WPFの画面実装を終えると、Bindingやレイアウトの経験カードが増える。
- **最小構成・既存機能との関係**：手動のスキルタグと、それに関連する完了作業の一覧・木を表示する。
- **検討点**：完了件数だけで習熟を断定しない。スキルの前提関係と作業の依存関係を分け、本人の自己評価や成果への参照を残す。
- **関連案**：[F012](#f012)、[F013](#f013)、[F021](#f021)、[F023](#f023)、[F044](#f044)、[F052](#f052)、[F072](#f072)、[F077](#f077)、[F092](#f092)、[F097](#f097)

## 実装案へ進める際の共通検討事項

- **意味と表示を分ける**：関連線、注釈、写し、一時的な並べ替えを、依存計算や正式な配置変更へ暗黙に混ぜない。
- **履歴の単位を決める**：現在の計画、手順の定義、各回の実施、スナップショット、今日の表示状態のどこへ保存するかを案ごとに決める。
- **仮操作と確定を分ける**：ホバーや試運転で未保存の印やUndo履歴を増やさず、複数変更を採用するときは意味のある1単位で戻せるようにする。
- **参照を長持ちさせる**：名前だけで紐付けず、ID・参照先の版・削除や移動への対応を決める。複数ファイルを更新する案は保存失敗時の回復も設計する。
- **予測の前提を示す**：未入力を0として扱わず、作業時間・経過時間・待ち・同時進行・本人の主観評価を区別する。
- **演出なしでも使えるようにする**：音、回転、移動、自動表示は省略できるようにし、キーボードや文字でも内容を理解できるようにする。
- **外部機能の境界を決める**：QRの別端末利用、音声認識、画像出力、常駐通知などは、現行のローカルWPFアプリだけで成立する範囲を先に確認する。AI利用は必須にせず、導入する場合は接続・費用・データの扱いを別途決める。
- **保存と既存方針へ合わせる**：保存形式の変更、旧形式の読み込み、部品への引き継ぎ、JSON・Markdown・Mermaid出力を確認する。外部依存を増やさない既存方針との整合も採用前に確認する。

## 採用するときに決める項目

個別の設計書へ進める際は、対象IDを残したうえで次を具体化する。

1. 誰がどの作業で困っていて、どの操作が減るか。
2. 初版に含める範囲と、後の段階へ分ける範囲。
3. 画面の入口、利用の流れ、確定・取消・失敗時の挙動。
4. 必要なデータと保存先、既存ファイル・履歴との互換性。
5. 合流・取り消し・ブロック・繰り返し・共有参照への影響。
6. 成功と判断する利用例と、必要な検証。

例えばミニカードなら「別アプリで作業中に今の完了条件を読める」「チェック操作が元画面と同期する」「対象を削除・閉じても壊れない」を初版の確認項目にする。条件分岐ならUI作成より先に、複数前提・共有の後続・選択変更・Undo・保存再読込の判定例を固める。

新たな案はF118以降を付ける。既存案を統合・採用・見送りする場合もIDは再利用せず、対応先や判断理由を追記する。実装が完了した案は、個別設計書とロードマップへのリンクを追加して状態を更新する。
