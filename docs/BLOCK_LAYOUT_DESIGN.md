# ブロック内の整列：機能設計

作成日: 2026-09-06  
状態: 初版実装済み（実装状況更新: 2026-09-06）
前提: ブロックの作成・移動・所属編集・解除が実装済み

本文のAPI案と実装順は設計時の記録です。2026-09-06に後続の吸着実装を含むビルドとCoreテストが成功しています。
内部整列の一連の実マウス操作は、別途[開発・検証ガイド](DEVELOPMENT.md)に沿って確認します。

## 1. 目的

ブロック内でステップの追加や分割を続けた後、1操作で読みやすい配置へ戻せるようにする。
操作感を優先し、見出しの位置、外のカード、選択、ズームと画面位置を保つ。

例: 「設計」ブロック内に追加したカードが散らかったら、見出しを右クリックして
「中を整列」を実行する。依存関係に沿って中だけが並び、続けてその場で編集できる。

この設計はブロック内の整列だけを対象にする。後続の[吸着・ガイド](BLOCK_SNAP_DESIGN.md)は実装済み。折りたたみは未実装。

## 2. 現在の実装と変更方針

- `MainViewModel.AutoLayout()`は、ブロック所属ノードを一時固定し、全体の未所属ノードを整列する。
- `LayeredLayoutEngine.Apply()`は渡されたグラフのノード座標を直接変更する。
- `LayoutOptions`には方向、ノード寸法、間隔、原点、固定ID、障害物領域がある。
- `BlockGeometry.Compute()`はノードの外接矩形に見出しと余白を加えて囲みを算出する。
- ブロック操作は変更前スナップショットを確定時に履歴へ追加するトランザクションを持つ。

全体整列の意味を変えず、ブロック専用コマンドと、実データを変更せずに候補を作るCoreの処理を追加する。
全グラフを直接整列して外側を後から戻す方式は使わない。

## 3. 操作

| 場所・入力 | 動作 |
|---|---|
| ブロック見出しの右クリック →「中を整列」 | そのブロック内を整列 |
| ブロック選択中に`Ctrl+L` | 選択ブロック内を整列 |
| ブロック未選択時の`Ctrl+L` | 従来の全体整列 |
| ツールバーの整列ボタン | ブロック選択中は「中を整列」、それ以外は「自動整列」 |
| 表示メニューの「全体を整列」 | 選択に関係なく従来の全体整列 |

この文脈に応じた`Ctrl+L`とボタン表示は新仕様。ツールチップにも対象を明記する。
右クリックは先に押した見出しのブロックを選択し、そのIDへコマンドを渡す。
カード編集中・IME変換中・ドラッグ中には発火させない。編集の終了後に操作する。

整列後も同じブロックを選択し、フォーカスをキャンバスへ戻す。
全体表示イベントは発火させず、スクロール位置とズーム倍率を維持する。
初版はアニメーションを入れず、計算した結果を1回で反映する。

### 実行可否

| 条件 | 扱い |
|---|---|
| 対象なし | 無効 |
| 所属が1件以下 | 無効。「2件以上のステップが必要です」 |
| 一部の所属ノードが非表示 | 無効。「すべてのステップを表示すると整列できます」 |
| 所属に`IsPinned`が1件でもある | 初版は無効。「中のステップの位置固定を解除すると整列できます」 |
| 検索やタグで薄く表示されているだけ | 全所属ノードを対象として実行可能 |
| 名前編集・接続・ノード／通過点／ブロックのドラッグ中 | 無効 |

無効なメニューにも理由を表示する。実行時も再検証する。
固定カードを残した内部配置は、依存関係の方向と衝突を両立する追加設計が必要なため初版の対象外。
固定フラグを一時的に解除して配置することはしない。

## 4. 配置で守ること

1. 対象ブロックのノードだけが動く。
2. ブロックの左上、つまり見出しの始点をワールド座標で維持する。
3. 現在の配置方向（左→右／上→下）とカード／ミニマル表示に対応する寸法を使う。
4. ブロック内の直接の依存関係をレイヤ決定に使う。ノードや辺は追加・削除しない。
5. 外部への接続は内部のレイヤ計算に含めず、描画時に再計算する。
6. 同じ構造・表示モード・方向で連続実行したとき、2回目は同じ配置になり履歴を増やさない。

囲みの幅と高さは変化してよい。現在の矩形に押し込んでカードを縮小したり、文字を読めない大きさにしたりしない。
原点が負の座標にあってもその位置を保持し、ゼロへの丸めはしない。

外を経由してつながる内部ノード（例: 内部A → 外部X → 内部B）は内部計算では直接つながない。
これは図全体の流れを最適化する機能ではなく、ブロック内の直接の関係を読みやすくする機能とする。

## 5. 候補の計算

### 5.1 入力のコピー

- 対象の全所属ノードをCloneし、両端が所属ノードのエッジだけをCloneする。
- 一時的な`TodoProject`と`TodoGraph`を構築する。ブロックや外部ノードは含めない。
- 実プロジェクトのモデル参照を候補計算に共有しない。
- 既存の`NodeMetrics.LayoutFor(Direction)`から寸法・間隔を取得する。
  設定オブジェクトを共有変更せず、内部整列用のオプションを作る。

### 5.2 安定した並び

既存エンジンは現在座標を初期順序に使うため、繰り返し実行で順位が変わる可能性がある。
内部整列では所属ノードを`CreatedAt`、次に`Id`の順に並べ、一時グラフの初期座標を
この順の交差軸上へ設定する。元の手動配置を初期順序として使わない。
同順位の解決にもこの順序を使い、プロジェクト配列の並びや辞書の列挙順に依存させない。

両端が内部にある辺をこの安定順で登録し、既存のレイヤ計算と交差低減を適用する。
独立したカードは初期順序に従う。連結していない成分も同じレイヤ配置に含める。
成分ごとのパッキングや外部接続に合わせた並べ替えは後続の改善候補。

### 5.3 見出し位置の保持

1. 整列前の全所属ノードから`beforeBounds`を計算する。
2. 一時グラフを原点`(0, 0)`で整列し、`candidateBounds`を計算する。
3. 差分`(beforeBounds.X - candidateBounds.X, beforeBounds.Y - candidateBounds.Y)`を
   全候補ノードへ加える。
4. 候補から囲みを再計算し、左上が元の位置と一致することを検証する。

一時固定IDと障害物は候補生成には渡さない。外の障害物のために内部の列を不規則に
押し出す代わりに、配置全体を次節で検証する。

## 6. 外側との重なり

外部ノードは動かさず、対象ブロックも勝手に別の場所へ移動しない。

- 他ブロックは非表示の所属も含めた全ノードから占有領域を計算する。
- 未所属の外部ノードは、非表示を含めた現在モードの矩形を使う。
- 外部ブロックのノードは囲みの占有領域で代表させ、二重計上しない。
- 対象の新しい囲み全体（見出しと余白を含む）と外部の占有領域を比較する。
- 重なりがあれば適用しない。「周囲と重なるため整列できません。ブロックを広い場所へ移動してください」と表示する。
- 現状ですでに重なっていても、新候補が重ならなければ実行できる。
- 辺と通過点は占有領域には含めない。辺が囲みを通過することは許容する。

判定は既存`BlockBounds.IntersectsWith()`に合わせ、境界が接するだけなら重なりとしない。
内部のノード同士も矩形衝突を検証し、不正候補は適用しない。
この初版の制約によって実行失敗が多い場合、次に移動候補のプレビューを検討する。

## 7. 手動の通過点と接続

内部整列はノードごとの移動量が異なるため、ブロック全体の平行移動と同じ通過点追従は使えない。
初版は内部・外部とも、すべての手動通過点の絶対座標、順序、`IsSmooth`を保持する。
接続辺指定、ラベル、エッジIDも維持する。

適用後は全辺のルーティングキャッシュを無効化する。動いたカードが障害物になるため、
対象ノードに直接つながらない辺も再検証する。

通過点のある辺では整列後に線が遠回りすることがある。ステータスに
「中を整列しました。手動の通過点は保持しています」と示す。
必要な場合は既存の線メニュー「通過点をすべて解除」を使って調整する。
ノード配置に合わせた通過点の自動変形や一括消去は本機能に含めない。

## 8. CoreのAPI案

新規ファイル: `src/ToDoTree.Core/Layout/BlockLayoutService.cs`

```csharp
public enum BlockLayoutStatus
{
    Ready,
    Unchanged,
    TooFewNodes,
    ContainsPinnedNodes,
    OverlapsOutside,
    InvalidInput,
}

public sealed record BlockLayoutResult(
    BlockLayoutStatus Status,
    IReadOnlyDictionary<Guid, Vec2> Positions,
    BlockBounds? Bounds);
```

`Compute(project, blockId, layoutOptions)`で結果を返す。ノード寸法・方向はオプションから受け取る。
Coreで所属ID、座標の有限性、寸法と間隔の正値、内部グラフの循環を検証する。
不正な入力を既存エンジンの循環時フォールバックへ流さず`InvalidInput`とする。
結果の辞書はコピーとして返し、`Ready`以外では座標変更を要求しない。

可視性、選択、編集中かどうかはAppで検証する。UI文字列はCoreの結果コードからAppで作る。
座標差が全ノードで0.01 DIP以下なら`Unchanged`とし、微小な差をモデルへ書き戻さない。

APIの型名は実装時に既存コードへ合わせてよいが、候補生成と適用を分離する契約は維持する。

## 9. Appへの統合と履歴

- `MainViewModel.Blocks.cs`に`LayoutBlockCommand`、可否と理由、実行処理を追加する。
- `MainViewModel.Menu.cs`、見出しメニュー、整列ボタンとキー入力の対象を統一する。
- 従来の`AutoLayout()`は全体用として維持し、新コマンドからは呼ばない。
- `GraphView`の名前編集・IME・ドラッグ時のショートカット抑止を確認する。

実行手順:

1. 現在の文書と対象IDを確認し、操作可否を再検証する。
2. 実モデルを変更せず候補を計算する。
3. `Unchanged`は「すでに整列されています」、失敗は理由だけを表示する。
   履歴、Redo、選択、保存状態を変更しない。
4. `Ready`でのみ既存の`BeginTransaction()`を呼ぶ。
5. 対象ノードの座標をまとめて更新し、`CommitTransaction()`で1操作として記録する。
6. 境界、ノード位置、ルーティング、ミニマップを更新し、対象ブロック選択を維持する。
7. 例外時は`RollbackTransaction()`で元の座標・保存状態・選択へ戻す。

既存のトランザクション差分検出が今回の座標変更を確実に検出することをテストする。
同期処理の短い適用区間にawaitを挟まず、自動保存が途中の状態を保存しないようにする。
Undo/Redoで座標とブロック選択を復元し、ズーム・パンは変更しない。
名称、所属、ノードの内容、固定フラグ、辺は変更しない。

保存形式は既存の座標だけで表現できるため、スキーマ追加やバージョン更新は不要。

## 10. 確認項目

### Coreと履歴のテスト

- 直列、分岐、合流、非連結、長い辺を含むブロックで内部の重なりがない。
- 左→右／上→下とカード／ミニマルの4組み合わせ。
- 正・負の座標で囲みの左上を維持する。
- 外部ノード、他ブロック、所属、辺、固定フラグが変更されない。
- 候補計算だけでは実プロジェクトが変化しない。
- ノード・辺の配列順が変わっても同じ候補になる。
- 初回結果を適用した後の再計算が`Unchanged`になる。
- 1件、固定ノードあり、不正ID、循環、不正座標を安全に拒否する。
- 囲み拡大時に外部カードや他の囲みと重なれば、変更を一切適用しない。
- 既存の重なりが候補で解消される場合は実行できる。
- 内部・外部の通過点の座標、順序、滑らかさが保存される。
- Undo1回で元の座標と選択へ戻り、Redo1回で整列を再現できる。
- 失敗と無変更でRedoと未保存状態が変わらない。
- 適用結果を保存・再読み込みして座標が一致する。

### 実画面での手触り

1. ブロック内にEnterで5件を追加し、分岐を作り、見出しから「中を整列」。
2. 見出しが同じ場所に残り、外側が動かず、拡大率が変わらないことを確認。
3. 直後に中のカードを編集し、再度ブロック選択から`Ctrl+L`を使う。
4. 日本語変換中・名前編集中・ドラッグ中に整列が誤発火しないことを確認。
5. 見出し右クリックが別ブロックへ誤適用されないことを確認。
6. 固定・非表示・重なり時の理由が、無効メニューでも読めることを確認。
7. 通過点付きの線、Undo/Redo、タブ切替、保存までを続けて操作する。

通常ケースは全体100ノード・150辺、そのうち対象20ノードで計測する。
負荷ケースは全体300ノード・450辺、対象100ノード。両方に外部接続と通過点を含める。
通常ケースで入力から描画更新まで100 ms以内を目標とする。未計測の目標であり、
達成できない場合は計算と描画を分けて計測し、必要な部分だけ改善する。

### 実装との差分

- 状態コードは設計案どおり`BlockLayoutStatus`とし、`Compute`は`BlockLayoutResult`を返す。
  `Ready`以外では座標の辞書を空にして、書き戻しを要求しないことを型で示している。
- `Unchanged`の判定は外側との重なり判定より先に行う。いまの配置がすでに何かと重なっている場合に、
  「動かないのだから直しようがない」ことを重なりのせいにしないため。
- 「編集中は発火させない」は`MainViewModel.IsNaming`（カードの直接編集とブロックの命名）と
  `GraphView`側のドラッグ・接続の判定に分けた。IME変換中はWPFが`Key.ImeProcessed`を届けるため、
  カードの入力欄にフォーカスがある時点でキャンバスのショートカットは走らない。
- 辺のルーティングは`EdgeViewModel.InvalidateRoute()`を全辺に呼んで捨てる。
  既存のキャッシュ判定にも全ノード座標が入っているが、依存を明示するために残した。
- `Ctrl+L`はウィンドウの入力割り当てを`AlignCommand`へ向け、`GraphView`側でも同じ入口を呼ぶ。
  ドラッグ中の抑止は`GraphView`が担い、名前入力中の抑止は`Align()`が担う。
