# プロジェクト変数の設計

作成日: 2026-09-10

更新日: 2026-09-10

状態: 実装済み。本書の初版の範囲を形式10として実装した。実装後の確認内容は末尾の[実装の記録](#実装の記録)を参照する。

## 目的と基本方針

プロジェクトごとに固有名称などを定義し、ステップ内の `{Hoge}` を定義値で表示する。
値の変更を全参照箇所へ反映し、同じ文章を個別に直す手間を減らす。

- 保存・編集する文字列は原文のまま。表示用文字列だけを展開する。
- 変数の範囲は1つの `TodoProject`。別タブ・別プロジェクトの値は参照しない。
- 通常の文字列置換のみ。式、環境変数、外部ファイル、再帰展開は扱わない。
- 完了済み・取り消し済みのステップにも最新値を反映する。完了時点の名称を固定する機能ではない。

例: `Hoge = なにかしらの固有名称` のとき、原文 `{Hoge} の手順書を作成` を `なにかしらの固有名称 の手順書を作成` と表示する。

## 初版の適用範囲

| フィールド・用途 | 扱い |
|---|---|
| `TodoNode.Title`、`TodoNode.Notes` | 展開対象 |
| `InboxItem.Title` | 展開対象。キャンバスへ配置するときも原文を引き継ぐ |
| カード、ステップ一覧、次の一手、親子ステップのリンク、しおりが参照するステップ名 | 同じ展開後のタイトルを表示 |
| ステップ名を含むツールチップ、操作結果、読み上げ名 | 展開後のタイトルを使用 |
| プロジェクト名・説明、ブロック名、接続点名、タグ、チェック項目、ブロック理由、しおり自体のメモ | 初版では置換しない |
| 日付・数値・IDなど | 置換しない |

設定画面に対応範囲を明記する。対象フィールドの列挙をCoreへ集約し、検索・参照確認・改名・テンプレート抽出で同じ範囲を使う。

## 記法

| 項目 | 仕様 |
|---|---|
| 参照 | `{Hoge}` |
| 変数名 | 1〜64文字。Unicodeの文字または `_` で開始し、以降は文字・結合文字・10進数字・`_`。`製品名` も使用可 |
| 名前の比較 | `StringComparer.Ordinal`。大小文字を区別し、正規化・空白除去を暗黙に行わない |
| 空白 | `{ Hoge }` は変数として解釈しない。設定画面では空白を含む名前を入力エラーにする |
| 定義値 | 1〜4096 UTF-16コード単位の1行の文字列。改行と空白だけの値を拒否。前後の空白は保持 |
| 未定義 | `{Hoge}` のまま表示し、未定義として報告。保存・通常操作は継続可能 |
| リテラル | 対象フィールドでは `{{` が `{`、`}}` が `}`。`{{Hoge}}` は `{Hoge}` と表示し参照扱いしない |
| 不完全・不正な記法 | `{Hoge`、`{a b}` などは入力どおりに残す。内部の部分一致を拾わない |
| 再展開 | しない。Hogeの値が `{Other}` なら、結果は文字列 `{Other}` のまま |

スキャナーは左から1回走査し、エスケープを優先して処理する。展開した値を再走査しない。
解析結果は原文位置と表示位置を区別し、通常文字・定義済み参照・未定義参照のセグメントを返す。
名前変更・参照件数の集計にも同じ解析器を使用し、単純な `string.Replace` で原文を書き換えない。

既存データに `{Hoge}` がある場合、対応する変数を定義するまでは原文のままになる。
エスケープ記法は既存の `{{...}}` の表示を変えるため、旧形式から移行する際は対象フィールド内の全 `{` と `}` をそれぞれ二重化し、従来の表示を保つ。原文の変換はメモリ上で行い、通常保存時に形式10で確定する。
移行後の既存文字列を変数として使いたい場合は、編集で `{Hoge}` に変更する。

## 操作と画面

プロジェクトのメニューに「プロジェクト変数…」を追加する。現在のタブを対象にモーダル画面を開く。
画面にはプロジェクト名、変数名・値・使用箇所数の一覧、「追加」「削除」「保存」「キャンセル」を置く。
使用箇所数は対象フィールド単位で数える。同一タイトル内の2回の参照は1箇所とし、出現回数は詳細で示す。
一覧の下に選択変数の使用箇所と変更前・変更後の表示を示し、未定義名も別一覧で確認・追加できるようにする。

- 画面内では定義と参照変更の下書きを編集する。保存まで実プロジェクト・自動保存・履歴に反映しない。
- 保存は検証後に1回のUndo単位で適用。キャンセルは変更なし。同じ内容の保存も履歴を増やさない。
- 値を変更すると参照箇所の表示だけが変わる。ステップの原文・`UpdatedAt`・完了日時は変更しない。
- 名前を変更すると対象フィールドの有効な参照を同時に更新する。エスケープと非対象フィールドは変更しない。変更したステップの `UpdatedAt` は更新する。
- 名前の重複は保存不可。複数の改名は変更前の定義との対応を下書き内で保持し、一括変換する。名前の交換でも連鎖置換しない。
- 使用中の定義を削除する行には件数と「参照は未定義になります」を表示し、保存前に影響を確認できるようにする。参照原文は残す。追加の確認ダイアログは重ねない。
- 既に未定義参照がある名前を追加・改名先に使う場合、その参照も解決されることをプレビューへ含める。

カードのインライン編集は既存の `Title` を使い、非編集時だけ展開後を表示する。
詳細パネルのタイトル・メモは現在TextBoxなので、原文入力を維持し、変数またはエスケープを含む場合に直下へ「表示」プレビューを出す。入力内容はその場でプレビューへ反映し、編集中のカーソル位置を置換で動かさない。
未定義参照はプレビューで強調し、カードでは警告アイコンと「未定義: Hoge」のツールチップを使う。色だけに依存せず、ライト・ダーク両テーマに対応する。
定義済み参照のあるカードのツールチップには原文と使用変数を表示する。
カード寸法は既存の固定寸法を維持し、長い名称は既存の折り返し・省略とツールチップで扱う。

`{` 入力からの候補補完は次段階。初版では設定画面で `{名前}` をコピーできるようにする。

## 検索・コピー・書き出し

- 現在のタイトル・メモ・タグ検索を維持し、タイトルとメモの展開後もOR条件に追加する。検索語自体は展開しない。
- `Hoge`、`{Hoge}`、定義値のいずれでも参照ステップを探せる。参照していないステップを定義値だけでヒットさせない。
- 既存の検索比較方法を維持する。変数名の解決で大小文字を区別することとは別の仕様。
- 同じ優先順位のステップのタイトル順ソートには展開後を使う。変数保存・Undo・Redo・原文変更時は検索結果と順序を再計算する。
- 編集欄のコピーは選択した原文。別途「表示名をコピー」「表示メモをコピー」を提供する。
- Markdown/Mermaid書き出しとMermaidコピーは展開後。展開してから出力形式のエスケープを行い、ノードID・辺・状態を変更しない。
- JSON保存・バックアップ・プロジェクト複製は原文と定義を保持する。
- アウトライン入力は原文として取り込み、その後に表示だけ展開する。定義値内の記号をインデントなどの構造として再解釈しない。

## 保存・互換性

`TodoProject.Variables` に `List<ProjectVariable>` を追加する。`ProjectVariable` は `Name` と `Value` を持ち、Cloneを提供する。
JSONオブジェクトのキーではなく一覧にすることで、重複定義を読み込み時に検出し、設定画面の順番も保持する。
永続IDは初版では不要。設定画面の改名対応用IDは下書き内だけで管理する。

```json
{
  "schemaVersion": 10,
  "variables": [
    { "name": "Hoge", "value": "なにかしらの固有名称" }
  ],
  "nodes": [
    { "title": "{Hoge} の手順書を作成", "notes": "{Hoge} の設定を確認" }
  ]
}
```

上記は関連フィールドだけを示した抜粋。

- 現行9から10へ上げ、旧アプリが変数を消して上書きすることを防ぐ。実装時に別機能で版が進んでいたら次の未使用番号に変更する。
- 旧形式の定義省略は空一覧として移行する。形式10でも省略は空一覧。明示的なnull、null要素、不正な名前・値、重複名は読み込みを中止し、原因を示す。
- 形式9以下で空でない `variables` を持つファイルは形式詐称として拒否する。先に宣言版と内容を検証してから、旧原文のエスケープ移行・版の更新を行う。
- `TodoProject.DeepClone()` で変数要素も複製し、Undo／Redo・複製間で共有しない。
- 通常保存と部品の読み込み・保存で共通検証と共通の旧形式移行を使う。現在の `BranchTemplateStore` はJSONを直接読むため、`JsonProjectStore` だけの変更では不足する。
- 未定義参照は破損ではないため読み込みを拒否しない。読み込みや表示で元ファイルを書き換えない。
- 自動保存とバックアップは既存のプロジェクト保存経路を使用し、別の変数ファイルを作らない。

## 部品テンプレート

現行の `BranchTemplate.Capture` は新しい `TodoProject` を組み立てるため、参照原文だけを持ち出すと定義が失われる。

1. 部品保存時、保存対象のタイトル・メモが直接参照する定義だけを複製する。未使用定義は含めない。未定義参照は原文を保持する。
2. ライブラリでのプレビューは部品内の定義で表示する。部品名は展開対象外なので、ステップから名前候補を作る場合は表示名を使う。
3. 挿入先に同名定義があれば挿入先を優先し、なければ部品の定義を追加する。既存定義を自動上書きしない。
4. 同名で値が異なる場合、配置操作の前にライブラリ内へ使用する値と結果のプレビューを表示する。挿入先の定義でも解決しない参照は未定義として示す。
5. 定義追加とノード・辺・ブロックの挿入を1つのUndoにまとめる。部品元の定義は変更しない。

これにより、`{製品名}` を使う部品を別プロジェクトへ持ち込むと、そのプロジェクトで定義した製品名が使われる。

## 実装の責務

以下の追加ファイル名・API名は設計案。

| 層・既存箇所 | 変更内容 |
|---|---|
| Core `Models/ProjectVariable.cs`、`TodoProject` | 定義モデル、一覧、形式番号、DeepClone |
| Core `Text/ProjectVariableResolver.cs` | 解析、展開、参照名・位置・未定義情報を返す純粋な処理 |
| Core `Text/ProjectVariableService.cs` | 対象フィールド列挙、使用箇所検索、改名計画、定義検証・移行。WPFへ依存しない |
| Core `Storage/JsonProjectStore`、`BranchTemplateStore` | 宣言版の検証、共通移行、保存前検証 |
| Core `Graph/BranchTemplate` | 使用定義の抽出・複製・検証 |
| Core `Text/GraphExporter` | 出力対象文字列の展開後に形式別エスケープ |
| App `NodeViewModel` | 原文の `Title` / `Notes` を維持し、読み取り専用の `DisplayTitle` / `DisplayNotes` / 未定義情報を追加 |
| App `MainViewModel.ProjectVariables.cs` | 設定画面との受け渡し、1回のUndoで適用、Dirty、派生表示更新 |
| App `Views/ProjectVariablesWindow` と専用ViewModel | 下書き編集、検証、使用箇所・変更結果プレビュー |
| App `MainWindow.xaml`、`Controls/GraphView.xaml` など | 非編集バインディング、詳細プレビュー、コピー、警告表示 |
| App `MainViewModel.Editing`、Planning、Bookmark、Templatesなど | 検索・ソート・補助表示・部品挿入の連携 |

リゾルバーはMainViewModelごとに定義のスナップショットから構築し、staticな現在プロジェクトを持たせない。
初版は複雑な依存キャッシュを作らず、定義確定時に当該プロジェクトの表示を更新する。原文編集時は当該項目と関連一覧を更新する。
Undo／Redoでモデルが差し替わった場合もリゾルバーと表示を再構築する。
値変更だけでグラフの接続・レイアウト・選択を作り直さない。表示専用の変更通知を用意する。
詳細メモは現在LostFocus更新なので、プレビュー用の編集バッファを用意して毎入力で解析し、既存の保存・Undo粒度は維持する。変数設定を開く前に進行中の通常編集を確定する。
新しい外部パッケージは追加しない。

## 実装順と受け入れ条件

1. Coreの解析・モデル・検証・移行とテスト。
2. 変数設定、表示と編集の分離、検索、Undo／Redo。
3. 受信箱、補助表示、エクスポート、部品テンプレートの連携。
4. WPFのスモークテストと画面確認。全体が揃ってから初版として公開する。

必須検証:

- 複数参照、日本語名、大小文字、未定義、不完全記法、エスケープ、再帰しない値を正しく処理する。
- 旧形式の単独・連続した波括弧を移行しても表示が同じで、保存・再読込で二重移行しない。
- 不正定義は通常ファイルと部品の両経路で拒否し、元ファイルを維持する。
- 値の変更・削除・再追加が完了済みを含む全対象表示へ反映され、別プロジェクトへ漏れない。
- 名前変更・交換が有効な参照だけに作用し、Undo／Redoで定義と原文が一緒に戻る。
- 設定キャンセル・変更なし保存でDirtyや履歴が増えない。Clone先の変更が元へ影響しない。
- 原文と表示値の検索、値変更後の再検索・並び順が整合する。
- 展開値に引用符・角括弧・Markdown/Mermaid記号があっても書き出し構造を壊さない。
- 受信箱から配置しても原文を保持し、部品の同名競合・欠落定義・一括Undoが仕様どおりになる。
- 日本語IME入力、編集中カーソル、長い名称、ライト・ダーク、カード・ミニマル表示を画面で確認する。
- 多数のステップで値を保存した際の表示更新時間を測定し、操作を妨げる場合に限りキャッシュや更新対象の絞り込みを追加する。
