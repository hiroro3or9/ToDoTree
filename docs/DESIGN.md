# ToDoTree 設計メモ

## 1. コンセプト

ゴールに至るまでの「たくさんの細かいステップ」を、**分岐と合流のあるグラフ（DAG）** として
書き出し、眺め、進めていくための Todo 管理アプリ。

- Git のブランチのように、作業は分岐して進み、あとで合流する
- マインドマップのように、思いついた順にどんどん枝を生やせる
- 「いま着手できるタスク」がひと目でわかる

### 設計上の決めごと

| 項目 | 決定 |
|---|---|
| 構造 | DAG（1ノードが複数の親を持てる／循環は禁止） |
| 描画 | WPF Canvas に自前描画（ズーム・パン・ドラッグ） |
| 保存 | `IProjectStore` で抽象化し、既定は JSON ファイル（後で SQLite に差し替え可能） |
| 複数プロジェクト | 1 ファイル = 1 タブ。プロジェクト間の依存関係は持たせず、文書状態を独立させる |
| 依存 | 実行時の外部 NuGet 依存ゼロ（テストのみ TUnit） |
| テスト | TUnit（Microsoft.Testing.Platform）。`dotnet test` / 直接実行のどちらでも走る |
| ターゲット | .NET 10 / `net10.0-windows`（Core は `net10.0`） |

## 2. データモデル

```
TodoProject
 ├ Nodes : TodoNode[]      … ステップ
 └ Edges : TodoEdge[]      … 依存関係（From を終えると To に進める）
```

### TodoNode

| フィールド | 意味 |
|---|---|
| `Id` | GUID |
| `Title` / `Notes` | タイトル・メモ |
| `Kind` | `Start` / `Step` / `Milestone` / `Goal` |
| `Status` | `NotStarted` / `InProgress` / `Done` / `Cancelled` |
| `Due` | 期限（任意） |
| `EstimateMinutes` | 見積もり（任意、クリティカルパス計算に使用） |
| `Tags` | タグ |
| `X` / `Y` / `IsPinned` | 座標。`IsPinned` が true の間は自動レイアウトで動かさない |

**派生状態（保存しない）**

- `Ready`（着手可能）… 未完了 かつ すべての先行ノードが完了済み
- `Blocked`（待ち）… 未完了 かつ 未完了の先行ノードがある

ユーザーが管理するのは `Status` だけで、「今やれるか」はグラフから自動で決まる。
これが本アプリの中心的な体験。

### TodoEdge

`From → To` の有向辺。`Label`（任意）。自己ループ・重複辺・循環は追加時に拒否する。

## 3. Core の機能

- **TodoGraph** … ノード／辺の追加・削除、隣接インデックス、`CanConnect`（循環検出）
- **GraphAnalysis**
  - トポロジカルソート（Kahn 法）
  - 循環検出
  - `ReadyNodes()` … 着手可能なノード
  - `Progress()` … 全体／サブグラフの進捗（件数ベースと見積もり重み付け）
  - `CriticalPath()` … Start→Goal の最長経路（見積もり重み）＝ボトルネックの鎖
  - `Ancestors` / `Descendants` … 選択ノードの上流・下流ハイライト用
- **LayeredLayoutEngine** … Sugiyama 風の階層レイアウト
  1. 最長経路法でレイヤ（列）を決める
  2. バリセンター法を数回スイープして交差を減らす
  3. 座標を割り当てる（左→右 / 上→下 を切り替え可能）
  - `IsPinned` のノードは動かさない
- **JsonProjectStore** … `System.Text.Json`。一時ファイルに書いてから置換する原子的保存＋ `.bak`

## 4. 画面構成

```
┌──────────────────────────────────────────────────────────┐
│ タブ: [プロジェクト A] [プロジェクト B *] [＋]                │
├──────────────────────────────────────────────────────────┤
│ ツールバー: 新規/開く/保存 | ノード追加 | 自動整列 | 全体表示 | 検索 │
├────────────┬─────────────────────────────┬───────────────┤
│ 左パネル    │  グラフキャンバス              │ インスペクタ  │
│ ・着手可能  │   ○──┬──○──┐               │ タイトル      │
│ ・進行中    │       └──○──┴──◎ ゴール      │ 状態/種別     │
│ ・未着手    │  （ズーム・パン・ドラッグ）    │ 期限/見積り   │
│ ・完了      │                              │ 先行/後続一覧 │
├────────────┴─────────────────────────────┴───────────────┤
│ ステータスバー: 進捗 12/40 (30%) ・ 着手可能 3 件           │
└──────────────────────────────────────────────────────────┘
```

### 複数プロジェクトの構成

```
WorkspaceViewModel
 ├ Documents : MainViewModel[]  … 開いているプロジェクトタブ
 └ ActiveDocument               … 現在操作しているタブ
      ├ TodoProject / TodoGraph
      ├ FilePath / IsDirty
      ├ Nodes / Edges / 選択状態
      ├ Undo / Redo
      └ 検索・絞り込み・キャンバス表示状態
```

`MainViewModel` は 1 プロジェクトの編集状態だけを持ち、`WorkspaceViewModel` がタブの追加・選択・終了、
セッション復元、全タブの自動保存を担当する。保存、Undo、検索、選択、ズーム位置はタブ間で共有しない。
同じ絶対パスのファイルは二重に開かず、既存タブを選択する。

未保存プロジェクトは `%APPDATA%\ToDoTree\autosave\<DocumentId>.todotree.json` に分けて退避する。
`settings.json` にはタブ順、ファイルパス、選択中のタブ、キャンバス表示状態を保存する。
プロジェクト本体の JSON 形式には、タブ固有の状態を混ぜない。

## 5. 操作

| 操作 | 割り当て |
|---|---|
| 子ステップを追加 | `Enter`（選択中ノードの後ろに繋げて追加） |
| 兄弟ステップを追加 | `Shift+Enter`（同じ親にぶら下げる） |
| ノード名を編集 | `F2` / ダブルクリック |
| 完了トグル | `Space` |
| 削除 | `Delete` |
| 接続 | ノード右端のハンドルから別ノードへドラッグ |
| 接続解除 | 辺を選んで `Delete` |
| ズーム | ホイール（カーソル位置基準） |
| パン | 中ボタンドラッグ / 背景ドラッグ |
| 全体表示 | `Ctrl+0` |
| 自動整列 | `Ctrl+L` |
| 元に戻す/やり直し | `Ctrl+Z` / `Ctrl+Y` |
| 保存 | `Ctrl+S` |

### タブ操作

- 「新規」「開く」は現在のタブを置き換えず、新しいタブを追加する
- タブの `×` はそのプロジェクトだけを閉じ、未保存なら保存確認を出す
- アプリ終了時は、未保存のタブを順番に確認する
- 最後のタブを閉じた場合は、空の新規プロジェクトを 1 つ開く

将来追加するショートカット（初版では未実装）:

| 操作 | 予定キー |
|---|---|
| 現在のタブを閉じる | `Ctrl+W` |
| 次のタブへ移動 | `Ctrl+Tab` |
| 前のタブへ移動 | `Ctrl+Shift+Tab` |

「細かいステップをたくさん入れる」用途を最優先するため、`Enter` 連打だけで
ステップを直列に伸ばしていけることを設計の中心に置く。

## 6. 配色（状態が一目でわかること）

色は 1 か所にまとめる。`Themes/Palette.Light.xaml` と `Palette.Dark.xaml` が同じキーを持ち、
`ThemeManager` が `Application.Resources.MergedDictionaries[0]` を丸ごと差し替えることで切り替わる。
画面側は色をすべて `DynamicResource` で引くので、切り替えに自動で追随する。
自前で描いている層（`EdgeLayer` / `MiniMap`）だけはバインディングを通らないので、
`ThemeManager.Generation` を見てペンを作り直す。

| 状態 | 色 |
|---|---|
| 着手可能 (Ready) | 緑の枠＋淡い緑（次にやるべきもの） |
| 進行中 | 青 |
| 待ち (Blocked) | グレー（先行待ち） |
| 完了 | 薄く沈める＋チェック |
| 期限超過 | 赤いバッジ |
| Goal | 太い枠＋アクセント |
